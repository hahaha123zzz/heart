# 第二阶段真实模型验收

执行日期：2026-10-15 至 2026-10-16（Asia/Shanghai）。用户要求启动真实模型测试。

## 执行方式

复用 `scripts/accept_answer_flow.py`，通过聊天 API 同一 `_run_turn`/TaskService 执行链路调用模型，并设置 `LLM_MOCK=0`。采用临时 SQLite，显式隔离课程库和学习库；每例使用不同的合成学生。没有请求本机 8000 端口的学生服务。

首轮执行 9 例。随后针对误拒绝运行两次定向复测，并加入不存在的教材原图负例。最后一次复测共 18 次模型调用。回执重放时确认无额外模型调用和重复对话。代码记录提前交付时的文字、阶段耗时、状态、引用和图解结构，报告不含 API 密钥。

## 修正与定向复测

根因是心理学充分性检查和质量检查没有区分“讲解文字的证据”与“后续图解是否已生成”，把原书没有现成图解误当成生成前提。规则已明确：未指定教材原图时，“结合图解”指随后单独生成并核验辅助图解；仍按教材核验文字、变量和实验程序。明确要求解释原图、复现原始数据图或辨认图中数值时，仍须有相应图和数据。

| 案例 | 文字交付 | 总执行时间 | 最终结果 |
|---|---:|---:|---|
| 三种设计比较，修复后 | 26.000 秒 | 35.453 秒 | 文字核验通过，图解不可用，保留文字 |
| 双盲流程，修复后 | 8.594 秒 | 14.156 秒 | 文字先交付，随后生成 8 帧图解并写入同一历史回答 |
| 要求复现不存在的教材图4-999 | 未生成 | 1.266 秒 | 意图识别要求圈选/补充对象，停在 `awaiting_clarification` |

三种设计回答分别引用被试间、被试内和混合设计教材材料，通过回答质检。图解随后生成失败，最终返回 `visualization_status=unavailable`；回答被保留，且说明材料不能核验图形细节。双盲图解按顺序展示两名研究者的操作、变量和盲法控制。它证明失败的图解不会丢失合格文字，图解完成后可从历史恢复。

三种设计案例的文字交付耗时较长（26 秒）；双盲例为 8.594 秒。图解成功案例的最终总时间比文字交付多约 5.6 秒。总执行时间含服务端同 request_id 重放核验，计时不含客户端网络和浏览器绘制。单次样本不足以推断总体延迟，也没有测量学习收益。

负例缺少原图对象，因此被要求补充/圈选对象；模型没有生成回答或图解。它验证了缺少对象时先澄清，但没有直接测试同一轮中给出原图ID后、由于缺少图形数据而触发的充分性拒绝。
