# DeepTutor 原生完整回答链路迁入：范围与实施方向

日期：2026-10-25。用户已明确选择：**连回答流程一起复用，覆盖消息进入、Agent工具循环、检索、流式生成与输出**。本文取代此前“保留Q3作为核心循环，仅适配查询模块”的迁入方向；既有功能质量与数据保留要求继续有效。状态：范围设计，未启用或宣称迁入完成。

## 1. 目标架构

现有页面/账户入口 → 宿主权限与请求身份 → 已有NativeTurnBridge → DeepTutor TurnApplicationService → TurnEngine/ChatOrchestrator → AgenticLoopPipeline与上游工具编排 → RAGService/LightRagPipeline → StreamBus及原生持久化回合 → 宿主事件/来源/任务投影 → 现有页面。

直接使用固定上游源码及其依赖闭包，优先通过现有vendor/原生运行环境引用；不再把“按上游思路重写一个Q3循环”称为全套复用。上游固定版本为D盘仓库 `6cf793bd868ba5ecbe64722936d4be8fab5a01df`；迁入前核对工作树文件哈希、许可和实际导入路径。

单个回合只允许一个执行引擎。原生回合进入后，不能再启动宿主Q3生成、选择另一套检索或由宿主模型重写一遍原生最终答案。切换期旧入口只用于明确路由与回滚，不并发执行同一输入。

## 2. 直接复用与宿主边界

| 范围 | 复用/适配要求 |
| --- | --- |
| app/service、runtime/turn_engine、runtime/orchestrator | 使用原生应用服务、统一上下文、能力路由与回合协调，不能仅直调一次模型冒充原生入口 |
| agents/loop、runtime/agentic | 使用探索/回答、工具协议与调度、暂停恢复、预算、上下文管理和模型客户端生命周期 |
| services/rag/service、factory、pipelines/lightrag | 采用上游查询服务、模式、来源结构和角色解析；现有候选先检查布局/embedding/版本兼容，不擅自重建 |
| runtime/stream_bus及原生回合事件存储 | 保留事件身份、顺序、恢复和取消语义，适配现有SSE及前端，不把流重新收完后伪流式播放 |
| tools与能力挂载 | 使用上游注册/组合规则，先挂本项目已配置且授权的教材、澄清、阅读与学习工具；全套流程不等于无条件开放全部外部/执行工具 |
| 账户/教材/来源/图片 | 保留现有用户身份、课程访问控制、来源版本和原图身份；通过已有桥映射，不直接复制上游登录系统给用户再建第二套账号 |
| Q5与阅读器 | 绑定现有学习路径/本次安排与实际阅读位置；如迁入上游学习服务，须先定义数据所有权/迁移，不能双写两套掌握状态 |

保留发布所需原文/引用/图片验证，但只在一个清晰边界执行。逐项区分必要核验和现有重复模型调用；不能在原生答案后套用整个旧Q3链再检索、生成、质检。上游工具产生的内层答案若上游本就作为工具结果处理，按原生语义保留并计时，不自行冒充唯一最终回答。

## 3. 已发现可复用的本项目基础

- `integrations/deeptutor/native_bridge.py` 已有NativeTurnBridge、请求/任务revision映射、原生user/workspace/course/session/turn边界与内部端点。
- `tests/test_deeptutor_native_runtime.py` 已有边界测试及真实上游应用层/受控能力测试。受控能力替代模型，不证明教材、真实模型和页面全链路完成。
- 原生桥会写映射表并建立内部上游账户/配置；不能仅打开DEEPTUTOR_NATIVE_ENABLED就连接正式库。先审计其配置存储、删除/epoch、用户隔离、授权和回滚。
- 固定上游vendor、许可证、LightRAG全书候选、现有SSE/任务收据和Q5数据均优先复用，不再另造第三套桥或学习库。

## 4. 实施顺序

1. **N0 入口与依赖审计**：列原生桥调用方、实际导入源码、上游应用容器、存储与模型/KB依赖，形成“已用原码/必须适配/尚未接通”台账；核对最新主线与待集成Q4/图片交付。
2. **N1 原生宿主运行**：在隔离目录及数据库运行实际TurnApplicationService和chat能力，完成真实模型单回合、工具调用和流式；不走本项目Q3循环。保留trace证明实际类与工具路径。
3. **N2 教材与模型接通**：给原生KB服务映射现有11章候选、课程/来源/图片；验证兼容和查询配置。CPU/GPU沿用现有模型配置与会话核查，分别测reranker/embedding，不把切设备等同模型换版。
4. **N3 页面与持久化接通**：现有TaskService仅承担宿主请求/权限/结果投影；原生协调器拥有回合执行，原生事件为恢复依据。明确任务与回合终态、确认答复、取消、断线、重复提交、超时及删除epoch的映射。
5. **N4 教学与工具接通**：当前目标、画像、学习安排、Q5路径、PDF选区和reader动作通过原生上下文/工具接入。与上游mastery功能冲突时先统一所有权，不以两套状态互相猜测接续。
6. **N5 单一链路联合验收**：真实教材问答、跨章/partial、图像像素与返回、第一章/next、计划/插问返回、先讲不考、ask_user选项/文本、取消、断线/刷新/重启、会话/用户隔离及来源失效。对比现有同题延迟与模型调用数，不承诺迁入自动更快。
7. **N6 主线与运行切换**：固定提交、完整依赖、隔离数据迁移通过后，备份并按已授权部署流程切换；最终普通对话及已验收入口默认使用原生链路。确认无调用方依赖后删除被替代的重复生成/调度代码；回滚窗口结束前保留稳定旧发布，不删除学习数据。

## 5. 完成标准

不是“代码里出现DeepTutor类名”或“打开原生开关”，而是用户输入真实经过上游应用服务、Agent循环、工具与检索、原生事件恢复并回到现有页面；不再由旧Q3替它执行；教材、引用、图片、学习计划和历史均有同一稳定版本的端到端证据。

原生存储、模型和教材依赖尚未完成全量闭包审计；本次只确定新的迁入边界，没有修改业务入口或启用正式原生链路。
