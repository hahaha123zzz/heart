## 2. 关键发现：改写漏检**没有**现成的模型兜底

阶段 B 的结论是“14 条改写漏检留给模型路径”。核查代码后不成立：

- `service.understand()` 只有在调用方传入 `classifier` 时才走分类端口；
  `TaskService` 调用时只传 `llm`，**生产路径没有 classifier**。
- 复杂解析 `resolve()` 只在 `needs_resolution(turn)` 为真时触发，条件是“先…再…”“如果…否则…”“一方面…另一方面”等**复合任务**句式。
- 短句“转不过弯来”“站不住脚”既不满足 `needs_resolution`，也没有 classifier，**永远不会到达模型**。

实测路径（只读推导，未调模型）：

```
understand('我转不过弯来')
  → rules: 无标签
  → needs_resolution: False
  → classifier: None
  → model_calls: 0，annotations: []
```

因此当前真实标签覆盖率 = 规则覆盖率。留出集 R=0.42 就是上限，不是“暂时没接模型”。

## 3. 三个可选方案（需要用户决定）

| 方案 | 做法 | 代价 | 是否违反现有约束 |
|---|---|---|---|
| **A. 扩展复杂解析** | 让 `needs_resolution` 在“标签缺失且消息 ≤40 字”时也为真，同一次 `resolve()` 顺带产出标签 | 这些短句从 0 次调用变成 1 次（P95 约 2.9s、首字约 6.2s 的既有解析开销） | 不增加**单独**分类调用，但增加了总调用量与延迟 |
| **B. 接受漏检** | 规则只做高置信快路径，改写一律弃权 | 标签覆盖低（留出 F1 0.56） | 不违反 |
| **C. 离线批量标注** | 用真实模型离线标注一批真实学生输入，产出评测/训练数据，不上线 | 一次性批量成本；不影响线上延迟 | 不违反 |

推荐顺序：**先 C，再决定 A**。C 能给出“模型标签到底比规则好多少”的可复核数据；没有这个数据就开 A，等于用线上延迟换一个未经验证的收益。

## 4. 可以立即做的部分（不依赖上述决定）

- 真实模型**回答质量**对照（不是标签）：隔离端口 + 独立 SQLite，`LABELS_POLICY` off/on 各 5 条“分不清”样本，记录策略、来源、耗时、答案。
  - 前置：题库/教材数据未就绪时，涉及检索的样本会失败；需先确认用哪门课、哪些小节。
- 真实页面“分不清→对比”一轮：同样依赖数据与运行配置。
- 上述两项都需要先启动隔离服务；本轮未启动，因为缺少可用教材数据会得到大量假失败。

## 5. 阶段 C 结论

- 环境层面可跑真实模型（`.env` 有键），但**标签层的模型兜底不存在**。
- 在用户选定 A/B/C 之前，C 的“标签准确性”部分无法执行；回答层对照可执行，但受教材数据缺失限制。
- 不声称任何真实模型或页面结果。
