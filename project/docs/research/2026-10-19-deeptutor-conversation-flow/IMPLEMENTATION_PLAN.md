## 1. 目标与交付范围

将 DeepTutor 的完整对话运行机制接入当前心理学项目，包括请求与能力路由、上下文与来源预读、原生教材检索、Agent 循环、工具执行、用户交互、输出、事件恢复、学习反馈和下一轮接续。

本次不再把“模型调用网关”“只读宿主摘录的受限 AgentLoop”或“文本补充检索”作为完整接入的完成条件。新模式下由 DeepTutor 原生流程组织对话；原项目主要负责课程数据、账户与权限边界、教材原文/版本/PDF 映射及学习事实记录。

验收清单覆盖 11 个顶层能力、14 个循环扩展和 100 个内置工具，逐项记录：实现接通、资源/权限挂载、真实依赖状态、前端呈现及验收结果。实现范围完整，不代表每轮开放全部工具，也不代表缺少外部服务时可以标记可用。

### 交付物

- 当前页面可用的原生对话、教材问答、澄清交互与恢复。
- 原生知识库、解析、索引、混合检索、重排和原图来源接入。
- 用户偏好、历史、附加资料、学习日志与学习模式的完整接续。
- 对工具、能力和扩展逐项维护的验收台账。
- 课程数据、版本、引用、学习记录、取消和删除的适配。
- 可复现的安装、启动、教材发布、索引、检查、部署与回滚入口。

## 3. 目标结构与关键决策

```text
现有页面、PDF 阅读器、学习页面
  → 宿主请求归属与课程资源校验
  → 原生对话适配（请求/身份/会话/事件/结果）
  → DeepTutorApp / TurnApplicationService
  → TurnRequestPreparer / ContextBuilder / TurnExecutor
  → ChatOrchestrator → 选定的顶层能力
  → 原生循环与循环扩展 ↔ 原生工具、RAG、阅读与学习服务
  → 来源、正文、卡片、产物、执行事件
  → 课程发布约束与学习事实适配
  → 现有页面展示、恢复和继续交互
```

### 3.1 对话流程的唯一组织者

原生模式下，不再先经过旧 `ConversationRouter → TeachingPlanner → ResponseGenerator` 再调用上游生成。旧流程保留为显式兼容/回滚入口。

`TaskService` 的归属、版本、幂等、取消和结果收据可复用，但其旧语义路由、澄清和教学执行分支不能重新控制原生同一轮对话。先拆清生命周期校验与旧执行策略，再接原生入口。

不重新编写 Agent 循环、历史压缩或工具调度。需要本地变更时优先使用上游扩展接口；必须修改固定副本的补丁单独记录、更新哈希并验证对应上游测试。

### 3.2 状态与写入权威

| 数据 | 权威位置与约束 |
| --- | --- |
| 登录/学生/课程成员与资源权限 | 宿主服务端；不信任浏览器提交的上游身份、角色或路径 |
| 原生对话、模型协议、工具事件 | DeepTutor 会话/回合服务；按用户、工作区和课程隔离 |
| 教材原件、阅读 PDF 与发布版本 | 宿主教材发布清单；上游节点必须能映射回该版本 |
| 正式展示结果与宿主任务收据 | 以任务 ID/revision 和原生 turn 映射保存，幂等发布 |
| 作答事实、成绩与掌握资格 | 一个统一作答身份对应一条有效事实；不得两套系统各推进一次 |
| 偏好、日志与软教学状态 | 使用上游相应服务；与原记忆的迁移及撤销保持一致 |

跨进程不能依赖一个数据库事务同时提交全部状态。采用已存在的任务/回合身份、幂等记录与可重试状态推进；为“上游完成但宿主尚未发布/记分”设计恢复检查，禁止因恢复重新生成或重复记分。

### 3.3 输出与课程约束

原生 stage/progress/tool/交互事件即时呈现。对需要教材忠实性核验的回答，正文先处于待核验状态，通过原文、版本、引用及必要语义检查后成为正式答案。其他对话模式遵循各自原生输出语义。

课程核验作为适用场景下的结果发布约束；不把旧整套教学编排重新包在原生流程外面。未通过的草稿不能经恢复入口显示成正式答案，也不能作为已确认事实进入下一轮上下文。

“必须看原图”“必须实际检索”的任务不允许通过移除图片或工具后宣称成功。明确展示实际使用的能力和失败状态，保留原生兼容策略但使课程要求生效。
