# DeepTutor 整套能力与代码集成实施计划（修订版）

日期：2026-10-19。当前有效版本：代码集成路线。用户明确：保留现有页面，允许大块复用、整套接入；纠正的是把项目功能路由到 DeepTutor 应用执行的方式，不是缩减功能目标。对话质量仍是第一优先级，每个验证小阶段自动提交、推送。

本计划替代此前 P0—P8 的运行时委托路线。旧计划保存在 [历史计划](archive/NATIVE_RUNTIME_PLAN.md)，此前提交和测试仍是历史事实，不计作本路线的功能完成。配套：[接入边界](LOCAL_REUSE_CONTRACT.md)、[完整验收矩阵](ACCEPTANCE_MATRIX.md)、[质量基线](QUALITY_BASELINE.md)、[执行记录](EXECUTION_LOG.md)。

## 1. 执行目标保持不变

在我们的项目中集成 DeepTutor 的整套相关能力：高质量连续对话、教材检索与原图、工具循环、澄清、记忆与学习接续、阅读、题组与评分、解题、研究、可视化、动画和音频。继续维护 11 个顶层能力、14 个循环扩展、100 个内置工具的完整覆盖台账，不擅自缩为几个工具或仅优化提示词。

允许整包迁入、整体替换内部模块和调整项目内部流程；不以改动复杂度为由拆成低价值的小补丁。首个交付里程碑优先让现有页面中的普通问答和连续追问实质改善，其他能力随后按依赖接通，不取消。

执行方式是把可复用的实现集成到本项目。网页入口、任务生命周期、课程资源和学习数据仍由本项目管理；生成、上下文、工具和检索模块可以采用迁入的完整实现。不能通过把整个请求转交独立 DeepTutorApp、原生会话服务或另一个应用的接口，宣称完成代码复用。

## 2. 目标结构

```text
现有页面 / 阅读器 / 学习页面
  → 本项目 API、任务身份、版本与取消/恢复
  → 本项目对话模块（集成 DeepTutor 的上下文、提示词、循环实现）
  ↔ 本项目工具模块（集成工具注册、调度、澄清及能力扩展）
  ↔ 本项目教材服务（集成解析、混合检索、重排、原图处理）
  → 本项目模型入口、引用/质量检查、受控修订
  → 本项目数据库、记忆/学习记录、SSE 与现有组件
```

本项目继续拥有主流程，内部实现允许重组和替换。既不强制保留旧的每个模型调用，也不强行把旧整套教学编排包在迁入循环外再次执行。每轮只能有一个实际回答编排者，旧模块按职责留用、合并或替换，防止重复路由、重复生成和重复记分。

模型可访问原配置的模型 API；需要 embedding、沙箱、渲染、语音等服务时可使用专用进程。专用服务承担明确的资源计算任务，不接管整个对话、账户或学习数据库。

| 对象 | 修订后的处理 |

| 上下文、提示词、AgentLoop、工具调度及扩展 | 允许按完整模块组迁入本项目，改成本项目模型/数据/事件接口 |

| Markdown、公式、问题卡和产物组件 | 已可用的继续用，缺少的整组件迁入现有前端，不切换整个网页应用 |
| 本项目 API、TaskService、Orchestrator | 保留入口与业务权威，内部执行可以整体改造；逐个明确取代的旧分支 |
| 本项目学生、任务、对话、记忆和评分数据 | 保持单一权威；新增协议/事件数据接现有仓库，不另建 DeepTutor 账户与会话副本 |
| 已提交的 worker / native_bridge 等实验 | 标记历史实验；不继续建设为主对话路由，Q0 审计并解除不再需要的入口与依赖 |
| 此前模型/知识库网关和受限循环试点 | 保留历史证据；本地集成接通后逐项替换调用点，不用桥接成功冒充代码集成完成 |
| 此次尚未提交的宿主原生路由开发 | 已备份并撤出工作树，不纳入新计划的交付 |

代码迁入时保留来源路径、固定 SHA、许可证、必要 NOTICE 与修改记录。优先保留成熟算法和协议，不重新手写已有实现；裁去其对原生账户、工作区、应用容器及全局配置的依赖。可独立运行的固定模块允许直接引用，但不得因此隐式启动整个上游应用。

不删除正式教材、数据库、用户已有修改或历史提交。旧试点数据是否清理单列方案，不因路线修订自动删除。
