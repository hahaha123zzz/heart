# 流式草稿撤回、长等待与中断收尾实施计划

日期：2026-10-23；状态：待实施。编写时main为`9d5f5f6`，流式行为调查基线`974617d`；执行前重核并行提交。依据：[流式对照调查](STREAM_RETRACTION_DEEPTUTOR_COMPARISON.md)、[已交付取证修复](DIALOGUE_RETRIEVAL_FIX_ACCEPTANCE.md)。连接UX3/UX5、Q3循环和Q2证据链，不替代已有学习计划或部署专项。

## 1. 目标与取舍

解决三类现象：工具前出现正文又消失、撤回后长时间缺少有效反馈、正文中断后自动另生成导致再次等待或失败。

采用默认路线：**先取得本轮所需证据，再流式讲解；探索说明与答案分开；部分流中断不透明重做**。沿用现有LLMClient、AgentLoop、SSE、任务收据和页面，不另建流框架或逐token持久库。

不承诺所有请求零等待或绝不修订：取证和质检仍需时间，未通过的正文必须能撤回/替换，不能保存无依据内容。关键是普通取证不先展示注定被清掉的答案，真正拒绝只影响对应未发布内容。首字指标不把“正在检索”或探索草稿当作教材回答开始。

## 4. 输出与执行契约

### 4.1 取证阶段

- 首先按可信任务类型/导航决定是否需要教材证据；纯澄清、计划确认、状态查询保持原有合法入口，不因本专项强制检索。
- 明确教材问题进入取证阶段：点名图调用已有原图/原文路径，精确目标复用read_target，其余调用共同检索边界。已有本轮有效来源可直接复用，须核对对象覆盖和版本；历史引用不能直接冒充新证据。
- 可以复用强制工具轮或直接共享取证服务，选择与现有调用方改动最小的一种；不得同时预取与再开同义retrieve_course。调度仍归唯一AgentLoop。
- 仍需模型选择工具时，该阶段普通文本不进答案正文；显示服务端实际进度与阶段，不展示内部思考或猜测知识。模型未调用工具但给出完整候选回答时，在有充分证据且门禁通过后可直接发布缓冲结果，不为“真流式”再调用一次模型。
- 证据充分后进入answer阶段，工具关闭的讲解回合正常逐token输出；证据不足则有界补查或明确不足，不能绕过门禁。若模型还必须调用其他工具，先继续探索，不伪装成最终讲解。

### 4.2 事件与正文归属

保留answer_delta/answer_replace/answer_state、answer_id、task_id/revision、round_id、单调seq及最终answer/done快照。优先给现有事件增加可选`role=progress|answer`及对应片段状态；确需片段ID时可由answer_id+round_id推导，不再创建竞争请求身份。

- begin不再无条件清空整条消息。progress走现有处理记录，answer只修改本轮候选正文。
- 进度、取证、修订、核验、等待学生、保存、拒绝、中断要有清楚归属；同一工具回合不因没有答案而显示“处理失败”。
- 修订旧候选时将其移出可引用正文、按需折叠保留未发布痕迹；只替换相应answer片段。不能把未通过内容继续当作有效讲解留在屏幕主体。
- 最终answer/done为权威快照，历史只保存通过内容；工具前叙述、内部思考、partial草稿不进入学习记忆或掌握更新。
- 前后端按同一release交付；未知新字段不破坏旧最终快照。禁止在旧前端上只更新后端后宣称新分流行为已生效。

### 4.3 流中断

给本地LLM异常增加必要元数据：本轮是否向用户发过正文、finish_reason及可安全公开的错误类别。部分文本可保留在本轮结果/诊断中，不打印完整学生上下文。

- 本轮未输出正文，且已有有效工具成果、还有剩余预算时，允许一次受控恢复/收尾；首轮连接失败按已有错误语义处理，不无限重试。
- 已输出正文后中断：停止自动重新生成，关闭流，标记“输出中断，未保存”，保留可辨识的未完成展示或折叠诊断；不自动当作最终答案保存/推进。
- 用户显式重试按现有请求身份发起；网络断线恢复继续查询原收据，不再POST生成。浏览器断线不等于模型服务端流中断，必须分别测试。
- length不是transport：截断不得成功保存。若采用上游续写，必须另设一次有界续写并复验引用、重复与上下文；本轮最小实现可保持明确incomplete_answer，不强行扩展自动续写。

### 4.4 时间与取消

建立同一轮活动执行的绝对截止预算，取证/选证/覆盖检查/正文/质检共享剩余时间，不能各阶段独立用满默认SDK超时。设置连接、流空闲、总活动时间三个不同边界；仅增加timeout不能算修复。

- 先记录旧案例阶段耗时，采用同一处服务端预算配置。初始建议普通请求120秒、显式多对象180秒作为隔离评估值；最终默认值需由同组案例验证后记录，不当作响应速度承诺。
- 各内层调用timeout=min(本阶段上限,剩余预算)，SDK/JSON重试纳入总预算；选证和普通心理学质检不能遗漏，禁止嵌套重试乘法。
- ask_user等待学生时间不计入活动执行；暂停快照保存逻辑预算策略而非跨进程monotonic时间，恢复生成新的活动deadline并有明确上限，不无限积攒重试。
- 剩余预算不足不再发起新模型/补查；返回有终态收据的受控超时。同步线程未必能强杀，需传播取消、阻止后续调用，并在发布/保存/状态提交前再次guard。
- 等待阶段用现有进度通道更新实际阶段/耗时，不泄露模型思考、不假报进度百分比。浏览器/SSE断开保持既有收据恢复语义。
