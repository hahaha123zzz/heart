# 阅读器数据接口、引用导航与文档复用实施计划

日期：2026-10-26。状态：**计划已编写，RP0—RP5未执行、未验收**。

依据：[阅读器实测](READER_PERFORMANCE_AUDIT_20261025.md)及用户确认的优先级。目标依次为：普通小节读取不做全书扫描、不清全局缓存；批量读取对象身份；引用跳转不重复加载完整小节；最后评估跨章文档复用。

## 1. 基线变化与适用范围

原实测针对e8edcf4发布副本：第一章第一节2张图导致约725ms组件耗时、1,016次读取和累计约263MB读取量，约713ms在两次发布绑定校验。累计读取量不等于峰值内存。

本次写计划时main已是`577cac5`，新增`knowledge.fixed_book`：`course_release.binding/validate`在fixed runtime活跃时能读取启动快照，`SourceVisual.is_valid`也有固定模式分支。原实测不可直接当此新版运行结果；先复测，再改尚未解决的路径。

固定运行时已有资源映射应复用；不另建数据库、发布索引中心或文件监视框架。阅读导航不能为了取得发布身份而强制启动LightRAG、等待模型/GPU或依赖原生对话迁入完成。

保持PDF.js/react-pdf-highlighter、现有翻页、相邻页预渲染、选区与坐标体系。本轮不重建教材/图谱，不改变审核/ready状态。

## 2. 目标数据流和职责

`启动/明确发布操作 → 一次完整核验与版本快照 → 原子启用对应generation → GET按当前版本读小节及登记表 → 一次获取本请求身份 → 按需核验涉及的PDF/图片 → 返回`。

引用路径：`已有selection_ref或定位接口 → 检查引用身份 → 当前文档/版本/小节匹配时直接更新focus → 不匹配时加载必要导航信息 → 一次提交定位`。

### 发布快照复用现有字段

- 以已有release_id、document_id、PDF version、assets/image ID、SHA、来源映射、section及审核状态为基础，复用`course_release`、`pdf_manifest`、`source_visuals`和fixed_book资源。
- 新增字段仅限实际缺少的schema/generation标识或版本指针；不把用户伪代码中的字段名硬套成第二套格式。
- 若需持久化，在现有发布产物目录原子写清单和当前版本指针，构建失败不替换当前快照；不为元数据缓存新增业务表。
- generation表示资源快照，不代替release_id，更不把staging/ready=false变成published。

## 3. 正确性与失效契约

| 场景 | 必须行为 |
| --- | --- |
| 普通小节GET、引用定位 | 不调用全局clear_cache，不扫描其他章节或重新计算全书发布身份 |
| 发布/审核更新/清单重建 | 构建并完整验证新快照，原子替换generation，失效关联缓存；失败保留旧可用版 |
| 服务启动 | 复用当前合法发布产物/固定快照并执行必要完整性检查；无有效快照时明确失败或走受控兼容，不每次GET重新建快照 |
| 当前文档/图片内容变化 | 拒绝作为旧版本继续提供；仅mtime/size和缓存中的旧SHA不足以判定安全 |
| 更新另一章 | 不导致所有用户下次读取都全量重扫；已发请求绑定同一个generation，不混用两版来源 |
| 多worker | 当前指针/generation由共享产物决定，各进程检测到更新后加载对应快照；不能只清发布进程内缓存 |
| 引用换版 | 不把旧引用映射到新版冒充原证据；保留已有stale/410及真实降级 |

两种资源策略必须说明：固定模式按既有“更新需重启”的运维契约；可更新模式由发布操作原子换版。两者都不能让任意原地替换文件静默以旧身份发送：优先使用不可变版本资源；无法保证不可变时，在实际读取/发布对应资源时做内容核验，只检查涉及对象，不能用cached digest自证当前路径内容没变。覆盖同大小/同mtime替换测试。

`course_release.validate()`还被回答/引用发布等调用方使用，不能全局改成不校验。区分读取快照与显式深度验证，保留原有验证入口语义，逐调用方迁移。

## 5. RP1：发布身份读取与全局失效解耦（P0）

主要文件：`knowledge/course_release.py`、`fixed_book.py`、`source_visuals.py`及实际发布脚本/管理入口。

1. 读取侧复用已验证release快照；fixed活跃时使用现有binding和资源映射，避免重复加载/复制全书gaps或全量映射。
2. 非fixed路径建立同一发布快照的只读访问，不让binding隐式validate(refresh=True)。尽量在现有course_release内增加必要参数/读取入口，不新建通用缓存层。
3. 保留显式深度核验和生成快照操作；将clear_cache关联到实际发布、审核/资源更新和明确刷新命令。需要兼容旧调用方时先迁移再收敛，禁止修改默认值后漏掉证据验证。
4. 发布操作一次性核对文档、PDF、assets与来源并原子启用新generation。GET至多检查当前指针和本请求资源，不因缓存未命中退回全书重建；未准备完成时明确返回版本/资源未就绪状态。
5. 快照为不可变对象，不由请求修改；请求抓取一次快照后贯穿响应，防止新release搭配旧图片。公开响应字段仍保持兼容。
6. 启动/失效与GPU、图查询解耦；不把普通阅读器数据访问绑定到ResidentGraph可用性。复用fixed已有快照信息，但其未激活时阅读也有独立合法路径。

验收：普通读取全书扫描次数为0、全局clear_cache次数为0；固定/非固定两模式均通过。启动/发布扫描单独计时，不从总成本报告中隐藏。

## 6. RP2：图片身份批量获取与轻量小节接口（P0）

主要文件：`knowledge/figures.py`、`source_visuals.py`、`web_api.py::course_section`及实际消费者。

1. 先用chapter/section索引筛出涉及的资产ID，再以同一快照批量读取身份；不能遍历每个ID再次执行发布核验或加载11章资源。
2. section_figures为本请求获取一次binding/版本视图，并传给序列化；Figure.public保留已有字段与必要单对象调用方式。兼容调用方不能靠每图默认回退全书扫描。
3. 图片实际读取/生成/证据发布仍检查对应文件身份与审核状态；删除/越界/哈希不符明确拒绝，不把pending改approved。
4. PDF模式只需轻量小节元数据、PDF位置及必要资源目录，不应等待不会展示的完整figures/blocks。优先复用已有reading-map和section_pdf；确需差异时给现有小节接口加明确的读取投影参数，旧调用默认保持兼容，不随意破坏图表/笔记/练习页。
5. 原文、图表详情和选区裁图继续按需读取，不在目录点击时预先生成所有图像或重新解析Word/PDF。
6. 图表较多小节的工作量应随涉及对象增长；同一请求中的图共享同一个release_id。对多个小节并发读取不会互相清空缓存。

验收：0/1/2/多图小节均保持响应字段与身份一致；批量查一次而非N次扫描。对原2图样本记录文件读取次数/累计字节和组件耗时，与725ms/1,016次/263MB原样本分开比较新版基线。

## 7. RP3：引用定位复用与导航一次提交（P0）

主要文件：`frontend/app.js`、`web_api.py`现有citation-state/citation-location/figure-location、`reader-actions.js`和阅读器挂载入口。

1. 复用已有接口职责：小节接口提供内容/导航；citation-location或figure-location提供位置；selection/preview提供后端选区证据。只补缺少的契约，不再新增功能相同接口。
2. 已有合法selection_ref时，保留轻量引用身份校验。当前document_id/version/release及section均匹配时直接更新focus并定位，不调用selectSection请求完整小节。
3. 同文档换小节时只读该小节必要导航信息，更新目录/标题/目标位置；跨文档再加载对应文档。当前位置相同不意味着版本已验证，不能仅按chapter号跳过校验。
4. 无坐标引用只跳页/小节；有坐标才高亮。定位缓存按课程、release、document_id、version、evidence/asset ID和范围绑定；缓存不得给另一用户暴露受限来源。
5. 将选择小节、清/设focus、渲染和reader动作收敛为一次最终提交，避免renderContent先mount再额外syncPDFReader。保留已有navigation序号/selection guard，快速点击只采用最后仍有效请求。
6. 统一正文上标、历史引用、图像返回、reader_goto与练习引用的定位入口。动作成功必须确认真实目标页；视图不可见/版本失效/请求取消时不能回成功。

验收：相同小节已绑定引用重复点击，完整小节GET为0、GetDocRequest/worker.new新增为0；不重复清focus造成回顶闪跳；刷新/历史/原图/拆分页转换保持正确。

## 8. RP4：跨章复用与次要渲染开销（P1/P2）

这批在RP1—RP3通过后执行，避免用前端重构掩盖后端瓶颈。

1. 检查react-pdf-highlighter PdfLoader已知生命周期：卸载会destroy文档。复用文档不能只缓存URL或已被destroy的PDFDocumentProxy。
2. 优先评估现有PDF.js生命周期能否安全保留当前章与上一章文档，使用document/version/有效URL为key、有界淘汰并释放Worker。默认目标不超过2个活跃文档，不缓存11章Canvas；若做到此点需要替换大段库代码，则先交付安全最小方案及测量，不直接更换PDF.js。
3. 明确文档、页面Canvas/文字层和ReactRoot各自所有权；淘汰/版本失效/异常时只销毁一次。快速切章后的迟到load不替换当前文档。
4. 引用/metadata/highlights只在语义变化时创建新值；高亮尽量只更新受影响页。不得因稳定引用而漏掉真正的图、文字选区或版本变化。
5. 保留已工作的当前/相邻页预渲染及现有PDF.js页面缓冲，不另加全章预渲染。全书page容器、GetPage元数据和Canvas渲染分别计数。
6. Cache-Control/ETag/版本化URL仅在真实传输仍有收益时改：Range/206保持；新版本不能取到旧缓存。同章重复点击不得重复下载reader主模块；Worker版本与主程序保持一致。

验收：若启用文档池，A→B→A复用有效文档，新增解析/Worker数量下降，内存受限且淘汰资源正确。不能将监听器signal自动清理误报泄漏；需要长期heap观察时单独记录，不把DOM累计计数当实际保留内存。

## 9. RP5：性能、正确性与运行交付

### 性能目标（待测，不是收益承诺）

- 先确保普通GET零全书扫描/零全局失效、批量身份一次、同小节引用零完整小节请求。
- 同机同版本真实教材，热导航/引用相对RP0合法基线中位耗时至少下降50%为目标；轻量小节API中位≤150ms、已加载同小节引用≤250ms为目标。未达到需报告实际主阶段，不能通过弱化校验或计时提前结束达标。
- 每类至少5次，0/1/2/多图小节和新/已加载文档分开；冷启动、浏览器缓存与系统缓存分别注明。样本少时只报范围/中位数，不声称p95。
- 首屏T0—T5、选择、定位、滚动都复测；320ms人为手势间隔不计作渲染耗时。引用必须等异步处理/定位完成，不能沿用已修正的47ms错误样本。

## 10. 完成定义

新版fixed与兼容读取路径都不再由普通GET触发全书扫描或全局清缓存，图片身份批量读取，引用跳转复用当前文档与定位数据；真实性能目标、换版/资源正确性及五条路径有同一稳定版本证据，实际运行版本明确。

RP4的高级文档池若尚未安全实现，要单独标为未完成，不能影响已交付P0的真实性；整体计划不得仅凭P0通过标全量完成。未验证的触控板/移动端、长期内存和跨浏览器结果应持续单列。
