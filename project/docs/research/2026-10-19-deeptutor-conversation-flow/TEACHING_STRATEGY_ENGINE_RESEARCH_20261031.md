# 教学策略决策器深度调研与成熟首版建议

日期：2026-10-31。范围：对照用户第三层讨论稿、当前主工作区及本地 DeepTutor/OpenTutor/OpenMAIC 源码，核实论文与官方文档。仅调研与文档交付，未改业务代码、正式服务、模型配置、教材、数据库。本结论基于静态源码核对；未进行第三层模型或页面验收。

## 1. 核心结论

支持将第三层建设为可解释、可执行、可恢复的教学决策能力。成熟首版应覆盖完整教学闭环、统一策略权威、失败回退和真实验证，而不应限定为“先实现六种策略”；也不应以框架数量、模块数量或多 Agent 争论作为成熟标准。

推荐在现有 TeachingTurn/TaskService/AgentLoop 内增强统一教学决策，沿用 13 个策略库 ID、六维只读投影、教材证据发布、Q5 状态与题目生命周期。上游可复用的主要是状态与辅助记录、按需加载、动作预算等部件；目前核对的三个本地项目均没有能无适配替换当前系统的通用心理学教学策略决策器。

## 2. 用户讨论稿的保留、修正与补充

保留：规则约束与情境选择结合；目标、动作、深度、交互与退出条件结构化；学生反馈推动再决策；不把策略分别建成 Agent；不把自报理解当掌握；决策摘要只保存可核查理由。

需要修正：

- 讨论稿新设 12 个 S01—S12 与当前 13 个策略库重叠。保持 `knowledge/teaching_strategies.json` 唯一权威，建立能力映射，不新增平行策略表。“案例先行”是样例策略的动作顺序，“教材导读”可以是来源约束与读原文动作组合，“间隔复习”是已有复习调度请求，不强行都变成顶层策略。
- 第二层不能因为分类就直接决定模板，但第三层也不必再调一次模型重读同一输入。简单情形规则选择；复杂情形可扩展已有同次结构化解析，只有材料调查后新增信息足以改变决策时，才在既有循环内再决策。调用预算必须实测。
- “比较概念”不必总生成表格或最后出题；讨论稿 S03 固定六步须受用户不出题、提示级别、时间与已有 pending 限制。
- “我想复习”不一律转主动回忆；用户只想听讲时仍允许解释，正式到期复习与普通复述分开。
- “我觉得这个实验没控制好”是评价与潜在求助，先绑定实验、询问或查看控制条件，不直接写入误区，更不直接判为混淆变量。
- 调查、求解、写作三阶段是论文的特定工作流，不能要求每个“什么是自变量”都串行执行全部阶段。
- LangGraph 的检查点不能自动解决跨库幂等；官方说明 interrupt 恢复会从节点起点重跑，节点中副作用仍需收据。是否迁框架应另以当前恢复缺陷和迁移成本判断。

需新增：策略版本和别名迁移、策略适用能力检查、动作执行收据、来源缺口后的局部修订、未完成动作恢复、图片实际看见标记、学生可跳过、跨任务隔离、失效与取消、教学效果评估中的因果边界。

## 3. 当前项目实际情况

| 位置 | 当前能力 | 主要差距 |
|---|---|---|
| agents/adaptive_tutoring.py:98 analyze_teaching_turn | 教法模式、资料需求、是否检查、困难支持 | 困难时按 worked_example→contrast→break_down→prerequisite→hint 轮换，主要受上一策略影响，缺少动作效果证据 |
| 同文件 TeachingTurn | 待答题、插问、辅助评分、提示级别、状态同步 | 策略、状态与生成提示耦合；缺少统一动作计划和执行结果投影 |
| 同文件 LOCUS_STRATEGY / STRUCTURE_NOTES | 六维困难映射与结构提示 | discrimination/procedure/pace 直接映射，不足以表达候选过滤、证据不足和退出 |
| agents/teaching_policy.py | 唯一策略库、别名、模式和选择规则 | 与旧 planner、strategy_router、新 TeachingTurn 多处决策需明确权威顺序 |
| agents/teaching_planner.py / strategy_router.py | 旧结构化教学计划与动作路由 | 第三层建设应收敛调用，不再另设与之并存的必经 LLM |
| agents/deeptutor_learning、learning_feedback | 上游学习策略、题目公共投影、辅助历史 | 已存在，优先复用，不再从 D 盘重复复制同一功能 |
| TaskService/Q3/Q4/Q5 | 任务身份、授权工具、暂停恢复、位置与状态服务 | 统一决策要实际被聊天、选区、计划插问及显式题卡入口消费 |

策略库 render_hint 也存在冲突：直接讲解默认“之后用小问题确认”，苏格拉底写“连续提问”；需在编译决策时让本轮约束优先，并将允许检查与必须检查分开。

## 4. 本地开源源码审计

### DeepTutor

固定提交：6cf793bd868ba5ecbe64722936d4be8fab5a01df，Apache-2.0。

- `D:/deeptutor/deeptutor/learning/policy.py`：纯决策，is_assessed_mastered、learning_stage、next_objective、公开待答题。可复用学习状态与目标的决策边界；本项目已迁入相应能力，应做版本差异核对再选择性迁入。
- `learning/pending.py`：选项解析、明确提交识别、PublicPendingQuestion。继续复用题目身份与公开/私有分离，勿在第三层再写一套答案识别器。
- policy 的 is_mastered 允许 learner_mastery_overrides 作为路径放行来源，且与系统测得区分。这不等于本项目应把“我懂了”记成掌握；继续由本项目证据政策决定。
- 论文的调查—引导—写作、Trace Forest 说明整体架构，不能直接证明本地每次普通聊天都按相同工作流执行，更不能证明一个具体策略对本项目有效。

### OpenTutor

固定提交：a890519f3632efa14cf24449b366b3b9d901eecf，根许可证 MIT。

- `apps/api/services/agent/agents/prompts.py:38` `_load_strategy_fragments`：按段加载并缓存策略片段。适合参考按需注入，优先使用本项目已有 JSON 库与加载器，避免再维护一份策略正文。
- `agents/tutor.py:137`：最多装载两个相关片段；选择基于英文关键词，未命中默认前两个。可借鉴限制提示大小，但不要迁入这个选择算法作为中文教学决策。
- 同文件强制 SOCRATIC_GUARDRAILS；`prompts.py` 明写 NEVER give direct answer。与用户直接讲解要求冲突，不应照搬。
- `services/agent/teaching_strategies.py`：0—2 条策略记忆提取、去重、最多 20 条、按轮数/时间节流；background_runtime.py 调度。适合适配为后台观察候选，不能直接当实时策略选择器。
- 策略有效性评分存在掌握快照变化逻辑，但变化与策略的因果归因未得到证明；反复表达或模型自评不得自动升级为“这类策略对该学生已证实有效”。

### OpenMAIC

固定提交：d128ef67c920571a86ce8a7c0430185689ab3d45，根许可证 MIT；各 packages 和素材有独立 LICENSE，迁入时再逐项核对。

- `lib/chat/pi/director-loop.ts`：runPiDirectorLoop 接受 abortSignal、maxAgentTurns、maxActionsPerAgent，记录 directorToolTrace、endReason、userCued 和 sessionClosed，并保留 request-scoped 只读场景证据。
- `lib/action/engine.ts`：动作按类型执行；`lib/buffer/stream-buffer.ts` 有带 AbortSignal 的 onActionReady；`lib/playback/engine.ts` 记录讨论是否消费。
- 价值是“动作有预算、可取消、有执行状态、可等待学生”，不是“让多 Agent 多说几轮”。TypeScript 引擎依赖它的场景/画板/播放器，不能直接放进 Python 主循环；已有 AgentLoop 应先补相同语义，前端将来需要同类课堂动作时才选择性迁入。
- 讨论稿把 OpenMAIC 概括为 LangGraph 不够精确：本地所查课堂导演入口使用 pi-agent-core；不能以某个生成工作流用了 LangGraph 推断全部运行链路相同。

### 外部核验

IJCAI 2026 的 ITS 综述支持从领域、学生、教学与交互等职责分析系统，但没有给出适用于所有课程的阈值。DeepTutor arXiv v3 明确为技术报告，实验含学生模拟器；不能将论文分数直接作为我们实际学习增益。OATutor 官方仓库可作为 BKT/提示支架的后续定点审计对象，本轮未读其具体实现，不列为已审核的直接迁入项。

## 5. 成熟首版的建议设计

在现有流程中形成单一 TeachingStrategyPlan，逐轮由相同 task 和目标身份绑定。它是现有任务协议的可选扩展，不改六维 GroundedTurn 版本，也不引入第二个学习状态库。

决策输入：已绑定用户请求及约束、六维只读投影、有效教学目标、pending 公共视图、近期已发布动作及反馈、来源覆盖/图像可用情况、现有工具授权与能力。画像或分类缺失时明确缺失；不得猜测疲惫、认知负荷或能力值。

计划建议字段：decision_id、policy_version、task/revision、target_ref、主策略与最多两个辅助策略、有限有序 moves、每个 move 的所需证据/能力、depth、interaction_boundary、可观测 stop_conditions、fallback、可核查 decision_summary。需同时记录“选择了什么”与“实际执行了什么”，自然语言解释已发出不等于学生已经理解。

动作采用既有能力：read_material/retrieve_course/read_source、展示已验证原图、讲解/样例/比较、已有提示支持、ask_user、既有正式题卡与复习命令。能力请求只是建议，仍由 Q4 授权和原服务执行。下一步必须走 Q2/Q5，不从策略里另造目录位置。

优先级：取消/失效与权限 → 用户明确约束及题目披露政策 → 有效题目/任务身份 → 正式作答证据与学习阶段 → 认知需求/困难标签 → 历史策略偏好。标签可提出候选，不越过前面的边界。

单轮循环：读状态 → 规则过滤 → 简单直定或已有模型候选 → 结构/边界校验 → 现有工具调查 → 仅在新证据改变可行性时局部修订 → 执行与发布 → 保存真实动作结果 → 等待反馈。来源不足优先补相应缺口，不自动重跑全部决策；学生仍不懂时根据明确反馈改变表达或补前提，不固定轮换，也不默认学生有误区。

一开始应完整覆盖现有 13 策略的合法选择与回退，不要求每种都立刻拥有新 UI。是否需要图、表、开放问题由材料和用户需求决定；未配置的图像生成等能力不能被标为已完成。

## 6. 迁入顺序与复用清单

1. 先审计本项目已迁入的 DeepTutor pending/policy/feedback 与现有 TaskService；复用已有实现，建立决策权威表和调用图。
2. 扩展已有策略 JSON 的适用条件、能力需求、动作组合和退出条件；沿用 13 个 ID 与别名适配，暂保留模型工具的 9 名 enum。
3. 在 TeachingTurn 中形成并消费结构化决策，接 Q3/Q4/Q5、选区与显式题卡。只有新行为必需的协议和边界胶水自行编写。
4. 按 OpenTutor 思路复用按需片段、限条、节流；后台效果观察只存带证据的候选，沿现有删除/epoch 清理，不自动写偏好或掌握。
5. 按 OpenMAIC 的执行记录、预算与取消模式扩展现有循环；只有相同前端能力存在时才考虑复制具体 TS 执行器。
6. 每段实际复制保留来源文件、固定提交、SHA256、原许可证及改写说明；参考重写与直接迁入分别登记。全仓库 LICENSE 不能替代素材/子包核查。

## 7. 验收与决策质量

工程边界与教学效果分别验收。至少覆盖：明确概念直接解释、双对象比较、原因推导、不懂但不强制出题、已有题只给提示、完整讲解请求、否定作答、选区原图、连续追问、插问返回、暂停取消、同 revision 并发、资料缺失、模型失败、正式复习。

状态与权限错误、答案键泄漏、无证据掌握更新必须为零；所有策略和动作来自合法能力。指标记录原始分母和失败：候选接受率、任务目标覆盖、来源覆盖、无意义追问、同目标机械重复、策略调整后表现、首字/总时长、模型次数、动作恢复与取消。

专家对同一场景可接受多个策略，不用唯一字符串匹配当教学质量。真实对照从同一状态快照开始，固定模型和材料；已有六维 30 条留出集被观察过，不能当全新盲测。学习增益需等价前后/迁移题与受控设计，回答满意度和自报理解不能替代。

成熟首版交付条件：策略全目录及回退可用、同任务跨轮恢复可靠、所有关键入口消费同一决策、真实模型和页面有证据、延迟无无解释恶化、失败不隐瞒。数字阈值应按基线和标注一致性制定，不把讨论稿建议阈值当行业结论。
