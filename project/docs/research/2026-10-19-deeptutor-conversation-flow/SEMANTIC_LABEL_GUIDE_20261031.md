# 语义标签标注规范（阶段 B2，2026-10-31）

对象：`psy-6d-v1` 中可分类的四个标签集。注册表 `knowledge/semantic_labels.v1.json` 已冻结；本文件只解释定义，不改取值。
标注者要求：独立标注，**不看规则代码、不看模型输出**；只看原始输入与提供的上下文摘要。

## 1. 标注单元

一行 = 一个决策点：

```json
{"case_id": "B-001", "text": "我还是分不清信度和效度", "context": "无待答题",
 "labels": {"difficulty_locus": ["discrimination"]}}
```

- 标签必须能在 `text` 里找到依据；标 `quote` 时逐字复制，不改写。
- 无法判断就不写该维度（弃权），**禁止写 `unknown`**。
- 一次只标“这段话本身能证明什么”，不推断能力、不推断掌握、不推断误区。

## 2. 认知任务 `cognitive_demand`（可多标签，≤3，按任务顺序）

| 取值 | 定义 | 收 | 不收 |
|---|---|---|---|
| `recall` | 要求回忆或列出已学内容 | “说出三种类型”“默写步骤” | “什么是X”（这是理解，不是回忆） |
| `comprehend` | 解释、说明、比较、找关系 | “为什么”“有什么区别”“怎么理解” | 只要求一个名词定义且无解释要求 |
| `apply` | 把概念用到具体情境 | “如果换成随机分配会怎样” | 情境只是例子，核心仍是解释原理 |
| `analyze` | 拆要素、找变量、定位问题 | “找出自变量”“分析这个设计” | 直接问结论对错 |
| `evaluate` | 按标准判断合理性 | “这个设计合理吗”“有没有漏洞” | 只问“是什么/怎么做” |
| `create` | 设计方案、提出改进 | “帮我设计一个实验”“提出改进方案” | 只要求评价现有方案 |

规则：一句话同时要求“分析+评价+设计”时三条都标，顺序按原文出现顺序；超过 3 条按前三条。

## 3. 自报状态 `self_report`（单标签）

| 取值 | 收 | 不收 |
|---|---|---|
| `understood` | 明确自报“懂了/明白了”，**且没有紧接着的疑问或作答** | “懂了，但为什么…”（这是 continued confusion，弃权） |
| `confused` | 自报“有点懵/脑子乱”，未指出具体卡点 | 指出具体卡点（应标 `difficulty_locus`） |
| `none` | 明确说“没问题/没有疑问” | 沉默、不说话 |

边界：`self_report` 只记录学生**自己说的**，不是诊断；不得据此写掌握度。

## 4. 困难定位 `difficulty_locus`（单标签，按具体优先）

单标签内部优先级：`pace > memory > discrimination > procedure > comprehension`。同时出现两类困难时，选更具体的一条。

| 取值 | 收 | 不收 |
|---|---|---|
| `pace` | 太快、跟不上、信息量太大 | “太难了”（这是难度，不是节奏） |
| `memory` | 记不住、背不下来、想不起来 | “不理解所以记不住”（理解问题优先） |
| `discrimination` | 分不清、搞混、区分不开两个概念 | 名词“混淆变量”（这是术语，不是困难） |
| `procedure` | 不会做、不知道第一步、无从下手 | “不会解释”（表达困难，不是程序） |
| `comprehension` | 没听懂、不理解、看不懂 | 只是要求换个说法（这属支持需求） |

## 5. 参与信号 `engagement`（单标签，单轮信号）

| 取值 | 收 | 不收 |
|---|---|---|
| `help_seeking` | 明确求助但未要答案 | “给我点提示” |
| `answer_seeking` | 要答案/要完整解答 | “先别告诉我答案”（这是约束，反向） |
| `skip` | 明确不做、跳过、结束本题 | “这题有点难”（尚未放弃） |
| `off_task` | 与课程无关的闲聊 | 换学习话题（仍有学习意图） |
| `engaged` | 正常作答/正常提问 | 默认不标，避免与 `none` 重复 |

边界：`engagement` 只影响“本轮是否以等待学生结束”，不影响给不给答案；披露由约束决定。

## 6. 不标的东西

- 掌握度、正确率、能力等级、误区内容（由 `LearningEvidence` 与误区管线负责）。
- 情绪诊断（`affect` 是只读字段，不从文本推断）。
- 长期偏好（走偏好确认流程，不是标签）。
- 对象 ID、页码、题目编号（由服务端绑定）。

## 7. 流程与一致性

1. 两人独立标注同一批，互不沟通；分歧记录在 `disagreements` 字段，不在标注时就地“商量出统一答案”。
2. 用 `scripts/annotation_agreement.py A.jsonl B.jsonl` 计算逐维/逐标签 κ 与完全一致率。
3. κ ≥ 0.6 才算定义可用；< 0.6 先审阅分歧、改本文件定义，**不得通过追加规则或合并标签掩盖**。
4. 盲测集：标注前冻结注册表与代码 sha256；标注者不得查看规则、留出集或历史评测结果。
5. 单人时只能报告“工程标注”，不得称人际 κ。
