# 根据本次输入生成并执行学习计划：实施计划

2026-10-23；状态：待实施。源码核对基线 main `c3b86f6`，执行前重核最新提交。对应总计划Q5.7、Q5.14、Q5.16—Q5.19及Q3上下文接入，不另建第二套学习系统。

## 1. 目标

学生输入“今天有一小时，想学自变量和因变量，基础弱，先讲不要考试”后，系统利用有效教材和已知画像，生成范围、顺序、预计用时、教学活动和完成标准明确的本次安排。学生可以调整、确认；确认后按同一份计划教学，支持插问、继续、刷新与重启。

必须区分：长期学习路径是持续目标；本次安排是当前会话选定的一段学习活动。结束本次安排不代表长期路径完成，不把“我懂了”记成掌握，不把估算时长当作实际学习时间。

## 4. 业务契约

### 4.1 本次需求

`StudyRequest`只描述本次需求：goal、scope（主题/章节/选区及可信source refs）、time_budget_minutes、prior_knowledge、target_level、teaching_preference、practice_preference。每个采纳值保留来源：本次明示/已确认画像/已确认路径/公开假设。

- 优先本次明示，再用可兼容的已确认信息；不由语气猜基础或掌握度。
- “今天30分钟”不覆盖长期“每周五小时”；“以后都先讲后练”才按既有偏好服务处理长期更新。
- 仅缺少影响范围/目标的必要信息时ask_user；时间缺失可提供清楚标注的估算，不强制填满四个问题。
- 普通概念问答不自动创建计划；“今天先学什么”“帮我安排一小时”等明确安排请求可触发。含糊表达不得重建路径。

### 4.2 本次计划

`SessionStudyPlan`至少包含：schema_version、plan_id、revision、student/session/course绑定、path_id/path_revision（可空）、status、goal、约束及假设、source binding、items、current_item_id。

每个item含稳定item_id、关联objective_id、kind（讲解/例子/辨析/可选自测/回顾）、目标与来源、estimated_minutes、顺序理由、完成标准、status。区分planned/in_progress/explained/skipped/done，不能映射为mastered。

- 时间为正数，程序核算总和不超过学生预算；太紧时减少范围并说明未纳入内容，不生成无法执行的“一小时全掌握”。
- 学生“只讲解不考试”时不安排强制测试；可选活动明确标可选。
- 已有路径优先选取相关目标，不创建竞争教材目录游标；范围外主题用已有Q5合法路径机制或独立本次安排，不偷偷重写当前目标。
- 每个教学活动能追溯到合法教材原文。计划顺序理由/预计用时属于教学建议，不能伪称教材事实或考试重点。

### 4.3 持久化与并发

复用现有SQLAlchemy和任务库，不建JSON学习库。草稿/历次反馈保留在现有task_requests结果；当前生效安排绑定在现有Q5 session binding。

执行前核对Q5BindingRow是否已有同义字段；若无，采用一个可空的`session_plan` JSON字段保存版本化当前安排（含上列身份和revision），不挤进source_scope伪装成来源，不另建路径引擎。历史修订由既有任务结果保留。任何替代存储方案须先证明现有字段语义及刷新/新任务恢复可达，不能只存在进程变量。

新字段需要显式、可重复执行的增量迁移与旧库兼容测试；init_db/create_all不会自动给旧表加列。正式库迁移前按既有备份规程执行；本轮先隔离库。读旧绑定无字段/空值视为无本次安排。

计划revision独立于path_revision。命令按student/session/command_id幂等；同一base_revision并发推进只有一个成功。来源失效、路径已切换或revision冲突时拒绝旧确认/推进，保留旧草稿供调整。

## 5. 实施批次

### SP0：冻结调用链与样本

- [ ] 核对实际TaskService→Q5Runtime→服务→Q3→前端入口、活动路径和开关；保存当前目录草稿行为，不用旧报告替代当前代码。
- [ ] 固定六类输入：新目标、已有路径、时间缩短、只讲解、插问、普通单问；记录期望与来源版本。

### SP1：需求与画像接入

- [ ] 从本次输入提取有来源的约束，类型/数值/范围服务端校验；画像按可信student_id读取，不能模型指定其他学生。
- [ ] 已知信息复用，必要缺失用现有ask_user一次补问；部分回答可继续，不循环重复问。
- [ ] 显式区分一次性约束与持久偏好；更新、撤销沿用现有记忆服务。

### SP2：资料与计划生成

- [ ] 接通真实LLMPlanGenerator/现有服务；按选定范围先读取真实目录与有界原文，检索经Q3/Q5共用边界，不改LightRAG内部。
- [ ] 有长期路径则引用现有目标；无路径按范围生成有来源的合法草稿，不默认第一章、不每节仅取首点后宣称全覆盖。
- [ ] 生成本次items、顺序理由、预计时间和完成标准；程序验证时间/来源/目标身份/类型/重复/关系与遗漏说明。
- [ ] 对无依据目标或超预算结果做有界修订或受控失败，不能无限调用模型；不以短摘录声称整书全覆盖。

### SP3：展示、反馈和确认

- [ ] 用结构化数据展示“本次目标、安排、预计用时、依据/假设、未纳入内容、下一步”，不单独生成与保存数据不一致的漂亮长文。
- [ ] 自然语言支持缩短时间、减少范围、加深讲解、改变教学偏好和顺序；不能仅改第一个目标名。改动只影响未完成活动，保留学习事实。
- [ ] 草稿可改，确认前不进入study；确认绑定明确plan_id/revision。重复点击幂等、旧卡明确过期；有路径时不重新确认整条长期路径。
- [ ] 计划/画像/目录等结构化结果不硬造教材引用；其中教材知识陈述继续走原文核验。使用可信任务结果类型区分，不能由模型自报类型绕过发布门禁。

### SP4：同一计划驱动教学

- [ ] Q3每轮注入目标、活动、预算、基础和偏好；既有mastery_status可附本次安排，build/revise/mode复用已有服务，必要时做最薄参数扩展，不重复另建循环。
- [ ] 按计划先讲/例子/辨析，学生明确继续再推进；插问不移动原位置。教材next由Q2权威导航决定，活动next只切当前安排，不能混用。
- [ ] 讲解成功发布后才记录explained；取消、质检拒绝或晚到不推进；“懂了”不产生掌握分。出口标准可待评，不强行接未完成的正式评分。
- [ ] 暂停、刷新、重启和新任务恢复plan/current_item；跨会话路径切换保留对应身份，不串进度。修订时间预算不抹掉已讲活动。
- [ ] 结束时总结本次已讲/未完/可选后续，不自动宣布路径完成，不强制把剩余内容继续教完。

### SP5：验证与交付

- [ ] 扩展现有Q5服务、任务、预算/发布和暂停恢复测试；隔离旧库迁移/并发、失败无写入验证。
- [ ] 同一稳定提交真实模型→实际页面完成“请求→必要补问→草稿→调整→确认→讲解→插问→返回→继续→刷新”。保留全部失败与模型实际输入，证明画像和预算确被使用。
- [ ] 核对来源版本/引用/媒体及LightRAG或Q2实际后端；不以工具schema存在代替真实调用，不以测试夹具预填计划冒充模型生成。
- [ ] 提交源码、迁移、必要前端产物、测试和记录；不提交教材、密钥、学生库或runtime。不自动启用正式库迁移或改变服务配置。

## 6. 最小验收矩阵

| ID | 输入/操作 | 必须证明 |
|---|---|---|
| S01 | 一小时、变量、基础弱、只讲不考 | 同一需求进入模型；安排总时长≤60分钟，无强制考试，有来源 |
| S02 | 已有基础/目标/偏好 | 不重复补问；已有路径不被覆盖，计划量和教法实际不同 |
| S03 | “改成20分钟，只学自变量” | 结构化范围和时间同步缩减，保留原已学事实与修订历史 |
| S04 | 有活动路径时“今天怎么安排” | 使用该路径目标生成本次安排，不因has_path直接忽略请求 |
| S05 | 普通“什么是自变量” | 正常回答，不自动建计划或强制补问 |
| S06 | 计划确认→讲解→继续 | 来自同一plan/item；已发布才记讲解，未评分不记掌握 |
| S07 | 插问→返回、暂停/刷新/重启 | 当前活动与目标恢复；不串路径、不重复生成/推进 |
| S08 | 来源换版、预算异常或模型造目标 | 服务端拒绝/有界修订；不保存假计划或混版本 |
| S09 | 重复确认/两个窗口同时继续 | 幂等和revision生效，最多前进一步 |
| S10 | 取消/质检失败、偏好撤销 | 不保存/推进晚到结果；后续教学使用新偏好 |

追加对照：同一教材与主题，分别用“零基础20分钟只讲解”和“已有基础60分钟想练应用”生成计划，人工核对范围、活动与教学深度确有合理差异；不要求每次文案固定。

## 7. 执行边界与完成定义

本专项由Q5/集成负责人统一接公共TaskService、Q3上下文和前端计划卡；工具窗口可提供只读目录/原文/画像接口，未交付前可先调用同一服务，不把首批工具全部接入作为计划生成前置。LightRAG部署和滚轮窗口继续各自任务；不同时编辑其未提交代码。

不扩展全书40讲/考试重点承诺，不实现正式题卡评分或复习调度；全书规划请求必须按Q5.16—Q5.19返回真实范围与覆盖，不能被本次安排静默降成第一章。

只有计划生成真实接线、数据校验、调整确认、同计划执行与恢复均有证据才算完成。模型文字好看、底层类存在、旧Q5页面确认成功都不能替代这一闭环。
