# 教学策略、学习证据与交互能力实施计划

日期：2026-10-26。状态：实施中，TA0核对、TA1规则/宿主接线、TA2辅助证据补强及TA3展示首批已落地；真实回合与相关页面验收通过，完整多入口及原生统一学习服务未完成。依据：[调研与复用对照](TEACHING_AGENT_CAPABILITIES_RESEARCH_20261026.md)及用户附件。当前证据和保留失败见[实施记录](TEACHING_AGENT_IMPLEMENTATION_LOG_20261026.md)及[卡片交付](TEACHING_CARDS_IMPLEMENTATION_LOG_20261026.md)。

## 1. 目标与现有计划关系

让系统能根据本次输入和可信学习记录选择讲解、引导或练习，知道学生为什么卡住，允许逐步求助，并将真实作答用于后续复习。用户仍可要求直接解释、跳过练习或只查教材。

本计划细化主计划第21节NT3及已有Q5教学/评估/复习范围，不新增第二套AgentLoop、学习库或偏好设置。完整回答链路以DeepTutor原生迁入为目标；原生学习服务成为单一写入方后，旧Q5只做迁移或兼容投影。旧`NATIVE_CONTRACT.md`中与第21节相冲突的历史架构说明不作为新实现方向。

交付不包括自训知识追踪模型、完整LMS、额外多Agent调度、外发提醒和未经证实的考试重点预测。图谱关系和重点表达使用已有能力，不重建图谱。

## 2. 统一运行契约

正常链路：用户消息 → 当前明确要求/临时偏好 → 读取必要学习状态及待答题 → 轻量规则选择教学动作 → 原生工具/检索循环 → 输出正文与必要卡片 → 有效事件提交学习服务 → 保存/投影。

- 本轮策略只设一个权威入口。已有`teaching_policy`、`adaptive_tutoring`与原生mastery模式必须对账，避免三方各自提问、评分或追加生成。
- 策略默认不新增LLM调用；计划生成、真实作答评分等确有需要的任务单独调用并计时。简单查页、查定义不强制生成练习。
- 教学风格为直接讲解/引导探索/分步练习/备考复习；学习生命周期仍为outline/study/review。允许组合，不增加彼此矛盾的全局开关。
- 本轮明确指令优先于历史偏好。用户要求完整解释时，不执行旧策略中无条件“避免完整答案”的限制。
- 同一题的辅助程度、作答、评分和掌握更新使用同一交互身份、命令幂等键及revision。取消、重复点击、刷新和重试不能重复计分。
- 保存来源版本、原文块、题目版本与评估依据；来源失效或答案键不可信时阻断正式评估，不给负面掌握分。

## 3. 分阶段实施

### TA0：固定当前基线和写入契约

1. 记录最新main、实际服务身份、原生迁入进度和已有相关提交；核对原生服务与`agents/deeptutor_learning`是否已经包含所需源码。
2. 列出输入入口：普通聊天、学习路径、PDF选区、练习、ask_user恢复；逐个明确状态读取方、事件生产方、唯一提交方。
3. 对齐已有Q5 pending question、evidence、review契约；复用原生类型和服务，不建立同义表。需要增字段时明确迁移、旧记录缺省和删除语义。
4. 固定基线样例、调用次数、首字/完成耗时及状态快照。不得把旧分支测试结果写为当前部署通过。

完成条件：原生NT0/NT3相关契约可用，接口与状态所有权可审阅；后续实现有稳定SHA。原生迁入尚未稳定时，可先做样例/协议设计，暂停公共入口接线。

### TA1：教学风格、偏好与提示统一（第一优先级）

1. 将现有规则策略接入原生prompt/mode边界；停用同轮重复的旧TeachingPlanner与辅助策略调用。保留有效的困难识别和插问识别逻辑。
2. 消费现有next/session/long偏好及清除行为；可从自然语言指定本轮直接讲、少提问、多举例，不增加一组重复设置。
3. 沿用练习三级提示，第四动作是明确“查看完整解释”。服务端记录实际提示级别、解答已见和交互顺序，刷新不重置。
4. 引导模式每次只提出与目标有关的一个有效步骤；直接模式完整解释。用户拒绝测试或只要例子时，不强行进入待答状态。
5. 对教材重点提供来源类别；没有考纲或教师依据时只表达教学建议。关系解释区分教材明确关系与模型推断。

完成条件：直接与引导能稳定切换，提示程度可恢复，求助不误记答错；不因策略统一新增每轮模型调用。

### TA2：正式题目、证据与误解记录（第二优先级）

1. 复用原生待答题和mastery工具；有可信题干、来源及私有答案/rubric后才登记正式题目。公开卡片和前端事件不得包含答案键。
2. 出题作为本轮最后的教学动作；下一次消息区分作答、插问、跳过、延后、纠错。插问保留待答，返回原目标不串题。
3. 从实际提示事件计算辅助程度，替换不能表达真实帮助强度的固定值。保留原始学生作答、评分结果和评估版本。
4. 沿用EvidenceDecision和原生LearningEvidence，区分独立/辅助、暂定/核验、自报/观察；不将旧辅助检查直接升级为正式成绩。
5. 常见混淆优先记录为误解假设，例如信度/效度、相关/因果、自变量/额外变量；绑定学生原话和题目，支持纠正、撤销与删除传播。
6. 自评信心沿用原字段；掌握估计可信度初期使用证据数量、独立性、时效与核验状态解释，不输出未经校准的精确概率。
7. 概念/设计题采用可追溯rubric及必要教师复核；视觉任务须真实图像证据，来源缺失、看不到图或评分不可靠均不产生负面掌握。

完成条件：同一真实题目完成出题—作答—评分—证据—状态恢复；掌握更新可追溯，重复/并发操作只有一次有效结果。

### TA3：交互卡片增量接入

先复用现有题卡和动作，不替换聊天页面。补充三种有限卡片：分步展开、概念对比、学习进度。

- 统一最小协议：schema版本、card_id、关联interaction/objective、revision、内容、source_refs和允许动作。只允许已登记卡片，不接受模型任意脚本或HTML。
- 展开解释、请求提示、提交答案、延后、返回路径均调用既有服务端动作；本地按钮状态不作为学习结果。
- 分步内容若已生成，展开时直接复用；需要新取证或新生成时明确显示进度，不为每次展开自动调用模型。
- 保留正文流式、Markdown/公式、上标引用、原图、手机布局、键盘可操作性和刷新恢复。不能因卡片重新生成已保存回答。
- 对比卡显示差异、易混点和教材来源；进度卡显示讲过/作答/待复习，不把“已阅读”画成掌握率。

完成条件：题卡和三种增量卡片动作可恢复、幂等、不泄露答案键；浏览器重载后与服务端一致。

### TA4：复习队列与可解释调整

1. 复用原生RetentionScheduler和SpacedRepetitionScheduler；核对时区、当前时间注入及生产调试开关，不自行再写固定间隔算法。
2. 接应用内待复习列表，显示原因与关联证据，例如间隔到期、独立作答薄弱或反复混淆；旧薄弱项列表与新队列去重展示。
3. 支持开始、延后、完成与返回原学习路径；到期不强制把当前讲解改成复习课。队列计算不依赖记忆worker常驻。
4. 复习作答走TA2同一状态机；解释/跳过/提示不冒充独立回忆。来源失效进入待核对，不当作遗忘。
5. 只按有依据的困难、用户选择和近期有效证据调整教学方式；历史策略效果是观察性线索，不宣称因果最优。
6. 后续有标注数据再单独评估pyBKT/pyKT；先做离线分组与时间切分，防同题泄漏，未校准不用于正式掌握概率。

完成条件：队列跨刷新/重启稳定，可解释、可延后，不打断用户意愿；复习事件仅提交一次。

### TA5：联合验收和发布

在同一稳定宿主完成下表，分开记录单元/接口、真实模型和浏览器结果。仅通过替身测试不算真实教学通过。

| 编号 | 场景 | 必须满足 |
| --- | --- | --- |
| TE01 | 同题“直接告诉我”与“带我思考” | 策略不同，显式要求生效，无旧策略强制追问 |
| TE02 | 查页/查目录/普通解释 | 不无故出题、不更新掌握、不额外调用旧规划模型 |
| TE03 | 三级提示→完整解释→刷新 | 顺序和辅助程度保留，可直接要求完整解释 |
| TE04 | 求例子/看图/换解释 | 不误判为答错；教材例子与自拟例子明确区分 |
| TE05 | 提示后答对与独立答对 | 学习证据不同，辅助结果不冒充独立掌握 |
| TE06 | “我懂了，下一步” | 记录自报理解；由权威路径推进，不增加正式掌握分 |
| TE07 | 信度/效度混淆→学生纠正 | 假设有原话来源，可撤销，不永久贴标签 |
| TE08 | 临时/会话/长期偏好→清除 | 作用域正确；学生、标签页和会话不串数据 |
| TE09 | 出题→插问→返回→作答 | 保留同一待答题与目标，答案键不出现在公开数据 |
| TE10 | 重复答复/刷新/并发/取消 | 幂等、revision检查有效，不重复推进或评分 |
| TE11 | 三种新卡片及原题卡 | 手机与键盘可用，动作到服务端，刷新不重新生成 |
| TE12 | 复习到期→延后→完成 | 队列和原因一致，不强制切换学习模式 |
| TE13 | 来源换版/无原图/答案键存疑 | 阻断不可信评估，不扣负面掌握，不伪造来源 |
| TE14 | 清除记忆/撤销误解/删除事件 | 派生画像、队列与历史投影按既有删除契约失效 |
| TE15 | 自评信心高但证据不足 | 不混用confidence，不编造精确可信概率 |
| TE16 | 教学重点和知识关系 | 有依据类别；不将图谱中心性当考试分值 |
| TE17 | Q3/Q5、选区、视觉、ask_user | 原生统一入口与事件可证，不恢复第二套循环 |
| TE18 | 同配置性能对照 | 策略选择无新增必经LLM调用；单列检索、评分、正文耗时，保留流式/取消性能 |

TE01、TE04、TE07、TE16需人工抽查教学内容；TE09、TE11、TE12、TE17需真实模型与页面证据。功能通过不等于已证明长期学习效果。

## 4. 文件影响范围与窗口协作

| 范围 | 预计触点 | 协作要求 |
| --- | --- | --- |
| 原生学习核心 | vendor已审计学习源码、现有迁入模块、学习服务适配/迁移 | 原生NT3负责人统一；先核对已迁入源码，优先直接调用 |
| 策略与上下文 | teaching_policy、adaptive_tutoring、原生prompt/mode注入、偏好模型 | 单一策略负责人，清点所有调用方；不叠加旧Planner |
| 公共入口 | TaskService、原生桥、入口编排、事件投影 | 与原生完整迁入窗口共用一个负责人；只在稳定SHA后接线 |
| 页面 | 现有聊天/练习/偏好/卡片渲染及构建产物 | 可先开发协议与独立渲染样例，公共app入口集中合入 |
| 数据/API | Q5兼容、证据、复习、删除与权限 | 单写入和学生授权；先隔离迁移，不自动触碰正式库 |
| 验证 | 既有学习/策略/练习测试、黄金案例、浏览器脚本 | 共用同一schema与基线；有效证据记录运行身份和SHA |

可并行做卡片样例、教学黄金案例、上游源码差异核对；策略入口、状态写入和迁移不可由多个窗口各自实现。阅读器性能窗口继续独立推进，本计划不占用其PDF生命周期与发布缓存修改范围。
