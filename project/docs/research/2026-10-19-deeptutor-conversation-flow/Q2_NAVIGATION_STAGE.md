# Q2-B：章节导学与下一目标导航检查点

日期：2026-10-19。对应现行计划优先项 Q2.7、Q2.8 的基础导航链路；不是这两项的完整验收，也不减少 Q0—Q6 的完整能力范围。

## 交付与接线

- 原样提取固定版本 DeepTutor `deeptutor/services/courses.py::SyllabusUnit` 到本项目 `knowledge/local_rag/syllabus.py`，保留稳定 ID、position、title、topics、covered 及序列化方法。许可证、来源符号、来源文件与迁入文件 SHA 已登记。
- 新增本项目 `knowledge/course_navigation.py`：读取已发布的 11 章目录、正文标题和来源块，按章/节及叶子标题构成有序路径。路径类型明确是 `textbook_heading_order`，不是模型猜测的通用概念先后关系。
- `TaskService` 在模型识别前解析章节请求，给上下文附带服务端导航目标。章节中文数字、阿拉伯数字、实际章节名称汇入同一目标；用户明确章节优先于阅读器当前章节。
- `TutorOrchestrator` 按目标 ID 读取教材正文，再走原有依据核验、生成、质检、引用和学习记录提交。导航口令不再充当相似度检索查询，补召回也不会悄悄扩展到其他章节。
- 下一知识点按当前章标题序列选择；下一节、下一章分别按层级选择。没有已确认路径、版本失效或范围结束时返回澄清/结束提示，不伪装成“教材不存在”。
- “没听懂，请换个说法”等简短追问继续读取当前目标，不重新采用页面停留位置；显式新概念仍交给普通任务识别，不锁在旧目录。
- 位置只在回答 `answered` 且学习记录 `committed` 后写入现有任务收据，记录 `explained=true`；不自动设置 `covered`，不增加掌握分，不创建 Mastery 计划。重复 request_id、取消、跨会话、记忆删除和教材变化沿用原任务事务边界。
- 目录讲解同时需要交代位置和正文，生成与质检共用 320 字目标/360 字上限；简化和仅提示保持原预算。

保持当前 API、页面和数据所有权，不启动或转发到独立 DeepTutor 应用。本阶段没有改动 `main.py`、实际 `.env`、正式教材、正式索引或正式学习库。
