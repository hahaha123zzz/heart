## 1. 本轮明确采用的设计

1. 当前只有一本固定教材，服务运行期间不替换教材、图片登记与索引；更新资源需停服、更新、重启。
2. 项目启动时加载已有图谱、向量、BM25、原文定位和图片标签；不重新建图或生成全书向量。
3. 完整教材与索引校验执行一次；请求期间不重复全书哈希、不再次打开 PDF 复核已登记引句。
4. 精确目标直接读；普通问题使用 BM25＋向量＋RRF＋GPU 重排；复杂或低置信度问题使用 LightRAG。
5. 普通问题不调用模型进行路由、改写、关键词提取和证据选择；最终生成回答才调用聊天模型。
6. 复杂查询仅在实际需要时进行模型关键词提取和证据覆盖判断；缓存并限制补查。
7. 当前小节/章节作为优先候选范围；明确指定的其他范围优先于阅读位置，局部不足允许扩展。
8. 图片标签提前建立；图片身份、元数据和实际字节同轮读取一次并复用。
9. 独立读取和子任务按依赖关系并行；不以共享数据库 session、共享请求状态或移除存储锁来制造并发。
10. 保留轻量请求权限、来源 ID/引用编号和路径边界检查，不恢复二次模型质量审稿或强制教学步骤重写。

### 目标链路

```text
项目启动
  → 一次性冻结版本与完整检查
  → 加载索引/模型/原文位置/图片清单
  → LightRAG 常驻实例就绪
用户输入
  → 读取上下文与已有学习状态
  → 无模型路由：A 精确读 / B 本地混合检索 / C LightRAG
  → 小节优先、章节扩展、必要时全书
  → 规则证据包；仅复杂缺口需要模型选证
  → 按需图片，尽可能并行
  → 模型流式回答
  → 轻量引用映射与保存
项目退出
  → 停止接收新检索、结束/取消在途任务
  → 关闭实例和查询缓存，再关闭模型传输资源
```
