# DeepTutor 原生教材检索与回答主链接入设计

日期：2026-10-19。状态：待用户审阅的实施设计。

后续范围已扩大：用户要求整体复用从请求/能力路由到输出反馈的完整对话流程，并已要求编写实施计划。当前依据见 [完整对话实施计划](../2026-10-19-deeptutor-conversation-flow/IMPLEMENTATION_PLAN.md)；本文件保留为教材 RAG/chat 部分的早期设计，不再作为整套对话的唯一实施边界。

## 目标与完整复用边界

用户最新要求：将 DeepTutor 全套教材检索及回答链路复用到当前项目。此前 FAST_TRACK.md 中保留原主检索、优先精简原问答流程的建议由本设计取代。完整复用以一条可运行的 DeepTutor 原生主链为单位，接通其知识库、索引、检索、上下文、Agent 循环、来源与回合服务。

推荐采用上游默认 LlamaIndex 管线及原生 chat 能力。其他 RAG provider 是按知识库选择的替代实现；完整接入默认管线不要求同时部署全部 provider。现有页面、学生与课程身份、教材原文/页码/版本和学习事实记录接在主链边界。

目标数据流：

```text
现有聊天页面 / PDF 圈选
  → 宿主请求归属、任务版本与教材资源校验
  → DeepTutorApp / TurnApplicationService
  → 会话 ContextBuilder / ChatOrchestrator
  → 原生 ChatCapability / AgenticChatPipeline
  ↔ RAG 工具 / RAGService
  ↔ 原生 LlamaIndex：分块、embedding、向量/BM25、RRF、重排
  → 回答草稿、来源、工具事件及执行状态
  → 宿主引用原文/页码/坐标核验及教学质量检查
  → 保存正式回答与有效学习事实 → 原页面展示
```

普通教材对话在新模式下进入此主链；原 TutorOrchestrator 的检索、规划和 ResponseGenerator 不再串行组织同一次教材回答。教学目标、提示限制和课程规则作为主链的受控输入，最终核验负责检查输出，避免两套回答流程重复执行。

## 方案取舍

1. **推荐：完整复用原生应用入口和默认 RAG。** 同时得到会话上下文、模型工具补查、持久化执行及来源事件，满足本次目标。
2. 仅替换 RAG，保留原回答生成。接入较窄，但不覆盖完整回答链，本次不采用。
3. 仅接 AgentLoop 并读取宿主预先提供的摘录。当前工作区已有此类未提交适配，但缺少原生检索与会话装配，本次不将其认定为完整接入。

## 教材导入、索引及来源映射

- 通过原生 KnowledgeBaseManager / RAGService 和 LlamaIndex 解析、摄取与索引生命周期发布本课程知识库，记录解析器、embedding 签名和就绪版本。使用新运行目录和索引版本，沿用已存在的不可覆盖发布规则。
- 当前教材是 DOCX 源文件和按章生成的阅读 PDF。新主链经上游解析/索引服务处理，保存来源文档 ID、文件哈希、章/节、原文范围及阅读 PDF 映射。已有 1,465 个规范块可用于来源对照，不作为必须沿用旧召回的限制。
- 上游 SentenceSplitter 可再次切分来源，生成的 node_id 不等于宿主 chunk_id。明确保存并校验 node→文档/原文范围→宿主引用映射；不靠标题或相似文字猜页码。
- 原生 embedding 服务需要模型配置和端点。第一版沿用本地 BGE 模型，通过兼容其 embedding provider 契约的本机服务提供向量，避免未经用户选择引入新的付费 embedding 服务。模型与维度、可用端点和上游索引签名必须一致。
- 检索通过原生 vector + BM25 + QueryFusionRetriever/RRF；配置原生 cross-encoder 重排。上游重排使用 SentenceTransformers，与旧 FastEmbed/ONNX 路径不同，依赖和实际设备需要独立验证。
- 就绪检查确认 BM25、向量和配置的重排实际可用；缺失依赖、模型或索引失败不能显示成完整功能已启用。
- 图片/公式沿用上游 visual_assets/source_visuals 与受控教材附件，圈选文字从服务端 PDF 提取。未匹配或歧义来源只能显示其实际精度，不能冒充 exact 引用。

## 原生回答与对话执行

- worker 内使用 DeepTutorApp.start_turn / stream_turn / 原生取消接口，经 TurnApplicationService 启动 chat 能力；宿主保留原 /api/chat 和 /api/chat/stream 请求契约，增加内部主链适配。
- 沿用学生/课程/会话服务端映射，把 request_id、task_id/revision 映射到原生 submission/turn；原生真实执行回合与旧 heart_snapshot 投影回合区分，避免投影收尾取消真实执行。
- 使用上游 ContextBuilder 和会话历史服务维护上下文、历史压缩及预算。用户风格、提示限制、当前章节和经核验的选区资料经正式上下文入口注入。
- 原生循环拥有教材 RAG 工具调用、按需补查和草稿生成；不限定成一次读取预先准备的摘录。为本课程选择教材相关只读工具和可核验来源，配置回合/超时预算；外部搜索与执行工具不自动成为教材引用来源。
- 来源事件保留 node_id、来源版本、原文和评分；从原生实际检索结果建立本轮证据集合，再由宿主验证引用和回答的支持关系。校验失败可把反馈送回同一原生主链修订，限制修订次数，失败返回明确状态。
- 主链失败不悄悄转回旧生成器。旧链仅用于显式回滚和前后对照，响应/状态中可区分实际引擎。

## 正文、事件和学习记录

- 原生服务为了会话上下文会持久化问题、工具结果及草稿，与旧“只存指针”的投影不同。增加待核验/已发布映射：只有通过宿主核验的正文显示为正式回答，并参与宿主学习事实记录。
- 当前 API 保持 progress/sources/answer/done 语义；未核验的模型 token 不作为正式 answer 发布。持久化的原生事件必须通过任务归属、有效期、版本和删除门禁才能恢复。
- 删除、清空记忆和取消需同步上游会话/回合及缓存，或实施与其生命周期一致的失效清理；失败重试不能让旧正文重新进入模型上下文。来源换版同样阻断旧回合恢复。
- 原生成绩、误解、掌握度和作答资格继续由现有学习事实规则管理；模型输出不自动升级为学生已经掌握的证据。

## 实施与验收

按以下顺序完成同一条主链，不以完成单个阶段代替整链交付：

1. **原生教材知识库。** 配置 embedding/重排，完成正式教材解析、索引构建、就绪检查、原生搜索和来源映射。验证索引版本、跨章节来源、图片和歧义引用。
2. **原生持久化对话。** 接 DeepTutorApp/TurnApplicationService、原生上下文与可实际检索的 Agent 循环，覆盖概念、比较、追问、提示和选区/公式；保存原生检索与生成的执行证据。
3. **宿主 API 与生命周期。** 接质量/引用核验、正式结果保存、事件恢复、取消/删除和学习事实；确保没有重复生成或重复记录。
4. **真实页面与默认入口。** 扩展已有 9 类黄金集，加入跨章检索、无结果、连续追问、换版与恢复；实际浏览器验证问答及引用跳转。验收后启用完整主链，保留显式配置回滚。

必须验证实际链路经过原生 RAG 和原生 chat，不只判断 HTTP 成功或回答里有引用编号。针对接入边界、来源映射、幂等/删除/取消编写必要测试，运行上游相关索引/检索/会话测试和现有主线回归。记录质量、调用次数和耗时，收益以实测为准。
