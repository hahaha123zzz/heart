# 第 02 批：Dialogue-KT 源码、在线时序与复用审计

日期：2026-11-01。原稿正文范围：88—226 行。项目基线：`e5b3c004e8eca02cd124539355ef5fe40866ee4b`。本批完成官方论文、固定上游代码及项目接缝对照，未训练模型、未调用模型 API、未读取真实学生对话。

## 结论先行

Dialogue-KT 值得作为**对话标注与知识追踪研究参考**，不能直接作为本项目第六层运行服务迁入。最值得适配的是候选知识点约束、知识点/正确性任务分解、带来源的标注保留和时间切片；最需要改的是在线可见范围、非作答语义、逐 KC 证据归属及标注审查协议。

本批建议先复用本项目已有的事件、引用、题目身份、证据门禁和任务幂等。Dialogue-KT 可以提供离线比较方法及小范围数据处理代码；其整套训练依赖、数学标签体系、数据集和评分输出不宜直接进入正式掌握写入链路。

## 1. 原稿主张核验

论文为 [Exploring Knowledge Tracing in Tutor-Student Dialogues using LLMs](https://arxiv.org/html/2409.16490v2)，发表于 LAK 2025。§4.1 明确分别进行 KC 与正确性标注，并指出整段对话标注包含未来信息、不能直接用于实时场景。其任务区分回合正确性与潜在 KC 掌握，而非逐 KC 独立判分。这些研究结果仍需在心理学场景验证。[论文版本页](https://arxiv.org/abs/2409.16490v2)

| 原稿主张 | 核验结果与适配解释 |
| --- | --- |
| 知识点和正确性分开做更好 | 论文有此陈述，代码也分任务调用；这不自动证明本项目每条消息都要增加两个串行模型调用 |
| 一个回答可涉及多个 KC | 支持。源码保存多个 KC，但对应一个回合级正确性标签；不能据此生成多个独立“已测量”的结论 |
| 示例里每个 KC 分别 correct/partial | 是原稿提出的产品目标，不是此项目已提供的能力，需要逐 KC 评价依据和新标注协议 |
| 全对话标注存在未来信息 | 支持；需要同时限制文本、候选知识点和可使用的历史标签，不能只截断模型输入字符串 |
| 可以直接复用完整系统 | 应收窄为研究代码与局部函数候选。固定树主要是 CLI 标注、训练、评估、可视化；不提供本项目任务/学生授权、正式证据审核与事务提交协议 |
| MIT License | 已读实际 LICENSE，代码为 MIT；README 明确标注数据遵循各自原始许可，不能将代码许可套到全部数据上 |

原稿开头配图题名含 DK-PRACTICE，与本次目标论文题名不同，本批没有用该配图作为 Dialogue-KT 证据，采用官方仓库及论文版本。

## 3. 必须区分的三种时间点

| 目的 | 可用数据 | 不可作为输入的数据 | 对本项目的含义 |
| --- | --- | --- | --- |
| 作答前预测 | 当前题目/教师问题及此前已发生的交互 | 当前学生答案、之后的教师纠正、未来测验结果 | 可比较 KT 的预测能力，不能先看答案再报预测准确率 |
| 作答后证据评价与状态更新 | 当前学生回答、当前已授权题目/评分依据、此前帮助 | 之后的教师解释或下一题答案 | 第六层主要更新接缝；需要纳入当前回答，不能原样使用会删掉当前回答的预测格式化函数 |
| 离线回顾性标注/审查 | 经授权的完整历史，且标明其回顾性质 | 不能把回顾结果伪装成当时已知的线上状态 | 适合构建审查材料和研究标签，须与在线标签分开保存和评测 |

代码中 `anno_base_user_prompt` / `anno_atc_user_prompt` 没有传 turn_idx，会调用完整格式化；`kt_user_prompt` 传入 turn_idx。因此“预测文本没有未来回合”不能证明整条管线已经没有未来信息：该轮 KC 列表仍可能先由全对话标注产生。

建议在适配边界显式携带 `as_of_event_id`、评价目的、目标题目/回合身份、来源版本及当时可见帮助。未来追加对话时，应检查过去线上判断所用请求载荷、候选集合及已保存结果不会被悄悄重算，而不是要求多次随机 LLM 输出逐字相同。

## 4. 五项无模型探针

只 AST 提取已检查的两个纯函数：`get_dialogue_text` 和 `apply_annotations`，在合成字符串/字典上运行，没有导入完整研究模块、Torch、模型权重或 OpenAI 客户端。

| 检查 | 结果 | 解释 |
| --- | --- | --- |
| 默认格式化是否包含未来学生标记 | 是 | 与全对话离线标注行为一致 |
| 有效 turn_idx 是否排除当前答案及未来回合 | 是 | 适合作答前预测的局部格式化，不适合作答后更新原样使用 |
| turn_idx 不存在是否拒绝 | 否，会保留未来文本 | 本项目若适配，必须验证目标存在、唯一、排序正确；这不是已上线漏洞，而是移植时不能省略的契约 |
| 多 KC 标签是否分别有正确性 | 否，只有一个回合 correct | 不能将多个 KC 各自标成独立测量成功 |
| apply_annotations 是否改动原输入 | 是 | 只读审计/新旧路径对照需先深拷贝；不能让候选标注改变原事实 |

全部断言通过。复验：在工作区根目录使用 Python 3.11 运行 `.runtime/layer6-research/probe_round01.py`。结果见同目录 `round01-source-probes.json`。这仅验证所列函数行为，不证明标注准确、在线效果、模型性能或全套研究复现成功。

## 5. 多 KC：关联、评价与正式证据不能混成一项

`combine_kcs_and_correctness` 的输出单元是 `{correct, kcs}`；`LMKTDatasetUnpacked` 给每个 KC 构建一个预测提示，但仍保留共同的回合 label。`DKTDataset` 的 labels_flat 在每个 KC 上重复 turn.correct。后者是训练表示转换，不是新增独立观测。

假设学生说“自变量是研究者操纵的因素，因变量也是研究者操纵的因素”，整体判错不应直接把所有相关 KC 都记为“不会”，整体判对也不能证明三个 KC 各自得到验证。对本项目的建议是：

1. 保留同一原始作答身份与原句/片段。KC 关联只表示该作答涉及什么。
2. 只有评分依据能支持逐项结论时，才产生对应 KC 的正确、错误或部分正确观察；否则保留回合级标签，并将逐 KC 结论留空/未评价。
3. 独立性、核验方式、提示/完整解释披露、评价器版本与正式更新资格分别保存。原句可追溯只证明学生确实说过，不证明评价本身正确。
4. 同一作答展开成多条 KC 记录时保留共同 attempt/event 身份，训练和后续统计按依赖关系处理，不能当作 K 次相互独立的练习。

本批未确定最终表结构或 BKT 观测模型；这些问题留给第 03/06/07 批，不能先建新表再倒推证据含义。

| 参考实现 | 建议级别 | 需要保留或改变的边界 | 优先复用的项目接缝 |
| --- | --- | --- | --- |
| get_dialogue_text / kt_user_prompt | 小范围代码适配候选 | 保留角色/回合格式；新增目标存在性、顺序及评价目的检查；当前答案的可见性由目的决定 | TaskContext、原题公共视图和宿主事件顺序，不从聊天摘要猜原始题目 |
| collect_base / collect_atc | 借鉴任务分解，适配离线研究 | 基础路线两类标注，ATC 路线四阶段；不将每个阶段变成必经线上 Agent；数学 ATC 替换为有版本的心理学 KC 候选 | 先用已绑定题目/目标 KC 与现有评分入口；有新增不确定性再按需评估额外调用 |
| get_atc_options | 借鉴层级候选收窄 | 需要本领域 KC ID/层级；过早漏选父类会限制下游选择，保留弃权、人工补充和层级版本 | 当前课程目标、原文对象与未来 KC 注册表的映射 |
| combine_kcs_and_correctness | 离线合并逻辑候选 | 以完整回合 ID 对齐，校验集合及数量，不能只 zip/比较长度；保留原始响应和错误类型 | 已有事件去重、任务/epoch 身份及 Pydantic 验证 |
| extract_result | 不直接复制为生产解析器 | 正则提取 JSON 不提供本项目的原句、权限、题目身份与状态写入校验 | 现有严格 schema 与失败弃权；解析成功不等于证据合格 |
| apply_annotations | 仅作为离线数据处理参考 | 原位修改、末轮元数据覆盖、na 清理均需保留来源；不把数据集人工末轮标签混作线上自动评价 | 深拷贝快照及独立的原始/候选/人工审定字段 |
| human_eval.py | 借鉴审查维度，不原样复制协议 | 审查表显示模型标签，是审查/纠错材料；不能直接当盲标真值。硬编码数据与文件需替换，按样本 ID 对齐 | 已有 annotation_agreement.py 的重复 ID、集合一致和退化 κ 检查；第六层还需新增适配的样本/标签定义 |
| 模型及训练栈 | 后续离线比较对象 | 不覆盖当前服务依赖，不将研究预测直接写正式分数；未审完的训练/评测边界不宣称可生产复用 | 第 03 批比较 pyBKT/pyKT 与现有启发式，再确定必要依赖 |

## 7. 必须适配本项目的语义

`ANNO_CORRECTNESS_SYSTEM_PROMPT` 对某些测量问题下的非直接回答要求 false；原样套用可能把“只给提示、先跳过、我想问另一个问题”当知识错误。已有第二层/TeachingTurn 的行为识别应先决定是否构成作答，不能由标注器越权制造一次测评。

“我懂了”是自报；“讲过了”是教学交付；“答对了”仍需说明是否辅助、依据是什么。第三层已保存策略、原题、帮助次数和发布收据，可作为第六层的已发生上下文，但其自报困难反馈不能被转换为因果教学效果或正式掌握信用。

KC 提取、正确性评价和误解识别可以在逻辑上分开；本批没有找到足以证明本项目需要每轮三个独立模型节点的证据。题目已明确绑定 KC 时优先使用绑定；现有评价已经给出原句与逐项依据时优先复用；额外调用需证明有新增信息价值，并计入现有回合预算。
