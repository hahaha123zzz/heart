# 教学表达与自动可视化修复实施计划

日期：2026-11-03。状态：专项计划，待继续实施。适用实验心理学第3版当前项目。

## 1. 目标与当前进度

让回答根据学习目标采用比较、步骤拆解、反例、总结、实验分析等合适教法；需要直观解释时自动显示可核验的分步图解，学生主要使用“上一步/下一步”。不要求学生点击预制入口或先说“画图”。简单事实可以短答，无需每次附图或例子。

依据：[源码核查](TEACHING_AND_VISUALIZATION_SOURCE_AUDIT_20261103.md)。本专项解决教学表达与图解接线，不替代此前[跨轮理解计划](IMPLEMENTATION_PLAN_20261102.md)；沿用其主体、权限和任务契约，不新增意图识别器。

| 项目 | 当前状态 |
| --- | --- |
| 13种策略及策略提示注入 | 已有，需核对实际执行和内容承接 |
| 原始策略传给第五层 | 已做小修复，优先读取teaching.plan.primary_strategy；summary映射recap |
| 小修复验证 | 总结、反例两项函数断言通过；尚未完成正式回归或上线 |
| 普通AgentLoop自动图解 | 缺少普通问答生成入口与延迟任务传递 |
| 自动图解开关 | 已检查的.env为0；进程内配置待核实 |
| 内容规划和差异展示 | 仅部分覆盖，需要完善 |

本计划保留已有检索、引用核验、记忆、练习和学习状态服务，不迁移Agent框架、不重建教材索引。既有四类预制主题和三种心理学按需模板先接通并验证，再有限扩展。

## 2. 阶段与依赖

| 阶段 | 工作 | 完成依据 |
| --- | --- | --- |
| T0 | 固定基线、复现、建立验收样例 | 能区分未规划、未排队、开关关闭、生成失败和未渲染 |
| T1 | 保留原始教学策略、补齐必要内容规划 | 策略到内容块的回归通过，原有提示/作答约束有效 |
| T2 | 接入普通AgentLoop自动图解 | 普通问答真实入口可排队、生成、展示和保存图解 |
| T3 | 改善心理学覆盖与内容展示 | 指定教学场景有适合的展示，操作保持简单 |
| T4 | 真实问答和浏览器联合验收 | 核心场景、负例、取消、历史回放通过 |
| T5 | 集成8000并交付 | 运行代码、配置和可观察结果与验收版本一致 |

顺序T0→T1→T2→T3→T4→T5。共享入口串行接线；不让多个窗口同时编辑agent_loop_service/task_service。未完成联合验收前，不将半套图解流程直接启入正式服务。

## 3. T0：基线与复现

- [ ] 记录HEAD、工作区差异、8000实际启动入口及生效开关；只记录配置名和值，不记录密钥。根目录含其他窗口未提交成果，不能用旧HEAD代替运行基线。
- [ ] 涉及公共文件前检查当前差异和全部调用方；保留其他窗口成果。需要独立worktree时，使用已交接的稳定基线，不复制未经交接的未提交业务代码。
- [ ] 保存本专项既有小修复的差异，补正式回归，避免重复修改或误当已上线。
- [ ] 使用合成教材问答复现：总结被转解释、反例被转例题、普通聊天不创建图解任务；对照选区及旧入口。
- [ ] 采用现有task trace记录策略ID、内容计划、是否composer/host_snapshot、图解排队与结果。复用既有记录，避免新增完整学生历史副本。

## 4. T1：让教法真正进入内容规划

主要文件：`agents/response_composition_adapters.py`、`agents/response_composition.py`；按调用核对`agents/teaching_strategy.py`、`agents/adaptive_tutoring.py`、`models/learning_response.py`及相关测试。

### 4.1 保留教学语义

- [ ] 正式验证刚完成的原始primary_strategy优先读取；仅在旧入口确实缺少原始计划时使用兼容名称。
- [ ] 区分“策略ID”和“展示块类型”：内容规划不应反向猜测已压缩的旧别名。映射表保持单一来源，未知策略使用明确兼容回退并可观察。
- [ ] 当前self_explanation映射recap仍会失去教学区别。自我解释、提取练习属于允许互动且需等待学生的动作，不通过文字composer擅自造题；有该动作时继续交给现有教学状态/题目服务。
- [ ] 当前明确任务、仅提示、只讲不考和待答问题约束优先于形式多样性；不得为了切换教法泄露答案或推进掌握度。

### 4.2 优先完成的教学组织

| 任务或策略 | 内容组织 | 不应退化成 |
| --- | --- | --- |
| 直接概念解释 | 核心含义、关键关系/适用条件；确有帮助才举例 | 每次强制“定义＋一个例子” |
| 概念比较 | 同一维度比较、易混边界、适用情境 | 两段各自定义，没有区别 |
| 实验/方法步骤 | 目标、步骤、每步理由或控制关系 | 复述程序名称 |
| 反例/误解纠正 | 具体错误、反例、为什么不满足条件 | 普通正例 |
| 总结/知识梳理 | 压缩关键联系与判断线索 | 重新长篇解释定义 |
| 迁移 | 依已核验概念分析新的假设情境，明确非原书案例 | 只换例子名称；未经作答就宣称掌握 |

- [ ] 复用现有semantic_type及claims协议，不先新增大批块类型；需要新增时同步模型、生成、验证、恢复和前端消费方。
- [ ] 将已经决定的moves、任务和现有TaskExecution信号传到内容规划，避免只看策略名；不得从原句再建立并列意图权威。
- [ ] 保持来源约束，同时允许明确标记的类比、推演和教学示例；不强制普通组织性过渡语冒充教材引文，也不降低专业事实证据要求。
- [ ] 提示词写清每种块的教学目的，避免所有块都要求“解释并举例”。保持直接回答可简短，不为变化随机轮换策略。

T1验收：总结、反例、比较、拆解的原始策略和对应计划可对照；普通解释不被无条件加例子；互动动作仍由现有状态服务管理；host_snapshot与实际动态组合可区分。

## 5. T2：普通问答自动图解接线

主要文件：`main.py::_execute_task_turn`、`agents/agent_loop_service.py`、`agents/task_execution.py`、`visualization/on_demand.py`；兼容检查`agents/task_service.py`、`orchestrator.py`、选区入口和前端传输。

- [ ] main普通AgentLoop入口传递现有visualization_jobs，不仅传给选区或旧入口。
- [ ] 在普通问答通过文字核验、来源和任务检查后，复用build_guide排入延迟任务。保留选区execution；普通问答从当前已确认任务构建/复用TaskExecution，不伪造selection_input，不绕过范围、权限和提示约束。
- [ ] 普通图解与文字使用同一已解析主体、目标、当前回答、来源版本和引用位置；原句保留用于表达约束，不能用旧历史另换绘图对象。
- [ ] 仅为完成且可用于教学的文字排队；元数据查询、仅提示、等待作答、取消/过期任务和无可靠材料不生成答案泄露图。已有有效图解/重复恢复避免重复调用。
- [ ] 沿用TaskService的文字先交付、图解后补充、attach_guide保存与版本检查；不得持数据库写锁调用模型。无延迟收集器的兼容调用仍有明确行为，不静默丢任务。
- [ ] 排队前与执行前检查现有任务有效性；取消、清空记忆或版本变化后不得迟到挂载。图解失败不抹掉已保存文字。
- [ ] 使用既有状态表达pending/ready/unavailable，并在内部trace区分disabled、not_applicable、no_template、generation_failed、validation_failed、stale；不将内部失败参数暴露给普通学生。
- [ ] 检查按需图解当前独立40秒预算与宿主预算的关系，遵守共享剩余时间和取消检查；不新增一套重试循环，不因延迟图解无限延长任务。

T2验收：调用真实TaskService及普通问答入口的集成测试能收到图解结果和历史保存；开关关闭不调用生成；预制命中不调用按需模型；失败和取消不会破坏文字或学习状态。

## 6. T3：覆盖与展示优化

### 6.1 心理学图解

主要文件：`visualization/psychology_presets.py`、`visualization/templates.py`、`visualization/skills/experimental-design/SKILL.md`、已有presets及渲染器。

- [ ] 优先验证变量、被试设计、信号检测、空间线索四类预制包在普通问答可用；保留教材版本、证据位置和主题边界检查。
- [ ] 改善GENERAL词表导致的自然问法漏配；优先使用当前已确定主题/目标及证据匹配，不靠无限追加语气词，也不因提到关键词替换用户自定义实验。
- [ ] 先复用现有流程图渲染能力，补“实验方法选择流程”和“知识关系梳理”适用说明、schema及核验。区分教学关系与因果；没有原书数据不生成观测结果。
- [ ] 人物发展时间线、复杂统计动画等列为后续扩展，不作为本次修复前置；当前模板无法忠实表达时保留合格文字。

### 6.2 对话展示

主要文件：`frontend/chat-renderer.js`、现有样式、`frontend/visualizations/guided.js`；按需检查app.js/chat-transport.js。

- [ ] 对已发布的comparison/procedure/recap/counterexample等类型增加轻量语义样式，保留Markdown表格、步骤和少量重点加粗；不改原文、不重编引用、不插入未校验内容。
- [ ] 图解沿用对话内组件、上一步/下一步及教材来源跳转；不恢复输入框上方预制按钮，不要求学生自行调参数。
- [ ] 核对流式提交与历史恢复都消费同样协议；旧消息或协议不匹配仍显示基础正文。组件挂载失败不得让整条回答消失。
- [ ] 保持键盘可操作、焦点可见、窄屏不溢出；高亮同时配合文字/标记，不能只靠颜色传达含义。

T3验收：相同回答在实时流式、最终消息、刷新后历史显示一致；步骤改变时画面/高亮实际变化；图表与文字对象一致，引用仍能定位教材。

## 7. T4：验收集与执行方式

| ID | 场景 | 通过标准 |
| --- | --- | --- |
| V01 | 通俗解释自变量、因变量、额外变量 | 自动变量图或已核验预制图，无需说“画图” |
| V02 | 比较被试内与被试间设计 | 按相同维度比较，可见合适矩阵/流程；不混淆每人接受的条件 |
| V03 | 信号检测中的辨别力与判准 | 图形变化匹配当前步骤，假设数据不冒充教材实测 |
| V04 | 空间线索有效/无效条件 | 程序与时间顺序可视化，下一步有画面变化 |
| V05 | 总结刚才讲的实验控制方法 | 使用总结结构，不退化成新增长篇定义和例题 |
| V06 | 学生混淆两个概念，要求反例 | 保留反例策略，说明边界，不转成普通正例 |
| V07 | 学生说没听懂、要求拆开讲 | 依实际困难拆解，与上一轮不原样重复 |
| V08 | 简单人物事实或教材文件数量 | 正确简答/盘点，无无关图解和额外问题 |
| V09 | 只要提示或有待答检查题 | 不生成泄露答案图，不擅自替换原题 |
| V10 | 无证据、预制失效、生成超时/核验失败 | 保留文字，准确记录图解不可用，不编造成功 |
| V11 | 图解生成中取消、换会话或版本失效 | 无旧图迟到，无跨用户材料与状态写入 |
| V12 | 刷新历史、重试、恢复、窄屏和键盘操作 | 图解保存/恢复一致，幂等，操作可达，引用有效 |

测试分三层：

1. Python回归与集成：相关文件使用unittest，可在现有运行环境执行`python -m unittest tests.test_response_composition_adapters tests.test_response_composition tests.test_on_demand_visualization tests.test_psychology_visualization`；再按实际改动运行teaching_strategy、shared_strategy、TaskService及取消/恢复相关套件。无需因缺pytest而停止。若缺其他依赖，先核对项目既有测试环境，不随意污染正式环境。
2. 浏览器：复用`tests/response-composition.cjs`及`tests/browser/psychology-guided-visualization.cjs`，扩展普通聊天自动触发、步骤画面变化、历史恢复、引用和失败保留正文；现有纯组件测试不能替代真实问答入口测试。
3. 真实模型：隔离账户与数据库，合成问题及已获授权的心理学教材；先验证V01–V04，再验证V05–V07，记录策略、内容计划、图解方法、结果和耗时。不得发送既有学生完整聊天。核心自动出图场景至少重复一次，保留所有结果，不择优报告。

教师感人工检查：是否回应学生当前困惑、解释关系与理由、选用合适组织方式、例子是否有必要、图解是否帮助理解。与同一问题旧结果对照，不能仅凭加了标题/加粗或出现learning_response就判为改善。

发布阻断项：错对象图解、未经核验内容、提示泄题、取消后挂载、引用错位、正式学习状态误推进、核心普通问答无法排队或前端报错。简单事实无图属于预期，不作为失败。

## 8. T5：集成、启用和回退

- [ ] 交付稳定提交与变更清单，整合共享文件前检查其他窗口成果；未提交与已提交状态明确记录。
- [ ] 在隔离环境完成上述验收后，将实际服务的VISUALIZATION_ON_DEMAND设置为1；核实启动器没有覆盖，并记录进程实际生效值。启用属于功能发布步骤，不能只编辑.env就宣称已运行。
- [ ] 保存原运行代码/配置基线；不需要教材重建或正式数据库迁移。若实现中确需数据迁移，补方案再执行。
- [ ] 切换8000后用隔离会话验证普通问答自动出图、总结/反例、简单事实不强制出图与历史刷新；记录启动入口、提交SHA和未提交差异，确认进程已加载目标代码。
- [ ] 异常时可先关闭可选图解以保留合格文字；若策略或正文出现回归，回退本专项提交/部署。关闭图解只算故障缓解，不算专项完成。不得删除学生记录或关闭来源门禁。

## 9. 最终交付与完成定义

交付代码差异、正式测试结果、V01–V12验收表、真实模型与浏览器证据、运行配置/版本记录和必要的上游许可记录。本次以复用项目现有实现为主；如果实际复制上游代码，再依固定SHA保留版权与许可。

完成须同时满足：教学策略语义不在传递中丢失；内容组织与学习目标匹配；普通聊天在适用时自动生成可核验图解；学生简单点击即可学习；失败、取消和历史恢复可靠；8000实际运行验收版本。

当前仅有原始策略优先读取及summary映射的小修复，不能视为T1或整个专项完成。本计划不承诺每问必图，也不以模板数量衡量教学效果。
