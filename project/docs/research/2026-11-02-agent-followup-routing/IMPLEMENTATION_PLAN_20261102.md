# 六层跨轮理解与执行一致性修复实施计划

日期：2026-11-02。状态：待执行；本文件不是完成报告。适用课程：实验心理学第3版。代码仍位于历史目录`project/integration/discrete-math-tutor`。

## 一、目标与依据

修复真实对话：“费希纳是谁”之后，学生说“教材中与他相关的内容有哪些，我想学习，你教一教我吧”，系统却拒绝正常检索结果，或返回全书PDF文件清单并标记完成。

目标行为：同一有效会话中确定“他”的主体，梳理教材中的相关主题并开始讲解；有歧义则澄清。工具选择、选证、教学策略、内容组合和完成检查使用同一请求解释。真正的文件盘点、目录查询、页面跳转、画像读取仍可正常使用。

依据：[真实六层核查](../2026-10-31-layer4-evidence-execution/FECHNER_FOLLOWUP_SIX_LAYER_AUDIT_20261102.md)、[路由调研](01_CONTEXT_AND_ROUTING.md)、[校验调研](02_VALIDATION_STATE_AND_EVALUATION.md)、[复用决策](03_PROJECT_DECISIONS_AND_ACCEPTANCE.md)。七个上游仓库的固定版本和许可见[SOURCE_AUDIT.json](SOURCE_AUDIT.json)。

## 二、路线选择与范围

| 方案 | 收益与代价 | 决定 |
| --- | --- | --- |
| 在purpose里补“教一教我”等关键词 | 修改小，但仍有两套意图权威，换句话容易重现 | 不作为最终方案；仅适合可独立回退的紧急缓解 |
| 扩展已有GroundedTurn，贯通六层并校验交付目标 | 能覆盖已证实根因，保留现有检索、任务、流式和门禁 | 本计划采用 |
| 立即迁移LangGraph或更换完整Agent框架 | 可改善编排表达，但仍要实现相同语义约束，联调面大 | 本轮不做，后续单独评估 |

不重建项目、记忆库或教材索引，不替换embedding，不新增人物知识图谱，不修改练习/复习/学习记录的页面布局。不新增一套平行的分类服务、完成状态库或模型校验框架。

本轮可能涉及六层，但范围是“跨层请求一致性”这一条链路，不重新开展全部六层升级。暂不承诺解决所有幻觉或输出失败；不能定位的其他问题单独归类。

## 五、请求契约：复用现有协议（P1）

### 5.1 数据与优先级

以`GroundedTurn`及其`ContextHeader`、`ObjectReference`、`TaskFrame`为唯一可信解析载体；不另设完整ResolvedRequest对象树。建议最小增量如下，执行时以模型兼容测试确认最终字段名：

- 原句继续保存在InputEnvelope.raw_text，normalized_text仍只做原协议允许的规范化；人物替换不能写回这两个字段或破坏source_positions。
- `ObjectReference.kind`只按实际需求增加人物/主题类别；其身份来自当前授权会话的对象引用或可验证历史片段，不伪造教材知识点ID。保留引入轮次、引用片段与版本依据，沿用canonical_id/status的一致性验证。
- 独立检索问题优先放入既有`TaskFrame.query`，不再设置一份可能分歧的查询字段；保留task.action和constraints，改写不能创建权限或业务写入意图。
- 允许在GroundedTurn增加一个可选、向后兼容的执行用途字段，复用当前`textbook/outline/catalog/personal_state/reader_goto`等实际用途集合，不新创另一套分类体系。未提供用途不等于确认catalog；显式元数据请求与普通知识学习必须区分。
- `resolution_status`必须反映任务所需主体是否绑定；包含待解析指代而缺少依据时写missing/ambiguous/partial及原因，不能以“规则没匹配”默认为resolved。无指代的一般问题不强制拥有target_ref。

用途以完整输入理解结果为准；下游不能重新用原句正则推翻它。存在明确文件管理请求与知识教学混合任务时分别保留义务/任务帧，按现有多任务预算执行；协议无法可靠表达时澄清，不以文件清单替代教学。

### 5.2 指代规则与边界

- 有唯一可信主体且无话题切换时，“他/她/这位学者/这个理论”等追问可绑定；先覆盖本教材人物与主题所需的最小范围，不做通用中文实体识别平台。
- 不将上一条回答中出现过的所有姓名视为当前学习主体，不盲选最近姓名；当前主体优先来自上一有效任务的目标与已验证对象。
- 多候选或无可信对象时，按现有预算调用结构化语义解析或澄清。模型只能选择服务端提供、可回验的候选；凭空生成的姓名/ID不得成为resolved。
- 明确命名的新人物/主题优先；选区、练习对象与待答问题的授权和优先级保持现有规则。正文提及某人不自动改变整轮选区目标。
- 跨学生/会话、历史删除、教材版本变化、任务revision过期时拒绝旧绑定；不恢复已失效的旧引用。

### 5.3 兼容策略与交付

新增可选字段使用安全默认值，旧合法无指代快照可继续读取；旧快照含未绑定指代则在恢复时重新核查或澄清，不能仅为兼容而信任resolved。若确实需要改变schema_version，必须一次更新语义输出schema、存取适配、恢复、测试和摘要；优先保持向后兼容，避免数据库迁移。

P1验收：协议/指代/歧义/旧快照测试通过；原句和位置映射不变；独立查询包含正确主体；简单唯一主体路径不新增模型调用，语义兜底不超过现有GroundedTurn.model_calls上限与共享回合预算。

## 七、交付检查、有界修订与状态（P3）

### 7.1 在现有门禁增加任务满足检查

复用已有最终门禁及final_summary，不另建门禁框架；具体校验函数保持单一来源供流式完成和非流式完成使用。

检查顺序：会话/版本/取消有效性→请求主体和交付类型→所需证据与引用→事实和教学目标覆盖→业务完成状态。存在合法澄清、等待作答或部分交付时，使用现有相应状态，不能一律判作失败或完成。

确定性硬约束：教学任务不得用catalog冒充完成；错误主体、未满足明确必需义务、过期来源不能完成；只有learning_response结构合法不能直接通过。解释类frame不能仅由`result.completed`推导完成。

语义检查优先复用已有证据与回答核验，补充当前主体和目标；不依赖中文词重合，也不新增每轮第二套模型裁判。需新增判断时使用现有预算并分别记录确定性错误与语义证据不足，人工验收覆盖后者。

### 7.2 修订和流式边界

可修订偏题/漏目标时，在现有总预算内提供具体原因，最多增加一次针对性修订；现有机制已执行修订时不再叠加一次。取消、权限拒绝、版本冲突不重试为内容问题。预算耗尽时准确失败/暂停，不关闭门禁发布草稿。

已验证分块仍遵守现有发布契约；整个任务不满足时保留部分交付语义，不把已发内容伪装成全部完成。不为了最终检查缓存所有token而破坏现有流式；可提前确定的类型/主体约束在首块发布前检查，最终覆盖在终态前检查。

### 7.3 状态与日志

分别记录工具执行成功、内容发布、任务frame满足、学生掌握。教学内容交付不是独立作答证据；不得据此自动确认掌握。日志复用现有task trace，记录主体绑定依据、用途决策、实际检索问题、选证和失败类别；不记录密钥，不新增完整学生历史副本，不对用户展示隐含推理。

P3验收：错误catalog即使工具成功也不能完成explain_content；失败与取消不推进学习步骤；真正catalog查询可完成；修订计数、流式终态、恢复与幂等保存测试通过。

### 测试执行层次

1. 确定性测试：复用`tests/test_input_understanding_*.py`、`test_first_wave_*.py`、`test_response_composition*.py`等实际受影响套件；新增一个专门多轮一致性测试文件和必要合成数据，避免为每个实现分支重复造测试。
2. 集成测试：隔离数据库与账户，通过真实TaskService/问答入口检查解析、工具、响应协议、状态与引用；校验不是仅在测试直接调用purpose时正确。
3. 真实模型：确定性检查通过后，使用已配置DeepSeek和获授权教材，只发合成问题与教材片段，不发已有学生历史。核心F01/F13/F15各连续回放3次，其余按需一次；保存每次结果，不只保留最佳样本。若不可运行，明确缺项，不把模拟结果当实测。
4. 人工内容核对：检查费希纳相关主题是否来自当前教材、引用跳转/页码是否有效、本人事实是否与关联人物区分、是否真的开始教学。不能把JSON合法视为人工内容通过。

记录整轮耗时、首个有效内容时间、输入理解模型调用数、修订次数及检索用时，与相同隔离场景的基线逐项对照。简单规则路径不增加模型调用；真实模型耗时受外部服务影响，报告分项变化，不用少量样本宣称总体P95改善。

阻断上线：24条确定性预期未通过、错主体/清单冒充教学完成、权限或版本串用、取消后发布、非法学习状态推进、现有兼容回归失败。语义人工核对失败的核心场景也不得以“协议测试通过”放行。
