# 第三批：结合项目的复用决策与后续验收设计

2026-11-02。本文件是调研结论和建议范围，不表示实施已完成。正式失败证据见[六层执行核查](../2026-10-31-layer4-evidence-execution/FECHNER_FOLLOWUP_SIX_LAYER_AUDIT_20261102.md)。

## 已证实的问题与改造边界

同一会话两条真实任务中，历史含“费希纳是谁”，但“他”没有绑定到目标，仍被标成resolved；上游任务是explain_content，下游purpose却从原句重新判为catalog。一次retrieve_course成功仍因未调用kb_files而拒绝，另一次返回11份文件列表并标完成。两次均绕开正常教学策略与第五层learning_response。不能将这两个结果笼统归结为检索模型差、历史没存或生成模型随机失常。

因此先修跨层请求一致性，再改善教学表达。现有检索、TaskService、来源与发布门禁、取消和版本检查应复用；不重建记忆库、不重解析教材、不因这一个故障整体更换embedding或Agent框架。

## 建议的最小实施顺序

1. **先立复现夹具与跨层约束。** 把两条真实失败简化为无学生信息的多轮夹具，检查教学意图不能进入catalog完成分支；同时保留真正“教材文件有几份”的能力。
2. **让同一解析结果贯穿六层。** 优先扩展现有上下文、对象引用与任务类型，保留raw_text；携带主体、来源依据、任务目的、歧义状态和独立检索问题。不新建平行意图系统，也不让模型改写权限、教材版本或会话身份。
3. **补人物/主题指代与不确定状态。** 唯一且有可信上下文依据时绑定；多人物、话题切换、失效历史时澄清或保留未解析。规则无法判断时才按现有预算启用结构化语义解析，不硬编码“他=费希纳”。
4. **统一工具适用性和选证。** 工具路由、检索、选证及教学规划接收同一主体与任务；明确文件管理请求才用catalog。区分可用、适用和必需，已有有效证据可复用，不强制每轮相同工具序列。区分教材以某人为主体，还是仅在他人传记中提及。
5. **检查交付是否满足任务。** 分别检查主体一致、交付类型、来源有效、事实支持、教学目标覆盖。explain_content不能因kb_files成功而完成；有learning_response也不自动等于讲得对。教学型追问应梳理相关主题并开始讲解，不强制每次堆叠全部内容模块。
6. **有限修订与准确状态。** 对可修复的偏题或交付错型，在统一预算内反馈具体原因；取消、过期版本、权限错误不作为可无限重试的内容问题。工具成功、内容交付、教学任务完成、学生掌握分别记录，不能相互替代。

这需要贯穿第一/二层、工具分发、第三/五层入口和第六层完成检查；第四层的选证也应使用同一主体。不是仅修改第五层提示词。后续正式实施前，应搜索这些共享入口的全部调用方和现有测试；本轮未做调用方修改。

## 拟议验收集：先做24条，再按失败增补

以下是待实施的用例设计，不是已通过的测试。

| 类别 | 数量 | 必查结果 |
| --- | --- | --- |
| 人物介绍→代词教学追问，含简短/换措辞 | 4 | 绑定正确人物；继续知识教学；无全书文件清单完成 |
| 两个人物、多候选、无有效历史 | 4 | 不凭最近姓名强行绑定；必要时澄清 |
| 明确换人物、换主题、取消后重问 | 4 | 新请求生效，旧主题和旧结果不串入 |
| 真文件数/文件名查询与“相关内容有哪些”对照 | 4 | 分清元数据与知识学习；保留合法catalog功能 |
| 已有证据、检索空、工具失败、仅关联人物证据 | 4 | 不强制无关工具；证据不足说清；主体不混淆 |
| “只讲不考”、分步学习、重复重试、版本失效 | 4 | 尊重教学约束，完成状态可信，旧版本不发布 |

验收分三部分：确定性回归检查主体/意图/路由/输出类型及状态；隔离账户真实模型回放检查连续对话与失败分类；人工检查教材支持和教学覆盖。选定关键对话重复运行，报告每次结果与耗时，不能只保留最好一次。

对人工复核的固定集，文件清单冒充知识教学、错主体完成、取消后发布应作为阻断项；不据此宣称总体准确率100%。模型回放所需材料仅用合成提问和获授权教材，避免发送已有学生聊天。教材发送已有用户授权，本轮未调用真实模型。

## 实施之后应交付的可观察证据

每轮在内部日志中能对照原句、解析主体及依据、最终检索问题、选用工具原因、证据主体、交付类型、完成检查结果和耗时；避免在普通用户界面展示调试细节。对外“处理记录”继续折叠，不用展示模型隐含推理。

最终验收必须覆盖真实多轮入口与8000使用的代码，而不只测某个函数返回正确标签。是否后续采用LangGraph另行根据编排复杂度评估，本次调研没有发现必须先迁移框架才能修复的证据。
