## 2. 各维度比较

| 维度 | 本项目当前实现 | D 盘 DeepTutor | 判断 |
| --- | --- | --- | --- |
| 正文格式 | composer 路径要求最终 JSON，限定 blocks、pending、claims、source_ids；非 composer 路径可自然语言输出 | 普通 chat 是正文与工具调用的循环，模型无工具调用时结束；不统一要求教材解释转 blocks JSON | 本项目结构化路径对正文形式约束更强 |
| 回答组成 | `plan_response` 在生成前把策略编译为既定块组合，模型不能任意增删 pending 之外的块 | chat 用行为说明；mastery 按状态和 playbook 指导讲/问/停，正文不统一套同一种段落协议 | DeepTutor 在自然语言组织上留有更大空间 |
| 教学策略 | 服务端按困难、任务、偏好和作答等选候选，再注入 moves；部分策略投影为较少的固定块组合 | mastery 按当前状态、知识点类型和偏好给教学规则，模型通过工具行动 | 两者都有策略控制，决策权限划分不同 |
| 证据与引用 | composer 每条 claim 必须有来源 ID，限定 provenance；发布器检查本轮引用和部分原文位置 | 普通 chat 提示要求事实有据并提供检索工具；掌握式视觉任务有来源/原图要求 | 已读路径显示本项目对教材回答证据编码更细，不能据此证明事实准确率更高 |
| 普通知识补充 | 最新心理学提示词及 blended 路径允许一定课堂补充，但不能编教材归属 | chat 可按问题使用已有知识或工具，不把所有问题绑定一本书 | 本项目已部分放宽，不是“每句话都必须抄教材” |
| 提问与进度 | 待答题、明确不考、提示披露、学习状态由服务端管理；存在禁止问号的硬检查 | mastery_quiz、grade/assess 等服务掌管题目交付和掌握；finish hook 拦截虚假出题完成 | 此类硬约束两者都保留，值得继续坚持 |
| 发布失败 | 普通循环 publish_gate、composer 校验、专用质量检查及图解校验因路径而异 | chat 有协议、工具和 capability 收尾检查；mastery 可拒绝未交付题目的收尾；visualize 有确定性校验与修复 | 不应说本项目每条消息必经独立模型审稿，也不应说 DeepTutor 无门禁 |
| 长度 | 当前 reply_budget 不设字数上限；ANSWER_MAX_TOKENS 默认 8000 是 API 技术预算 | 循环/上下文/模型输出也有技术预算，提示要求简洁 | 旧的固定字数限制不能作为当前主结论 |
| 图解 | 本地组件/模板、预制教材锚点及按需生成审计 | visualize 专用能力约束代码格式并按校验错误修复 | 两边都对可执行或可渲染内容限制更强，和普通聊天不是同一标准 |

## 3. 本项目的具体约束位置

### 3.1 提示词与结构协议

`agents/course_prompts.py` 的 SCOPE/RESPONSE/QUALITY 分别携带学科边界、生成要求和检查要求，针对变量、设计和公式等累计了领域修正规则。`agents/loop_prompts.py` 再加入当前循环、工具、目标和教学策略。多处有相似的证据、范围、补充讲解要求，维护时需要一起核对。

`agents/response_composition.py::plan_response` 将 worked_example 等策略映射为特定块；`ResponseComposer.instructions` 限定只生成 pending 中的块。`models/learning_response.py` 限定块类型、数量、依赖、claims 和来源字段。这些是可由代码拒绝的结构要求，强于一句“尽量按步骤讲”。

结构要求的收益是可恢复、可定位、引用稳定；代价是组织权限较窄。不能只用“表达自然”的提示词解除它，必须协调计划、生成、验证及恢复契约。

### 3.2 生效范围必须按入口判断

`agents/agent_loop_service.py` 约第 637 行仅在 `RESPONSE_COMPOSITION_ENABLED=1`、教材工具目的、无部分提问/展示/恢复边界等条件下创建 composer。提示、待答题等情形有排除条件。因此固定块要求不是所有回答通用的约束。

`published_snapshot` 可以包装宿主既有正文；不能仅从结果存在 `learning_response` 推断模型受 blocks 协议生成。

本次 `.env` 文本中 `RESPONSE_COMPOSITION_ENABLED='1'`、`VISUALIZATION_ON_DEMAND='0'`，但未读取正在运行进程环境；启动器可能覆盖配置，本文不据此断言 8000 实际开关。

### 3.3 普通发布门禁与独立质量检查需要区分

`agent_loop_service.py::_publish_gate` 主要进行非空、内部协议、来源、跨对象覆盖及引用位置等检查；该函数没有统一调用 `quality_checker.check`。旧入口、专门教学或其他调用点可能有独立质量检查，不能把检查器文件存在等同于普通问答每次必跑。

当前 `_publish_gate` 有一个值得后续单独核查的分支：固定教材激活、已有 sources 但正文无数字引用时，直接允许发布并设置空引用列表；它位于后续部分证据与引用检查之前。这说明最近的放宽涉及代码门禁，不只是提示词。可能出现“文字发布但没有可点击教材来源”，本轮只记录静态行为，未复现线上问题。

## 4. D 盘 DeepTutor 的具体方法

`deeptutor/agents/chat/prompts/zh/agentic_chat.yaml` 指导模型按证据和上下文工作、按需使用工具、自然组织简洁 Markdown；伙伴可通过 Soul 改变教学节奏，但不能覆盖安全、隐私和工具真实性。

`deeptutor/agents/loop/agent_loop.py` 描述并实现单一循环：工具调用继续循环，没有工具调用时作为收尾；还有有限的预算、恢复和 capability finish 检查。读取约第 628 行可见 capability 拒绝收尾后丢弃相应输出并给予一次修正机会，并非把所有模型文字无条件当成功。

`deeptutor/capabilities/mastery/loop.py::finish_instruction` 检查已请求 quiz 是否真正投递卡片，拦截只宣布出题或正文伪造正式选择题等情况。它检查特定任务的实际交付，不要求每段讲解都满足统一文学结构。

`deeptutor/capabilities/mastery/prompts/zh/mastery_loop.yaml` 将知识点状态、探查、讲解、复习和交互规则分开。题目待答时允许回应学生插入的问题；讲解不等于掌握，能简短讲解时不强制出题。此版本的规则与较新在线版本细节不同，不混用后者作为本机已实现证据。

`deeptutor/runtime/agentic/tool_dispatch.py` 和工具组合/业务服务约束工具注册、参数、执行结果与回合信号；`agents/visualize/prompts/zh/review_agent.yaml` 要求针对确定性校验错误修复代码，并限定 JSON 返回。由此可见其约束按能力设置：普通正文自由度较高，工具交付和生成代码更严格。

本轮没有审完全部阅读引用管线和全部 capability，不能断言 DeepTutor 全部产品都没有逐项证据或内容质量校验。

## 5. 与机械感直接相关的风险

1. 策略压缩：多种教学策略最后变成少量固定块组合；问题诊断即使不同，正文骨架也可能一样。
2. 指令叠加：学科提示、循环规则、策略 moves 和 composer 同时影响回答，需要明确覆盖顺序，而非无限追加例外。
3. 标签冲突：心理学提示要求正文不显示“非原书例题”等标签，但 composer 的 `_text` 仍自动添加“教学示例（非教材原例）”“教学类比（非教材原文）”及“补充说明”。实际路径不同会出现不同口吻，单改提示词无法统一。
4. 问号等同测验：`final_gate` 在不允许检查时按问号拒绝正文，可能把解释中的设问也当作出题；更合理的边界应围绕是否创建要求学生作答的交互。这里只是静态风险判断，尚未测实际触发率。
5. 精确事实约束与解释组织混合：来源真实性需要严格控制，但不意味着每次都先定义、再举例或每轮检查掌握。应分开决定。

相反，近期课堂补充、取消字数门禁、正确解释不因纯风格失败等修改已经在放宽表达。当前问题是约束分布及一致性，不宜统一描述为“所有约束都太严”。

## 6. 推荐保留、放宽和合并的内容

| 处理 | 对象 | 原因 |
| --- | --- | --- |
| 保留代码硬约束 | 工具权限、用户/会话隔离、题目答案与评分、取消/版本、引用身份和原图来源 | 这些不能交给模型文风决定 |
| 放宽组织权限 | 例子是否需要、讲解顺序、必要前置、对照或图解的选用、每轮功能数量 | 允许根据当前学生问题组织教学 |
| 改为柔性指导 | 口吻、段落长短、标题、设问和收束 | 适合条件提示与教学案例，不宜仅凭措辞拒绝正确答案 |
| 合并矛盾规则 | 示例标签、来源不足时怎么说、问号/出题边界 | 避免多层分别发出相反要求 |
| 单独核查 | 固定教材无引用早返回、结构化开关的实际入口 | 放宽表达不能意外削弱引用交付 |

推荐借鉴 DeepTutor 的分工方式：正文表达由情境化教学规则指导；业务行动由工具服务和结果门禁保证；专用产物采用各自协议。无需迁入整个 DeepTutor 框架，也无需去掉现有证据保护。
