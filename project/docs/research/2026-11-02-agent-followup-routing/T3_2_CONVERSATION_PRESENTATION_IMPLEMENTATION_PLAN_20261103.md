# T3.2 对话内容语义展示实施计划

日期：2026-11-03。状态：计划已编写，尚未开始本阶段代码实施。

上位计划：[教学表达与自动可视化修复实施计划](TEACHING_VISUALIZATION_IMPLEMENTATION_PLAN_20261103.md)。本计划细化其中 T3.2，并规定进入 T4、T5 的交接要求。

## 1. 目标和当前基线

让学生看清回答中的核心结论、比较维度、实验步骤和易混边界；适用时配合已有分步图解，继续以“上一步/下一步”为主要操作。

当前代码事实：

- `models/learning_response.py` 已有 `learning-response/v1`、`PublishedBlock.semantic_type` 和 `content_origin`，覆盖 comparison、procedure、recap、counterexample、misconception 等类型。
- `frontend/chat-renderer.js::renderLearningResponse` 已检查协议、发布状态、块身份和正文拼接一致性，但所有块都渲染为同样的 `response-block` 容器，没有利用类型做展示。
- `renderTutorAnswer` 已支持 Markdown；降级路径支持加粗、高亮和引用按钮，可以直接复用。
- `frontend/app.js` 已从最终结果、恢复结果和历史读取 `learningResponse`；`answerContent` 在非 streaming 状态才调用结构化渲染，需要核查这与已提交部分回答的显示是否一致。
- `frontend/chat-transport.js` 已消费 publication 事件中的 `learning_response`。协议传输不是本阶段的默认改造范围。
- `frontend/visualizations/guided.js` 已有逐步画面、来源按钮和关注标记；本阶段复用现有组件。

已完成的自动图解修复作为基线保留：变量、被试设计、信号检测、空间线索，以及新增的方法选择和章节目录结构图。最近 8000 重放中，方法选择 4 次有 3 次完整成功，章节结构图 3/3 成功；6 次成功回答都返回 4 步图解和逐帧 PDF 锚点。另 1 次返回 `model_unavailable`，未进入图解阶段，底层原因尚未定位。

章节目录结构图只表达章与节的包含关系，不等于已经实现教材概念之间的先修、因果或理论关系图。

## 2. 范围与交付边界

本阶段交付语义展示规则、统一前端渲染、必要样式、相关回归和 8000 实际展示记录。

不更换 Agent 框架，不重建教材索引，不新增教学策略或后端语义类型，不重新生成已发布正文，不恢复输入框上方的预制按钮，不增加学生参数编辑。

前端只能使用服务端已发布的类型和正文：不通过关键词猜类型，不自行把一段回答拆成“定义、例子、结论”，不重新编排引用，不执行模型返回的 HTML 或代码。

## 3. 展示规则

总体采用轻量排版。普通解释保持连续正文；只有已发布类型明确且存在阅读收益的块才增加视觉层次，避免每段都成为卡片。

| 已发布类型 | 展示方式 | 边界 |
| --- | --- | --- |
| direct_answer、definition、explanation | 正文、合理间距，保留已有重点加粗 | 不自动提取“核心结论”，不强制加标题或例子 |
| comparison | 轻量对照容器；正文已有 Markdown 表格时保留表格 | 不将自然段自动改成表格，不补比较维度 |
| procedure | 步骤区域与清晰间距，保留正文已有编号 | 不重复编号，不把每个段落都判成独立步骤 |
| recap | 简洁总结区域，便于回看 | 不生成新总结，不重复正文中的“总结”标题 |
| counterexample、misconception | 边界提示区域；使用文字标记配合样式 | 不把反例当正例，不只靠颜色区分 |
| worked_example、analogy | 轻量示例区域，保留服务端已有来源与示例说明 | 不擅自判定是否教材原例，不添加来源声明 |
| hint、check_question、feedback、next_step | 首轮保持已有正文及交互 | 不突出答案、不重造题目、不暗示已掌握 |
| roadmap、section_map 及其余已知类型 | 首轮保持基础正文 | 本阶段不增加第二套知识图渲染器 |

加粗和高亮只保留已发布正文中的标记，不由浏览器按关键词自动涂色。首轮不修改生成提示词来增加强调；若真实验收发现关键内容始终缺少强调，记录为后续生成质量问题。

`content_origin=host_snapshot` 保留宿主原文和既有互动语义，不因携带类型就增加教学标签。缺少类型的旧消息仍显示基础正文；未知类型不进入专用样式。

## 4. 文件与调用范围

| 文件/入口 | 计划动作 |
| --- | --- |
| `frontend/chat-renderer.js` | 在现有一致性校验之后，以固定类型映射增加安全的 class/必要可见标记；复用现有正文渲染 |
| `frontend/styles.css` 及实际加载的样式 | 先确认现有选择器和样式顺序，再增加局部语义样式；覆盖窄屏、表格滚动、焦点和可读对比度 |
| `frontend/app.js::answerContent`、`messagesFromHistory` | 审查最终消息、已提交部分回答、历史恢复的调用一致性；仅在发现缺口时做最小修改 |
| `frontend/chat-transport.js` | 审查 publication 事件；默认复用已有字段，不新增事件或另一份状态 |
| `frontend/visualizations/guided.js` | 核查正文更新不会重新挂载组件、重置步骤或改变来源对象；有复现问题时才修改 |
| `tests/response-composition.cjs` | 扩展类型展示、旧协议回退、原文及引用一致性检查 |
| 现有聊天/图解浏览器脚本 | 按现有能力复用，在 8000 实际页面验证；不另起替代服务来宣称正式页面通过 |

实施前检查以上文件的调用方和工作区差异，保留其他窗口的修改。若发现必须改后端协议或教学内容规划，先记录具体缺口和影响，再补入范围，不把展示修复扩展成整条问答链路重写。

## 5. 实施顺序

### S0：确认实际输入并保存对照

- [ ] 记录当前 HEAD、相关文件差异和 8000 启动入口；不记录密钥。
- [ ] 通过 8000 的隔离测试会话收集比较、步骤、总结、反例各一条可用回答，检查实际 `semantic_type`、`content_origin` 和正文一致性。
- [ ] 区分真实结构化块和整段 `host_snapshot`。后者保持基础展示，不能用样式冒充内容规划已经改善。
- [ ] 确认 `styles.css`、其他样式和 Markdown 样式的加载顺序，防止覆盖正文或图解布局。

完成依据：四类输入及当前页面展示可对照；无法获得某类有效块时明确登记为上游缺口，不伪造真实验收结果。

### S1：统一类型展示

- [ ] 建立小型固定类型到样式映射，类型值不直接拼接为任意 HTML。
- [ ] 保留现有协议、发布状态、块 ID、重复检查及正文一致性门禁。
- [ ] 落实第 3 节的比较、步骤、总结、边界和示例展示；普通解释保持自然正文。
- [ ] 不重复渲染正文，不改写文本，不改变引用数字及其绑定对象。
- [ ] 处理窄屏长表格、长公式和长链接，滚动限定在对应内容内，不撑宽整页。
- [ ] 对关注/边界提供文字或形状标记，焦点可见；不添加无交互意义的焦点停靠点。

完成依据：同一份发布数据改变展示层次，原文、引用及互动语义保持一致。

### S2：核对消息生命周期

- [ ] 未发布草稿保持原有处理方式；只对已发布内容使用结构化展示。
- [ ] 已提交部分回答、最终消息、刷新历史和恢复任务使用同样的类型映射与降级行为。
- [ ] 正文更新不重置图解当前步骤；已有“处理记录”和教材原文折叠状态保留。
- [ ] 组件挂载异常时正文仍可阅读；不把图解失败转成整条回答失败。
- [ ] 旧消息、缺失类型、未知协议、正文不一致均按现有规则安全回退。

完成依据：相同已发布内容在上述状态下展示一致，没有重复正文、重复引用或图解状态丢失。

### S3：8000 展示验收与交接

- [ ] 运行与本阶段改动直接相关的 Node 渲染测试；触及流式或图解生命周期时补对应现有回归。
- [ ] 用 8000 实际页面检查桌面和窄屏、步骤切换、引用跳转、高亮、刷新历史和键盘访问。API 返回成功只能证明数据链路，不能替代页面展示验收。
- [ ] 将结果写入本目录验收记录，记录真实数据与合成夹具的区别，保留失败，不择优报告。
- [ ] 交接 T4 未完成项及 T5 版本/部署记录，明确提交状态和实际运行版本。

## 6. 本阶段验收表

| ID | 场景 | 通过标准 |
| --- | --- | --- |
| P01 | 简单事实、普通定义 | 正文清楚，无强制卡片、例子、图解和多余标签 |
| P02 | 被试内与被试间比较 | 比较块层次清楚，原有表格和引用完整，图解对象一致 |
| P03 | 实验过程或方法步骤 | 步骤可顺序阅读，无重复编号，图解翻步画面发生变化 |
| P04 | 总结已讲内容 | 总结区域易回看，不新增解释或重复标题 |
| P05 | 反例和误解边界 | 文字标记与样式共同提示边界，反例含义不被改变 |
| P06 | host_snapshot 与旧消息 | 保留原文、题目和状态；缺少结构信息时不猜测分类 |
| P07 | 部分发布→最终→历史恢复 | 同一发布块展示一致，正文不重复，引用编号一致 |
| P08 | 图解与教材来源 | 上一步/下一步有效，更新正文不重置当前步骤，点击来源定位正确页并高亮 |
| P09 | 窄屏、键盘、长内容 | 无整页横向溢出，控件可达且焦点可见，高亮不只靠颜色 |
| P10 | 协议异常与组件失败 | 未发布块不展示；旧/异常协议按现有规则回退；正文和原引用仍可用 |

发布阻断项：原文改变、引用错位、提示泄题、题目被重造、未发布草稿被当成已核验内容、消息更新丢失图解状态、前端错误导致回答不可见。

## 7. T4、T5 衔接和回退

T3.2 完成后进入 T4，补齐上位计划 V01–V12 中仍未覆盖的真实教学表现、失败/取消/版本失效、历史恢复和幂等验收。本轮两类图解已完成的重复回放直接沿用；仅在新改动影响相关链路时重测。

T5 交付稳定提交 SHA、变更清单、验收记录、8000 实际加载版本及生效配置。8000 当前已启用图解不代表 T5 已交付；未提交工作区必须如实记录。

样式与渲染问题优先回退本阶段相关差异，恢复已有基础正文。保留已有安全转义、引用处理、发布门禁和图解失败降级，不通过删除学生数据或放宽来源核验解决展示问题。

## 8. 完成定义与未解决问题

T3.2 完成须同时满足：四类重点内容的实际展示有区别；正文、引用及互动含义不变；实时、最终和历史一致；8000 页面验收通过；交付可追溯的代码及记录。

本阶段不承诺每次回答都有结构化块或图解。`model_unavailable` 单次失败仍单独登记；尚未定位底层原因，不能因展示验收通过而关闭该问题。复杂概念关系图也不能用现有章节目录结构图替代验收。
