## 源码链路

- `agents/course_search.py::select`将Q2候选经choose_evidence产出带原文范围、定位状态和坐标的证据。`knowledge/grounded_citations.py::choose_evidence`可对无法精确定位的内容标记section，但仍保留原文范围与版本信息。
- `agents/tools/first_wave.py::register_sources`在允许模型引用前逐条验证来源，并在全批成功后提交source_index；`agents/tools/first_wave_services.py::CourseReadService.verify_source`重新核验来源范围和位置。段落状态为section时需要无矩形且引文属于当前教材；其他情况必须为exact，且重新定位出的状态为exact、矩形与原证据完全相等。任何一项不成立都会产生同一条坐标错误。
- 来源注册抛错时整个retrieve_course调用失败，模型未获得本次可引用来源。`agents/response_composition.py::_validate`拒绝不属于已注册source_id的claim；外层`agents/agent_loop.py`修订后仍失败，显示回答模块未通过核验。

本地只读复核当前第7章的块531和495：整个原文块分别可定位为exact，矩形数为4和1。但原始任务没有保存最终被Q2选择的完整引句和原始rects；整块可定位不等于当时所选子片段与坐标可一一复现，更不能据此断言核验器错误。

## 初步归因与待核查

直接故障跨第四层和第五层：第四层候选来源注册失败，第五层在无有效证据下仍尝试生成引用，最后将失败表现为回答模块核验失败。首要排查的是引文登记时的定位状态、坐标及版本一致性；要保留现有来源安全检查。

下一步用隔离数据固定当时相同检索对象，记录非敏感的来源ID、引文范围、location_status、重算状态、矩形数量和一致性；分别判断是来源定位歧义、证据格式差异还是坐标确有变化。修复应针对确定原因，并在无来源时明确提示教材证据不足，不能虚构引用，也不能通过关闭校验或直接使用预制图掩盖失败。
