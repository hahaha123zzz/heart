# 教学回答如何组成：Study Mode、LearnLM 与学习 Agent 源码对照

日期：2026-11-03。范围：论文/官方说明、固定提交源码、项目当前工作区静态核查。此次没有修改问答业务、启动配置或学生数据，没有调用真实教学模型。

## 1. 结论与名称核对

用户提到的 OpenAI“learnmode”未在本轮检索中找到可明确对应的同名官方论文。分别核查 OpenAI Study Mode、Google LearnLM 和 Anthropic Learning mode，避免把不同产品和研究混为一谈。

主要判断：固定学习目标、证据约束、交互边界；在这些约束内，按学生本轮困难选择教学动作，允许模型组织必要的内容和顺序。固定“定义＋例子＋总结＋提问”会继续产生机械感；完全让模型自行决定策略也可能重复、偏题或连续追问。

“老师感”应检查能否接住学生思路、讲清关系与理由、控制每轮负担、根据反馈调整，以及适时停下。亲切用语、加粗和卡片仅改善表达，不能证明完成了这些教学行为。

本文的可选教学功能及推荐架构是对资料和本项目的综合判断，不声称是任何产品公开的完整内部架构。

## 2. 官方资料和论文说明了什么

### 2.1 OpenAI Study Mode

[官方发布说明](https://openai.com/index/chatgpt-study-mode/)将初始版本描述为由与教育专家共同编写的系统指令驱动，包含主动参与、支架、认知负荷、个性化及反馈等行为。公开说明没有提供一套固定的 N 段回答协议，也未公开完整生产提示词或服务源码。不能据此断言其内部没有模板或路由。

[2026 年学习效果说明](https://openai.com/index/understanding-ai-and-learning-outcomes/)延续教学指令，并讨论互动和长期学习的测量。启示是评价跨轮的学习过程，不能只以单轮回答“像老师”、用户喜欢或出现互动图为完成依据。本文不以其研究结果推断我们的系统已有学习增益。

适合借鉴：针对学习目标调节深度、逐步建立联系、用有意义的反馈检查学习。公开程度只支持借鉴机制，不支持复制其完整实现。

### 2.2 Google LearnLM

[LearnLM: Improving Gemini for Learning，2024](https://arxiv.org/html/2412.16429v1)强调 pedagogical instruction following：教师/开发者指定场景行为，模型学习执行不同的教学要求；其后训练包括 SFT、人类偏好及 RLHF，而非只修改通用模型的提示词。文中的场景模板用于构造评测情境，不是要求所有学生回答套相同段落。

附录的编程和辩论等场景呈现不同的指令约束；连续多轮可以累积完整性，不必单轮讲完。我们可以借鉴条件性教学指令和情境评价，但不能把提示词移植描述成获得 LearnLM 的训练能力。

[较早的 LearnLM-Tutor 报告](https://arxiv.org/html/2407.12687v1)补充了教学评价、提示词局限和多轮评价视角。论文及附录是可读依据；本轮没有取得完整训练流水线、权重或训练语料来复现其能力。

### 2.3 Anthropic Learning mode

[官方发布说明](https://www.anthropic.com/news/introducing-claude-for-education)描述引导推理、苏格拉底提问、核心原理和学习工具。结构化写作模板是其可提供的产物之一，不代表每轮对话都使用相同模板。

适合借鉴其对原理和推理过程的重视。不能据公开介绍还原内部选择器；也不能把“永远不直接回答”设为我们所有心理学讲解的规则。

### 2.4 Tutor CoPilot / Bridge

[Tutor CoPilot 论文](https://arxiv.org/html/2410.03017v1)研究给人类辅导教师提供建议。教师会选择策略，系统结合上下文生成建议；它并非一个已证明可以完全自主替代教师决策的系统。论文明确讨论模型默认重复策略的问题。

固定提交的 [Bridge 策略提示词](https://github.com/rosewang2008/bridge/blob/a5b1d426ce517e0aeb4b7b2a64e842501c98e38f/prompts/task2_strategy/gpt4.txt)分别列出教学策略和教学意图，允许在列表不适用时说明其他选择。另有错误判断和回应生成任务。错误是什么、为什么采用某个动作、最后说什么在机制上可以区分；不代表我们必须照搬为三次模型调用。

[公开 CoPilot notebook](https://github.com/rosewang2008/tutor-copilot/blob/25c6eab7e416614f2033358bceddd30a4d5ca616/Tutor_CoPilot_Demo.ipynb)用课程主题、对话和策略填充提示词再生成建议；它是演示代码，包含占位演示和真实 API 示例，不是完整生产后台。其单句生成限制适合即时提示建议，不适合直接复制为教材讲解长度限制。

适合借鉴：把教学意图和学生困难作为选策略依据，用教师审阅过的决策实例约束模型，而非收集很多不同措辞的漂亮答案。

## 3. 两个开源 Agent 的实际组织方式

### 3.1 DeepTutor：状态与交互边界固定，正文按上下文组织

读取提交 `f7aed0744c36c5afef16a4261c31ebee1208cac2`：

- [普通聊天提示词](https://github.com/HKUDS/DeepTutor/blob/f7aed0744c36c5afef16a4261c31ebee1208cac2/deeptutor/agents/chat/prompts/zh/agentic_chat.yaml)：材料、记忆、persona 和工具结果影响生成，普通入口与伙伴 Soul 有不同行为约束。
- [mastery 提示词](https://github.com/HKUDS/DeepTutor/blob/f7aed0744c36c5afef16a4261c31ebee1208cac2/deeptutor/capabilities/mastery/prompts/zh/mastery_loop.yaml)：状态提供教学位置；教学 playbook 根据阶段、偏好和反馈指导本轮动作；提问工具形成回合边界，掌握判定仍交给服务。

值得借鉴的是：允许先教后测，讲解不等于掌握，学生插入疑问可以先答疑，反复困难要实际换方法，而非原样重述。正文可以自由组织，但不能自由更改状态、题目和工具结果。

局限：这是静态代码机制，未运行其完整产品，不能证明其所有回答都更自然或中文教学一定优于本项目。不能把它的普通 chat、mastery 和 book 内容生成混作一套固定回答机制。

### 3.2 OpenTutor：条件提示片段与苏格拉底状态机

读取提交 `3afba67fb809e85559d904ee4e901869d60f5eb9`：

- [tutor.py](https://github.com/zijinz456/OpenTutor/blob/3afba67fb809e85559d904ee4e901869d60f5eb9/apps/api/services/agent/agents/tutor.py)的 `build_system_prompt` 注入当前模式、纠错/评估等条件段、认知负荷指导和少量策略片段，再让模型生成正文。
- [prompts.py](https://github.com/zijinz456/OpenTutor/blob/3afba67fb809e85559d904ee4e901869d60f5eb9/apps/api/services/agent/agents/prompts.py)包含提问、纠错和理解检查等说明。部分条件由英文正则触发；策略片段用词匹配，匹配不到会退到前两个片段。
- [socratic_engine.py](https://github.com/zijinz456/OpenTutor/blob/3afba67fb809e85559d904ee4e901869d60f5eb9/apps/api/services/agent/socratic_engine.py)根据回答情况转换 probe/clarify/confront/scaffold/confirm，并有连续支架后转直接讲解的出口。

适合复用的思想是状态→局部指令→正文。风险是全局“不直接给答案”的规则可能与反复困难后的直接讲解出口冲突；英文触发和固定默认策略也不适合原样迁到中文教材。源码公开不等于教学效果已经充分验证。

## 4. 回答可以包含哪些部分，如何选择

以下是本项目推荐的可选教学功能池，**不是每轮必填栏目，也不是从论文照搬的统一六段模板**。一轮可只完成一个功能，多个功能也可自然融合在一段话里。

| 可选功能 | 何时有价值 | 什么情况下省略 |
| --- | --- | --- |
| 承接学生思路/局部诊断 | 有具体作答、混淆或上一轮困难时，指出已知正确部分和待解释位置 | 只有简单事实查询；没有足够证据判断困难 |
| 核心机制与理由 | 需要理解为何成立、条件如何影响结果 | 用户只要术语或一句答案 |
| 具体示例、反例或逐步示范 | 抽象概念落不到实际场景，或要区分边界 | 示例不能增加理解，或用户明确不需要 |
| 对照、图解、实验流程 | 关系、变化或顺序值得直观看见，且资料与组件支持 | 事实查询；图解会错对象、泄题或没有依据 |
| 独立解释/预测/应用检查 | 允许互动，当前已经有可检查的理解目标 | 只讲不考、仅提示、已有待答题或学生要求跳过 |
| 收束与下一步 | 本轮完成一个关系，需要形成可用判断线索或承接后续目标 | 短答已完整；重复总结只会增加负担 |

推荐由系统确定目标、允许行为和证据，由模型在候选动作中作局部组织选择。正式题目、评分、等待作答和掌握度仍使用现有服务；模型不能靠一句“看来你懂了”推进状态。

不同情况应呈现不同节奏：

| 学生当前请求/反馈 | 合适的本轮行为 | 避免 |
| --- | --- | --- |
| “费希纳是谁” | 简答身份与本教材相关贡献 | 先盘问基础，再展开整堂课 |
| “我想学他相关内容” | 依据教材明确学习路径，从一个有价值的关系开始讲 | 只列章节；一轮堆完整生平和理论 |
| “辨别力和判断标准分不清” | 围绕同一场景区分感知能力与决策规则，配合可核验图解 | 分别抄两个定义后默认学会 |
| “没听懂刚才的图” | 聚焦本图的一个变化，解释其含义；必要时问一个能区分困难的问题 | 从头再讲所有术语；只说“我再简单点” |
| 有具体错误回答 | 先承接其正确部分，再修正具体条件或提供反例 | 无证据贴“基础差”标签；只说再试一次 |
| 多轮仍困难 | 增加直接帮助、必要前置或部分示范，减小任务 | 无限苏格拉底追问 |
| “只要提示” | 给推进当前一步的线索并停下 | 正文藏完整答案，图解却泄露解题过程 |
| “总结一下” | 压缩关系与判断线索，结束或承接已定目标 | 重新输出长篇定义和新例子 |

“先诊断”不意味着每次先问问题。能够从当前输入和已有可靠记录看清目标，就直接教；缺少关键条件时再问。问完需要等待学生，不能同轮代答。

## 5. 当前项目的限制在哪里

以下是当前工作区的静态发现，不能替代实际运行 trace 或覆盖每一条回答路径。

1. `agents/teaching_strategy.py::_decide` 已考虑模式、困难位置、作答结果、既往策略及交互边界，有多个策略候选；不能说项目完全没做教学策略。默认分支仍偏向 direct_explanation/worked_example/scaffolding。
2. `agents/response_composition.py::plan_response` 把策略编译成小量固定块组合，例如 scaffolding→explanation/procedure、worked_example→direct_answer/worked_example。块组合在生成正文之前已经定下，不能仅靠提示模型“自由组织”改变计划。
3. `response_composition_adapters.py::response_plan` 能投影明确任务，且部分情况下保留第二个策略块；但未完整表达每一个 move 的教学意图。策略多不等于正文结构就多样。
4. `ResponseComposer.instructions` 要求输出 pending 中的既定块、统一 claims/source_ids 协议，且禁止创建新题目等。证据与状态保护应保留，但模型目前不能自行增删块；提示词表述更自由不等于结构权限更自由。
5. `published_snapshot` 可以把宿主整段正文包装为一个块。因此看到 `learning_response` 并不证明运行过动态内容规划。需要区分 generated 和 host_snapshot，以及相应来源路径。
6. `frontend/chat-renderer.js` 的统一容器影响可读性；T3.2 能改善这一点，但无法修复上游同样的教学组织方式。

“结构限制可能促成机械感”有代码依据；“所有不自然回答都由这些位置造成”尚无证据。本轮没有读取学生既有原始聊天或运行对照实验。

## 6. 推荐优化方向

### 6.1 教学决策与文字段落分开

第三层继续决定本轮目标、难点假设、允许策略、披露程度和停止边界。第五层在这些约束内决定必要内容和组织，不另建意图识别权威，不由前端猜教学目的。

固定业务义务和安全约束，允许解释、例子、比较等表达功能按价值选用。对于“学生已经懂术语，只是不知道原因”，可以直接解释因果或控制关系，无需再生成定义块。

### 6.2 先改固定结构的限制，再谈加更多模板

推荐有边界的动态组织：明确哪些内容义务必须覆盖、哪些表示方法可选、哪里应停下。在现有调用预算内探讨选择与生成一起完成；不默认再加一个规划 Agent 或多次串行模型调用。

这需要审查 ResponsePlan、pending、验证、恢复与历史契约，不能通过一句“自由回答”绕开现有块校验。先做一个可回退的窄场景试验，再决定是否扩大；保留既有固定路径作为对照和恢复依据。

### 6.3 用教材案例沉淀教学决策实例

优先整理被试设计、信号检测、变量控制等少量教师审阅实例。每例记录：学生输入、已有基础证据、具体困难、选哪个动作及原因、应当停在哪里、合格回应。few-shot 示例展示的是“为何此时这样教”，而非让所有回答复制相同文风。

不立即微调，不复制数学策略的领域内容，不把“visual/example/check”全部变为必填模块。图解在教学目标需要且材料支持时调用，使用已核验预制包或受约束模板。

### 6.4 用连续反馈维持老师感

通过已有状态和记忆服务保留局部教学结果：尝试了什么、学生明确反馈了什么、哪些困难仍未知。沉默、已讲解或系统选择了某策略不证明有效。一次困难不建立永久学习风格标签。

对于“没听懂”，必须能观察到解释方式或聚焦点改变；对于有正确片段的作答，明确指出正确处再补缺口；对于只想听讲的学生，不强制每轮考核。

### 6.5 评价教学行为，而非只评价文风

建议用少量固定多轮案例对比当前版本与候选版本，先由人工盲评，再考虑自动辅助评分。检查：目标是否命中、困难处理是否有依据、是否讲清理由、信息负担是否适当、是否使用了学生反馈、何时讲/问/停是否合适、引用和图解是否可靠。

区分“教师偏好更好”“学生觉得更好”“独立迁移表现改善”。前两项不能证明第三项。无需为了展示结构差异而随机轮换策略或强制加问题。

## 7. 如何衔接刚写的 T3.2 计划

T3.2 的渲染、一致性和引用验收继续有价值，但不足以单独解决本次用户提出的教学质量问题。建议在改展示之前或同时，补一项面向第三/第五层的教学决策到内容组织核查，用具体输入证明实际选择及交付。

推荐顺序：先记录实际第三层策略、第五层计划/生成来源和交互边界；再设计有边界的动态组织试验及教材决策案例；随后用 T3.2 展示结果；最后进入 T4 的多轮人工对照和状态/引用验收，再进入 T5。

这是本轮调研建议，尚未修改上位实施计划、业务代码或默认运行行为。
