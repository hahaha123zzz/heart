# “我想学习第一章的主要内容”为什么只得到 235 字：六层链路核查与外部调研

日期：2026-11-02。对象：`project/integration/discrete-math-tutor` 当前 8000 服务（`7b752ad` + 工作区未提交改动）。方法：只读源码 + 6 条隔离测试账户真实请求 + 外部资料调研。没有修改业务代码、配置、正式学习库或课程数据。

## 1. 结论摘要

**这不是模型能力问题，也不是单纯“字数限制”问题，而是“问答流水线”与“学习会话”不匹配。**

同一模型、同一课程，只把输入从

> 我想学习第一章的主要内容

改成

> 我想学习第一章的主要内容，请详细讲解

输出就从 **235 字** 变成 **1152 字、5 个部分**。模型完全写得出章节导学；是上游把这一轮定义成了“解释一个知识点”，并在提示词里写了“回复不超过 200 字”。

更严重的是：原始回答不仅短，而且**把第一章标题说错了**。课程目录里第一章叫“实验心理学概论”，回答却说“第一章的标题是‘心理学的实验设计和数据处理’”。引文本身在教材里，但它是教材比较不同教材编写体系时列出的**另一本书的目录标题**，不是本课程第一章标题。引用能通过校验，指代对象错了。

| 层级 | 这一轮发生了什么 | 责任 |
| --- | --- | --- |
| L1 上下文与输入理解 | `chapter_id=null`、`section_id=null`，目标是节级知识点；“主要内容”没有绑定为章节范围 | 中 |
| L2 任务与工具路由 | 任务是 `explain_content`，不是“章节导学/学习请求”；`routing.intent` 还是硬编码 `continue` | 高 |
| L3 教学策略 | 13 种策略全是回合级动作，落到 `direct_explanation`，一个 `explain` move | 高 |
| L4 证据检索 | 用原始句子做向量检索，只选 2 个片段，其中一个是别书目录；没有用课程目录 `outline()` | 高 |
| L5 内容组合 | 预算 200/260 字，单块 `explanation`；没有章节地图/学习路径块 | 最高 |
| L6 完成检查 | 标记 `answered/explained`，但没有核对“是否覆盖第一章”；`course_navigation=clarify` 没有进入正文 | 中 |

**设计层面的根因：六层是“问题→证据→回答”的流水线，不是“学习请求→会话计划→分段教学→检查”的流水线。** 项目其实已经有 Q5 章节导学/学习计划，但它埋在“章节导学”“制定计划”等显式关键词后面，没有接入主链路；而且现有 Q5 章节导学只列“每节第一个目标”，也没有主线、重点、节奏和讲解，见 `FULL_BOOK_TEACHING_PLAN_AUDIT.md`。

**另一个必须先确认的事实：8000 当前只有“实验心理学”课程，没有《数据结构》。** 你给的 ChatGPT 回答是《数据结构》第一章；项目回答的是心理学第一章。内容不同，不能直接比较“讲得好不好”。如果目标是数据结构，先要导入该课程/教材，否则这一轮只能验证“教学编排能力”，不能验证“同一章讲得是否更好”。

### 原始回答的关键问题

1. **标题错**：课程目录第一章是“实验心理学概论”。回答写成“心理学的实验设计和数据处理”。引用 [1][2] 指向的是教材第 4 页讨论“不同教材编写体系”时列出的另一本书目录，不是本课程第一章。
2. **没有章节结构**：没有列出第一节到第四节，没有说明各节解决什么问题。
3. **没有学习顺序**：只有一句“抓住两条主线”，没有“先学什么、后学什么、为什么”。
4. **没有下一步**：没有“先从第一节开始”或“要不要我展开第一节”的收束。
5. **长度过短**：235 字，只相当于一个概念解释，不足以承载“第一章主要内容”。

### 变体 B 说明了什么

B 的输出是：

- 第一章定位：“像整本书的总门厅”；
- 五块内容：含义与发展、实验程序、报告撰写、伦理；
- 三种教材编写体系；
- 后面各节的展开顺序；
- 一个“做实验像做菜”的类比。

这不是完美答案，但它证明：**模型有能力在同一个课程里组织出章节导学；缺的是路由、证据范围和预算。**

B 仍然有问题：只有一个 `explanation` 块，五个标题是模型自己加的，不是系统契约；没有覆盖校验；1152 字还超过了它自己的 500 字上限却仍然发布。说明长度门禁在 AgentLoop/内容组合路径上并不统一。

## 4. 逐层证据

### L1：章节范围没有绑定，“主要内容”反而破坏识别

- `input_understanding` 实际输出：`parser=rule`、`model_calls=0`、`actions=[explain_content]`、`content_target.knowledge_point_id=实验心理学的研究方法`、`chapter_id=null`、`section_id=null`。
- `course_navigation.intent()` 对以下句子的结果：

| 输入 | intent |
| --- | --- |
| 我想学习第一章的主要内容 | **None** |
| 我想学习第一章 | start |
| 我想学习第一章的内容 | start |

原因在 `knowledge/course_navigation.py:104-111`：匹配到“第一章”后，要求剩余部分只能是“的/内容/全部/从头/开始/学习/讲解/吧/标点”的重复；**“主要”不在允许集合里**，所以整句不成立。`第一章讲什么`、`第一章主要内容是什么` 也都是 `None`。

- `agents/q5_runtime.py:50-59`：`is_plan_request` 只认“制定/生成/规划…计划”“今天怎么安排”等；`is_chapter_guide` 只认“章节导学/目录草稿/目录计划/按章导学”。自然说法“我想学习第一章的主要内容”两个都不命中。
- 结果是：上游目标是节级知识点，下游检索却从“第一章”三个字里恢复了 `chapter_id=1`。同一个请求被两套判断解释，目标不一致。

### L2：把“学习一章”当成了“解释一个问题”

- `six_dim.request_intent=knowledge_query`，`action=explain_content`。作为“解释”没错，作为“学习/导学”不够。
- `routing.intent` 在 `agents/agent_loop_service.py:237` 是硬编码的 `"continue"`，不是本轮分类结果。这条字段不能当作理解正确的证据；它与 `input_understanding` 的 `knowledge_query` 是两套口径。
- Q5 有能力：`第一章章节导学` 会返回章节草稿（见下），`帮我制定第一章的学习计划` 会进入 session plan。但自然问法没有进入这个入口。

`第一章章节导学` 的实际输出：

```text
### 学习计划草稿
目标：浏览第1章结构，从各节首个目标开始；不代表整章覆盖或掌握
1. 第一节 实验心理学的研究对象
   - 实验心理学的含义 ← 当前
2. 第二节 实验心理学的产生与发展
   - 笛卡儿的哲学思想
3. 第三节 心理学实验的程序
   - 理论之间的争论
4. 第四节 心理学实验中的伦理问题
   - 应该遵守的伦理原则
确认后进入学习；也可以先调整。
```

这是可用的骨架，但它仍然只是“每节第一个目标”，没有章节主线、没有各节核心问题、没有讲解。`FULL_BOOK_TEACHING_PLAN_AUDIT.md` 已经指出：当前按节分组只取 `section_units[0]`，不能叫完整覆盖；也缺主线、重点理由、讲次、节奏和出口标准。

### L3：13 种策略都是“回合级”，没有“章节级”

- `agents/teaching_strategy.py:270-271` 的兜底分支是 `direct_explanation`；本轮 `depth=normal`、`moves=[explain]`、`allow_check=true`。
- `knowledge/teaching_strategies.json` 里是直接讲解、苏格拉底、提示、支架、样例、对比、反例、自我解释、提取练习、引导修正、直接纠正、迁移、总结。没有“章节导览/先行组织者/学习路线”这一策略。
- 所以即使预算足够，第三层也只能决定“这一轮怎么讲这个点”，不能决定“这一章先讲什么、分几段、哪里停”。

### L4：证据检索选到了“别书目录”，而且没有用课程目录

- 原始请求的 `retrieval_trace.q2_selection` 只有两行：`ch01:b87` 被拒，`ch01:b63` 被接受；最终 2 个 PDF 引用都来自 `ch01:b63` 附近。
- 被接受的片段是：

```text
(三)主要讲心理学实验具体应用的教材
这种结构体系的教材从各个心理学领域的具体实验入手……有代表性的教材是赫葆源等编写的《实验心理学》(1983)。其目录如下:
第一章　心理学的实验设计和数据处理
```

- 这段是教材在比较不同教材编写体系时列出的**另一本书的目录**。模型把其中的“第一章”当成了本课程第一章标题。引用字面成立，指代对象错误。
- 课程自己的目录在 `knowledge/course_navigation.py:42` 的 `outline()` 里，第一章标题是“实验心理学概论”，下面是四节。这轮没有用它。
- 根因不是“检索引擎坏了”，而是任务类型错了：章节导学是**结构任务**，需要目录/课程元数据；当前却用了面向正文语义匹配的向量检索。用“我想学习第一章的主要内容”这种低信息量句子去检索，最容易命中“第一章”字样的目录碎片。

### L5：200/260 字预算是直接原因，但不是唯一原因

- `agents/agent_loop_service.py:499-503`：

```python
budget = reply_budget(request.message)
system_prompt = build_loop_system_prompt(...) + "\n" + budget.instructions()
```

- `agents/reply_budget.py` 对普通问题默认 `target=200`、`maximum=260`，提示词是“回复不超过 200 字；为保留必要内容可到 260 字”。
- `agents/quality_checker.py:275-285` 在旧路径上会硬性拒绝超过 `maximum` 的回复。
- 实测：

| 输入 | target | maximum |
| --- | --- | --- |
| 我想学习第一章的主要内容 | 200 | 260 |
| 我想学习第一章 | 200 | 260 |
| 我想学习第一章的内容，请详细讲解 | 480 | 500 |
| 我想学习第一章的主要内容，请详细讲解 | 480 | 500 |
| 帮我制定第一章的学习计划 | 200 | 260 |
| 第一章章节导学 | 200 | 260 |

- `reply_budget` 里其实有“详细/完整/展开”“先…再…”“多个子问题”“计划+详细”等放宽分支，但都要求**显式措辞**；“我想学习/主要内容/带我学/导学/第一章讲什么”不在里面。所以“学习请求”被按“概念简答”对待。
- 预算不是硬保证：A（预算 260）输出 417 字，B（预算 500）输出 1152 字，都超过了上限仍发布。说明长度控制在 AgentLoop/内容组合路径上主要是提示词约束，不是统一门禁。原始问题 235 字落在 260 以内，模型是按提示词收着写的。
- `response_composition.py:16-35` 的 `plan_response`：`direct` 只生成一个 `direct_answer`；`explain_content` 在适配器里变成单块 `explanation`。没有 `roadmap`、`outline`、`chapter_map` 之类的块类型。所以 L5 即使想写章节导学，也没有结构契约。

### L6：完成标记只证明“发布了”，不证明“学习请求完成了”

- 原始结果：`answer_status=answered`、`teaching.stage=explained`、`strategy_plan.status=published`，但 `strategy_plan.moves[0].status=not_observed`。
- 同一结果里 `course_navigation.status=clarify`，正文是“这次回答对应的教材位置不唯一。请说明要从哪一部分继续。”但最终 `reply` 没有这句话，也没有让用户选择。
- 没有检查“第一章导学是否覆盖了四节”“章节标题是否等于课程目录标题”“是否声称了未提供的掌握”。
- 这和费希纳追问审计里的第六层问题同型：**工具/发布完成 ≠ 原始学习任务完成**。

## 5. 所以，是字数限制太多了吗？

**是，但只对了一半。**

1. **直接原因确实是 200/260 的默认预算。** 原始问题 235 字，和 200/260 的提示高度吻合；改成“详细讲解”后同一模型写出 1152 字。
2. **不能全局调大。** 项目自己的原则是“适当长度、管理认知负荷”；简单定义题也写 1000 字，会变成另一种失败。应按**任务类型**给预算：概念简答 200–300；比较/多步 320–500；章节导学/学习计划 600–1000，并分段。
3. **只调预算不够。** B 虽然长，但仍是单块、无覆盖校验、无下一步契约；章节标题还可能错。预算解决“写多长”，解决不了“写什么结构、依据什么、如何算完成”。

一句话：**这不是“字数上限太低”，而是“把章节导学当成了概念简答，并用一个正则决定所有任务的篇幅”。**

## 6. 外部调研：其他学习 Agent 怎么做

### 6.1 OpenAI Study Mode：用系统指令塑造“教学行为”，并明确反对一次性讲义

OpenAI 的 Study Mode 不是新模型，而是一组与教师、科学家、教学法专家共同写的 **custom system instructions**。公开材料列出的核心行为是：

- 鼓励主动参与（提问、提示、自我反思，而不是直接给答案）；
- 管理认知负荷；
- 发展元认知与自我反思；
- 激发好奇心；
- 给具体、可行动的反馈。

功能上对应：

- **Interactive prompts**：苏格拉底式提问、提示、自我反思；
- **Scaffolded responses**：把信息组织成易跟的分节，突出主题之间的联系，降低复杂主题的压迫感；
- **Personalized support**：根据目标、水平、历史调整；
- **Knowledge checks**：小测/开放题 + 反馈；
- **Break a large topic into smaller sections**。

OpenAI 在发布说明里强调 Study Mode 是**分段、带检查**地展开，而不是直接给最终答案；Ars Technica 的报道把普通 ChatGPT 的回答形容为“a mini textbook chapter”。也就是说，你给的那段 ChatGPT 回答更接近“普通模式的一次性讲义”，不是 Study Mode 的目标形态。值得学的是它的**结构**（先给地图，再分段，再例子/检查），不是它的**长度**。

对我们的启示：

- “章节主要内容”应该先给 **advance organizer**（这章解决什么问题、分几块、怎么排），再进入第一段；不是一上来把五节全讲完。
- “先给计划/目标”要写进系统指令，但**不能只靠提示词**——OpenAI 也承认 prompt-only 会不一致，计划后续把行为训练进模型。我们的工程化程度更高，应该用确定性计划补上。

### 6.2 Google LearnLM：把“教学法”拆成可评估的 rubric

LearnLM 的核心是 **pedagogical instruction following**：训练和评估样本都带 system-level instruction，描述期望的教学法属性；再用教育专家做盲评。它的五条学习科学原则是：

1. Inspire active learning；
2. Manage cognitive load；
3. Stimulate curiosity；
4. Adapt to the learner；
5. Deepen metacognition。

在 2025 年的“arena for learning”评测 rubric 里，和本次问题直接相关的条目包括：

- **Appropriate response length**：回复长度适合学生；
- **Manageable chunks**：用分点/格式把信息拆成可管理的小块；
- **Communicates a clear plan or objective**：向学生说明本次对话的计划或目标；
- **Adapts to learner**：根据目标和水平调整。

这几乎就是本次回答的反面清单：长度不适合“章节导学”、没有分块、没有说明计划、没有根据“我想学第一章”调整任务类型。

对我们的启示：

- 给“章节导学”定义一份可检查的 rubric：是否有本章主线、是否覆盖各节、是否说明学习顺序、是否给出下一步、是否区分教材原文与教学建议、是否声称掌握。
- 只改 prompt 不够，必须有结构和验收；否则每次输出形态都不一样。

### 6.3 Mayer 的先行组织者与分段原则：不是越长越好

- **Advance organizer / signaling**：先给组织框架，突出材料结构，帮助学习者把新信息挂到已有认知结构上。
- **Segmenting principle**：复杂内容按学习者节奏分成有意义的片段，比一次性连续呈现更利于保持和迁移。

所以“第一章主要内容”的理想形态不是 3000 字连续讲义，而是：

```text
本章地图（1 段）
→ 4 个节级问题（列表）
→ 推荐顺序（1 段，说明理由）
→ 第一段讲解（1 个概念 + 例子）
→ 一个下一步（开始第一节 / 先看某一节 / 不出题）
```

### 6.4 项目自己的全书教学规划审计：计划契约还缺什么

`FULL_BOOK_TEACHING_PLAN_AUDIT.md` 已经给出目标契约：

- 总体主线；
- 阶段/模块及目标；
- 章/节/目标映射；
- 学习顺序理由；
- 核心/细节/易混点及依据；
- 必要先修；
- 建议学习活动；
- 可观察出口标准；
- 预计讲次/时长；
- 下一动作。

现有 Q5 章节导学只做到“章/节/第一个目标”的映射，其他项都缺。所以“把自然问法路由到 Q5”是必要条件，不是充分条件。

## 7. 建议的修改顺序

### P0：先用最小改动验证“路由 + 预算”是否足够（1–2 天）

1. **修 `course_navigation.intent` 的后缀白名单**  
   在 `knowledge/course_navigation.py:104-111` 允许“主要/重点/核心/基本/大致/整体/概要/简介/框架/脉络/讲什么/学什么”等修饰；补测试：
   - 我想学习第一章的主要内容 → start
   - 第一章讲什么 → start/overview
   - 第一章主要内容是什么 → start/overview
   - 我想学习第一章的主要内容，请详细讲解 → start
   - 不要默认第一章、不要抢“第一章某节具体概念”的提问。

2. **让 `reply_budget` 识别“学习请求/章节导学”**  
   不要改全局默认。新增条件：包含“学习/想学/带我学/导学/概览/主要内容/框架/脉络”且包含“章/节/全书/课程” → `target=600/800`、`maximum=900/1000`；如果同时出现“详细/完整/逐节/分别”再提高到 1200。  
   同时修一个明显的漏洞：`帮我制定第一章的学习计划` 现在是 200/260，计划类请求至少应该 480/600。

3. **把“章节导学”的验收写成测试**  
   最低验收：  
   - 字数 ≥ 600；  
   - 明确写出本章标题（必须等于 `chapters()` 的标题）；  
   - 列出全部节标题，或明确说“本次只覆盖前两节”；  
   - 至少 1 条本章定位/主线的教材依据；  
   - 不声称掌握、不推进路径；  
   - 最多 1 个下一步问题。

这一步的预期：原始问题从 235 字提升到 700–1000 字，且结构接近 B。风险：如果只放宽预算而不修章节范围，可能得到“更长的错误锚点”（比如继续把别书目录当本章标题）。

### P1：增加一等公民 `chapter_overview`，用课程目录而不是向量检索（3–5 天）

1. **L1/L2 新增任务类型**  
   `chapter_overview`（或复用 `propose_learning_plan` 的轻量分支），与 `explain_content` 分开。输入是“章 + 学习/导览/主要内容”，不是“某个概念”。

2. **L4 用 `course_navigation.outline()` 作为结构证据**  
   - 章标题、节标题、每节第一个目标来自课程发布数据，不靠向量检索；  
   - 本章“定位/主线”再从章节导言/第一节正文取 1–2 个有引用的片段；  
   - 不要把“目录/标题”当作教材正文事实；需要区分 `course_structure` 与 `textbook_quote` 两种 provenance。

3. **L5 增加 3 块计划**  
   `roadmap`（本章地图/主线）→ `section_map`（各节核心问题）→ `first_concept`（第一段讲解 + 例子）。  
   这不一定要新建渲染器；可以先在 `ResponsePlan` 增加 `semantic_type`，或者用现有的 `explanation` + `procedure` 组合，但要有结构契约，不能靠模型自由加标题。

4. **L6 完成检查**  
   - 章节标题必须等于当前课程目录；  
   - 覆盖检查：列出全部节，或显式声明省略；  
   - `course_navigation=clarify` 要么被正文消费，要么不要返回给前端造成“两个答案”；  
   - 不允许 chapter overview 写 `formal_mastery=true` 或推进路径。

### P2：把 Q5 计划补齐（按已有全书审计）

- 主线、重点/细节、先修、活动、出口标准、讲次/时长、下一动作；
- 章节导学只写“每节第一个目标”不够，至少给出每节的核心问题；
- 计划确认后要能真正按计划教学，而不是回到“第一章逐节草稿”。

### 不建议的做法

- **不要全局把 200 改成 1000。** 简单定义题会变得啰嗦，违反认知负荷原则。
- **不要只加正则同义词。** “主要内容”只是入口；后面还需要章节范围、结构证据、块计划和完成检查。
- **不要关闭引用/证据门禁来让回答变长。** 这轮的问题不是门禁太严，而是证据选错了对象。
- **不要把 ChatGPT 的 3000 字讲义当默认目标。** 更合理的是“先行组织者 + 分段 + 第一段 + 下一步”。

## 8. 边界与未验证

- 本轮只测了 6+2 条单轮请求，使用隔离测试账户；没有测多轮“导学→开始第一节→追问”、浏览器页面、教师评分或学习增益。
- 8000 服务是 `7b752ad` + 工作区未提交改动；结果只代表这个快照。
- 8000 当前只有实验心理学课程；没有《数据结构》教材。跨课程比较需要先导入课程。
- 原始回答的“第一章标题错误”是就课程目录而言；引文本身在教材第 4 页存在，但属于另一本书的目录。这个判断已核对 `chapters()` 与引用片段。
- 没有验证 B 的 1152 字是否被前端完整展示；只核对了 API `reply`。
- 没有声称“更长=学得更好”。学习效果需要独立试验，不能用字数或主观偏好替代。

## 9. 需要你确认的两件事

1. **目标课程**：你要优化的是“心理学第一章”的导学，还是准备把《数据结构》作为新课程导入后再比较？如果是后者，当前 8000 没有该课程，先导课程/教材，否则我们会在不同内容上做无效对比。
2. **首轮期望形态**：  
   - A. 章节地图 + 各节核心问题 + 第一段讲解 + 一个下一步（推荐，符合分段/认知负荷）；  
   - B. 一次把整章讲完（接近你给的 ChatGPT 回答，但更长、更容易超载）；  
   - C. 先给计划草稿，用户确认后再逐节讲（现有 Q5 风格，交互更重）。
