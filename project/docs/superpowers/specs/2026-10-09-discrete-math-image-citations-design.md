# 离散数学助教教材图片引用设计

## 目标与范围

建立可核查的图片引用闭环：从原始教材取得图片，记录教材图号与章节，检索相关图片，在教材页面和助教回答中显示原图。当前发布已核对的图 7.8、图 7.20、图 7.23。

## 数据流

1. 图片文件放在 `knowledge/figure_assets/`，目录清单 `knowledge/figure_catalog.json` 保存稳定 ID、图号、章节、小节、来源、说明、SHA-256 和审核状态。
2. `knowledge/figures.py` 只读取 `approved` 且校验通过的图片。明确图号优先且只返回对应图片；其他检索按图注关键词匹配，不把一般性的“图”字视为命中。
3. `/api/course/chapters/{chapter_id}/sections/{section_id}` 返回该小节图片；`/api/figures/{figure_id}/image` 用白名单 ID 提供图片文件。
4. `/api/chat` 返回 `image_refs`，前端以图片卡片显示图号、来源和原图。回答提示词提供已核对的图号、图注和相邻说明。真实模型模式下，生成和质检请求还会将命中的已核对 PNG 作为视觉输入发送给 `OPENAI_VISION_MODEL`；发送前再次核对文件 SHA-256。模拟模式只检查引用流程，不做视觉理解。

## 验收

- 图 7.8、图 7.20、图 7.23 能在对应小节展示，并随明确图号问答返回；图号问答优先使用该图附近的教材原文。
- 无关提问、未审核图片、缺失文件或错误哈希均不产生图片引用。
- 图片 URL 不接受任意文件路径；教材正文和聊天文字继续进行 HTML 转义。
- 离线检查覆盖目录校验、检索、视觉请求格式和缓存后文件替换拦截；真实模型的视觉理解需要本机配置 API 密钥后单独验证。

## 后续批量导入

旧版 `.doc` 中公式和图片混杂。用 LibreOffice 转换后对 Docling 的图像、图注和小节定位做逐章抽样；只有人工核对通过的条目才进入 `approved` 清单。新增图片仍须验证图号、章节与内容的对应关系。
