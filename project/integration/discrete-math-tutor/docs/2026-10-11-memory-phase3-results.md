# 记忆系统第三阶段结果：逐项误区更新与解除

日期：2026-10-11

## 完成范围

在现有 FastAPI、SQLite、MemoryManager 和 StateUpdater 上扩展，未引入新的记忆框架运行依赖。借鉴前期调研中 Mem0 的显式变更、Graphiti 的事件来源链、Letta 的受约束记忆更新思路；没有复制它们的源码。

- StateUpdater 输出逐项 misconception_updates，包含已有误区整数 ID、resolve/dismiss、学生原文和纠正理由。旧 resolve_misconceptions 布尔输出保留解析兼容，不触发自动批量解除。
- 服务端校验当前学生、知识点、原文归属和独立作答资格。模型声称 verification=rule_verified 不会被采纳。
- AI 反证首次仅 pending；不同事件且不同原文累计两条后才解除或驳回候选误区。同轮重复更新、同原文跨轮复制不增加反证票数。
- 新支持证据中断旧反证累计；已解除的误区出现新的独立支持时重新开启。只更新对应误区，不清空其他误区。
- 同一轮出现支持和反证，或同时 resolve/dismiss，保留 conflict 审计并保持原状态。confirmed 误区的自动 dismiss 提议返回 review_required；目前没有人工审核页面。
- misconception_observations 保存事件、证据、动作、前后状态、原文摘要哈希和理由。状态、证据、审计和修订在同一事务内；质量拒绝、教学错误、版本冲突不提交纠正。
- 记忆检索排除已解除/驳回误区的旧支持证据，保留纠正历史；返回 evidence_type 和 misconception_id，让 AI 区分候选反证和当前状态。

## 定向验证

执行：

~~~text
.venv/Scripts/python.exe -m unittest tests.test_misconception_updates tests.test_memory_retrieval tests.test_memory_events tests.test_quality_guard
~~~

结果：**58 项通过**，本阶段新增 15 项，之前 43 项全部通过。使用内存 SQLite、模拟代理和模型，不调用真实 API，不读写生产学生数据库。

覆盖：逐项解除、重复事件/原文去重、新支持中断累计、误区复发、支持与反证冲突、相反动作冲突、学生/知识点隔离、无原文/纯自述/提示后作答拒绝、候选驳回与已确认误区保护、可信规则入口、非法模型输出、原子回滚、版本冲突、教学错误、真实 Orchestrator 接线、旧布尔兼容、质检拒绝、学生删除级联、纠正历史检索。

检索验证最初发现测试使用了不存在的 metadata 字段；追踪真实返回结构后，补充了产品所需的证据类型和误区 ID，并按实际契约验证。测试发现阶段的重复测试收集已移除，58 是最终独立检查数量。

## 实际限制

- 两条反证是初始工程阈值，未经真实学生数据校准；原文不同不保证语义独立，模型也可能误判内容，需要后续质量评估。
- 聊天中的判断始终 ai_provisional。rule_verified 单条通过逻辑仅为可信服务端入口预留；练习评分尚未映射具体误区，不能声称已接通习题自动解除。
- 纠正不会直接提高掌握度；掌握度依然使用第一阶段独立作答资格与单次数值融合规则。
- 旧批量解除 Repository/MemoryManager 接口仍保留兼容，但新自动教学流程不调用它。
- 本轮未启动/重启服务，页面暂不能视为已运行新版。新表由下次 init_db 建立，无须回填旧记录；旧误区仍可以接受新来源明确的反证。
- 检查输出存在原有 datetime.utcnow 弃用提示，不影响通过结果，本阶段未扩展修改时间字段。
