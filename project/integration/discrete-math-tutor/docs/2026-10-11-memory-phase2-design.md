# 第二阶段：统一长期记忆检索

依据已批准的调研路线继续实施。使用 brainstorming 梳理边界；本阶段设计延续已确认的“全历史记忆检索”，不改变界面。

## 选择
保留 SQLite 和 MemoryManager；新增可重建的记忆文档索引，FTS5 关键词、精确知识点/题号/PDF 位置和可选现有 BGE 向量融合。相比直接扩大最近对话窗口，可定位远期记录且限制提示长度；相比接入外部框架，不增加数据库服务和框架依赖。

## 数据与入口
- 原始数据仍在对话、证据、事件与练习表中。memory_documents 只是派生索引，按学生隔离，更新前核对来源哈希；删除学生级联删除索引和 FTS 条目。
- 检索读取完整历史，不使用最近 20 条上限；结果由相关性选择，不将全部历史塞给模型。FTS 在当前学生集合内排序与截断，避免全库 top-k 后才做过滤。
- PDF 定位匹配必须同时核对 document_id/version/page，练习匹配 question_id/version，版本不相容的结果不会作为精确来源。
- 当前偏好直接读取 profile；学习状态、当前误区、证据与原始对话分别返回。resolved/dismissed 误区不作为当前问题。历史助教回复不是学生能力证据或教材事实；不把候选诊断写成确定事实。
- 普通提问使用 MemoryManager.retrieve_context；圈选与练习保留 selection_memory 兼容壳，内部调用同一入口。

## 向量与预算
模型调用在数据库事务外。复用现有 BGE/ONNX GPU 配置；默认仅复用已初始化的本地模型，不为记忆检索下载模型。可显式配置 MEMORY_EMBED_MODEL 启用，模型失败时降级关键词。向量按模型版本/内容哈希缓存到派生表，保存时重新检查学生和源文档，删除后不能重生。全历史向量初次建立成本需单独评估；本轮用注入的确定性向量验证逻辑，不声称实机 GPU 性能已验证。
上下文 JSON 默认不超过 6000 字符，以硬预算裁剪；完整来源仍保留在数据库。RRF 融合只用于相关性，不将得分当作事实真实性。

## 验证
隔离数据库、模拟模型；检查 20 条之外的记录、同义语义召回、学生隔离、撤销/已解决误区、模型失效、文档版本、内容更新、删除、预算和三个入口接线。继续保留第一阶段及质量检查门禁。
