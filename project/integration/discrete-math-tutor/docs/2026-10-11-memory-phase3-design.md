# 第三阶段：逐项误区更新与解除

沿用已确认改造路线，继续使用 brainstorming 的边界梳理方法。本阶段实现具体误区的反证更新，不增加 UI 或新模型调用。

## 借鉴与本地规则
借鉴 Mem0 的显式记忆变更、Graphiti 的证据来源链与时间有效性、Letta 的受约束写入。学生是否纠正误区由本地证据规则决定，不交给一个批量 true/false。AI 连续两条不同原文、来自不同独立事件的有效反证才触发解除，是本项目初始工程阈值，不是论文给出的保证。

## 数据与流程
新增 misconception_observations 审计表，关联学生、误区、事件、证据，保存支持/解除/驳回/冲突、原状态、新状态及判定理由。同一事件同一误区唯一，与现有回合工作单元一起提交。
StateUpdater 输出 misconception_updates，每项必须有当前误区 ID、resolve/dismiss、source_quote、reason；旧 resolve_misconceptions 字段保留兼容但不执行批量解除。模型不能提供可信度等级以升级其结论。
只接受当前学生、当前知识点的目标；原文必须来自本轮学生输入；必须是具备有效原文测量的独立作答。自述懂了、提示后照抄、质检失败、教学错误、版本冲突均不触发解除。
单条 AI 反证保持原状态并记为 pending；不同独立事件且不同原文累计达标才 resolved。dismiss 用于推翻候选误区，不自动推翻已确认误区，后者保留待复核。服务器验证的 rule_verified 反证可走单条分支，当前实际聊天仍是 ai_provisional，练习尚无误区级评分映射，因此不自动接入此分支。
同轮同一目标同时支持和反驳，或同时请求 resolve/dismiss，记冲突而不改变该目标。重复反证不增加有效票数，新支持事件中断此前纠正票数；误区复发重开后必须重新累计反证。
更新只作用于指定误区，不提升掌握度、不清空其他误区。检索过滤旧支持证据，同时保留有来源的纠正历史；当前摘要由仍活跃的误区生成。

## 验证与暂不包含
隔离 SQLite 和模拟模型：逐项目标、两个独立反证、同原文去重、同轮冲突、复发、学生/知识点边界、伪造原文、旧总开关、回滚、并发版本、原子审计与检索更新。暂不实现人工复核 UI、习题到误区的评分映射、后台反思和真正的自动诊断正确率保证。
