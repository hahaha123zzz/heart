# 证明讲解与错误前提补检索

## 本轮目标

修复已有真实案例中的两项不足：删边证明未交代全图连通；欧拉回路的错误前提问题缺少定义依据，直接返回通用拒答。

## 方案

1. 在模型证明审核前加讲解完整性规则：对删边后整图仍连通的肯定论断，要求写明边的端点与任意路径的替换。不把假设或批评性的陈述识别为肯定论断。规则拒绝意味着讲解缺少必要展开，不意味着已形式化证伪。
2. 对含“是否、成立、正确、反例、判断、真假”的问题，在证据为 partial/insufficient 且列出具体缺失依据时，最多补检索一次。分别查询最多三个缺失依据，各优先取一个结果，避免定理编号污染其他缺失项的查询；最多增加三个片段，总数最多六个；原证据顺序和编号保留。
3. 用完整原问题再次检查充分性，仍不足则拒答。冲突、核验服务不可用、普通解释问题不进入此补检索分支。
4. 只有证据核验和质量审核均通过，才能发表答案并进入既有学习状态更新流程。错误命题可以依据已检索定义与反例被否定，不要求强行证明。

## 验证与边界

先确认旧实现对两种不完整删边解释均误放行，再加入测试与修复。以模拟模型一律通过的方式验证规则能独立拦截；同时测试条件假设、批评性解释与完整替换步骤。测试补检索去重、数量上限、原编号、完整问题复核和拒答时不写学习进度。

真实 API 重测旧失败案例属于开发回归，不能称为独立留出评测。保留原失败记录。规则依据措辞检查，覆盖有限，不能验证任意图论证明；模型审查也不是形式化证明器。补检索触发时增加一轮召回和充分性调用。
