# 长证明与前置知识检索结果

日期：2026-10-11

## 改动

保留 FTS5、BGE dense、RRF、GPU reranker 和现有页面。新增 PDF 编号单元关联层；不重新生成向量，不改变原教材文件。

扫描得到 473 个编号单元，其中 173 个定理；79 条能定位到教材顺序在前的显式引用；41 个单元有省略提示。这些是扫描结果，不是已验证的数学知识图谱。

只对已经召回的明确编号证明扩展；来源、小节、编号和 PDF 版本必须吻合。终点取下一个知识单元、小节或练习，完整正文最多八页/24000字符，超限保留原检索。模型视觉输入仍最多两页，指定步骤优先定位所在页。

前置引用提供独立资料编号和真实 PDF 页码。原文引用可能有错号，关系标记为 explicit_citation_not_mathematically_verified；不自动改号，不把“原文引用过”当作前提正确性保证。

## 开发验收

85 项回归测试通过，包括真实两页证明、跨小节引用、教材省略、错误来源/小节、版本失效、字母后缀误匹配、合成三页单元和裁图页数限制。

真实教材诊断使用五色定理、树等价命题省略方向、跨小节奇数度顶点证明和数据库越界问题。真实样本没有找到三页以上的目标证明；三页行为只在合成 PDF 测试中验证，不能声称完成真实三页证明验收。

## 保留的问题

多定理对比暂不走本轮扩展；只关联显式编号引用，隐含前置定义未自动建图。

当前按页/明确蕴含方向定位重点，尚未实现持久化的逐步证明学习进度。完整正文可支持追问，但模型回复仍受短段落限制。

教材可能有数学错误或错号；模型充分性与质检不能替代数学审查。多页正文中不在本轮两张裁图内的公式，视觉完整性不保证。

GPU 首次推理耗时仍需另行诊断。

## 真实问答与人工复核

旧 GPU 基线保留四题；中间 CPU 与 GPU 各五题，所有临时测试账号均已删除。中间 GPU 版本确认：指定红黄/黑白证明步骤聚焦第13页，跨小节证明带入第4页的定理7.2，树等价命题留给读者的步骤明确称为补充推导，PostgreSQL问题拒答且不返回教材引用。裁图 HTTP 均为200，讲解没有自动推进掌握步骤。

完整五色定理路线在第一轮 GPU 复测中仍被约200字的默认限制截断，不能据模型质检通过声称完整路线验收成功。修复为：学生明确要求完整证明/证明思路时，生成上限360字、650tokens；质检同步允许相应讲解到380字（含截断提示余量），普通提问仍用原限制。修复后的结果另存 overview-final，早期记录保留。

GPU第一次最终部署预热293.3秒；耗时仍定位在首个 ONNX reranker推理，根因未确认。普通模型调用用时与GPU冷启动分别记录，不混为检索耗时。

完整证明路线的受控生成暴露旧计划目标残留：正文检索虽已对齐，计划 goal 仍可能停在“图的基本概念”，导致错误质检。证明扩展生效时现将 plan.goal 对齐编号定理，并明确允许应学生要求先讲证明路线；学生掌握状态不因此推进。受控验证与端到端API结果分开记录。

受控生成按实际质检反馈最多重生成一次后，得到356字的完整路线和换色解释，质检通过，人工核对核心数学关系正确。它使用指定单元，不作为召回结果；记录见 artifacts/proof-overview-controlled.json（保留 attempts）及 artifacts/long-proofs-manual-review.json。
