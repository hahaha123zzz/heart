# PDF 教材阅读器升级与选区问答
日期：2026-10-09
状态：用户已确认；已实现并完成验收。
本设计替代 reader-workbench-design 中的界面重构方向，保留先前选中提问需求。

## 范围
保持现有平台布局、可折叠章节目录、右侧答疑及其他页面。仅将教材内容标签内的 HTML 阅读引擎升级为 React + PDF.js + react-pdf-highlighter，新增必要的页码、缩放、文字选择/区域框选控件及提问引用预览。
重点笔记、例题线索和测验继续使用已有结构化教材数据。

## 方案
推荐以 React 组件局部挂载 PDF 阅读器，保留现有原生 JavaScript 平台。整站迁移 React 会扩大范围；原生 PDF.js 自建选区则需要重新实现已有组件的选区与坐标处理。选择局部挂载。
依赖以 npm 实际发布版本和兼容性测试为准，锁定 React、PDF.js 和 highlighter 版本；不直接把 GitHub main 的候选版本当成稳定发布。构建产物、worker、字体及必要资源由本地 FastAPI 提供，不依赖运行时 CDN。

## 教材准备与定位
- 由 Word 只读打开原始十章 .doc，导出每章 PDF；不覆盖或保存原文档。保留图、公式、表格及原始排版。
- 建立教材清单：文档 ID、文件哈希版本、章、小节对应页码和位置。优先由 Word 段落位置与分页取得小节映射，并以 PDF 正文校验，不能仅按标题字符串模糊猜测。
- PDF 分页与 Word 渲染需实际验证；出现无法确认的映射时明确报告，不能静默错位。
- PDF 内保留原教材图注；此前去除的自动来源文件名、未核定标签及 Word 锚点不会重新插入。
- 章节目录点击后阅读器加载对应章节 PDF，并定位小节标题。两个教材入口复用同一组件实现。

## 前端选区
- 拖选文字显示“向 AI 提问”；开启区域框选后可选图片、公式或表格区域。
- 使用文档 ID、哈希版本、页码及归一化矩形保存选区；文字选区另存多行矩形与文字快照。缩放后仍可定位与高亮。
- 点击提问将选区预览附在现有输入框，用户可修改问题再发送；取消引用不发送请求。
- 选区记录绑定原 PDF，不随随后切换章节改变。课程学习页也能携带引用进入现有答疑入口。
- 首版区域框选限制单页；跨页文字以逐页矩形记录，明确限制页数与尺寸。触屏使用明确的框选开关，不依赖 Alt 键。

## 后端上下文与图像
- ChatRequest 新增可选 PDF selection；两个聊天接口统一验证文档、版本、页码、坐标范围及大小。
- 后端从自身 PDF 文本与坐标重建选中文本；图、公式及含图选区从原 PDF 按坐标裁图，不把浏览器提供的截图当权威教材事实。
- 抽取所在页与邻近段落，并关联原结构化教材小节、图和公式资源。混合图文以选区裁图及真实正文为证据，相关 RAG 只补充定义，不覆盖选中内容。
- 图片输入沿用数量、尺寸限制；超出时要求缩小选区，不静默丢弃。
- PDF 字体或公式不具备可靠文本层时按真实图像解释，不能把提取失败描述成已经识别数学公式。

## 学习记忆与回答
复用 MemoryManager，按 student_id 筛选相关知识状态、误解、偏好及有限历史。不让旧 active_goal 覆盖当前选区，不编造无历史用户的学习经历。
新增定位选区与读取学习记录的真实进度，复用生成、质量检查和保存流程；生成与检查均取得选区图片。
选区提问不自动认定掌握或错误，不推进原课程步骤。保存引用元数据与对话，回答引用可跳回 PDF 页及选区，刷新后可恢复。

## 实施顺序
1. PDF 导出与页码/小节映射，核对图表公式保真。
2. 局部挂载阅读器、章节跳转、缩放及文字/区域选择。
3. 后端选择校验、PDF 上下文与裁图、相关学习记忆。
4. 接入现有聊天、处理进度、引用保存与返回原文。
5. 单元/API/浏览器及真实模型验收。

## 验收
十章正常打开；第7章选定理、第8章圈匹配图、第3章圈二项式公式、第10章圈表格均得到正确位置和上下文。
至少图与公式各一次真实 DeepSeek 问答；确认模型实际收到裁图。两个学生记忆隔离，无历史不编造。
缩放、滚动、章节切换、重复提问、取消、移动端、刷新恢复与引用返回正确。
无效页码、旧版本、越界矩形、过大选区均在模型调用前明确拒绝。普通聊天和其他页面可用。
