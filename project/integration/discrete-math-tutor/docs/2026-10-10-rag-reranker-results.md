# 教材检索重排与证据门槛改进

## 诊断证据

原实现中，RRF 召回分约为 0.02～0.05，小节标题的字符片段加分上限为 0.09，章节偏置还会再次增加部分候选的分数。开发问句“集合的交集与并集有什么区别？”的正确定义段落 `ch1-b169-0` 是向量召回第一名，却被相邻小节压到后面。“两个相交集合的元素总数怎样计算？”也召回了第三章包含排斥原理，但被第一章的章节偏置压制。诊断原始数据见 `artifacts/rag-stage-diagnostics-before.json`。

固定余弦相似度门槛还误拒了“从不同颜色袜子中抽取怎样保证有同色一对？”；“牛顿万有引力定律的公式是什么？”则越过该门槛，并引用教材中的牛顿二项式。这说明余弦相似度与片段是否支持回答不能画等号。

中文 `BAAI/bge-reranker-base` 在本机可运行，但直接替换原排序时，25 道开发题 Hit@2 从原来的 25/25 降到 20/25，Hit@3 为 24/25，两道教材外问题均返回空出处。候选集对 25 道题的目标小节覆盖为 25/25。教材中残缺的数学符号、短公式文本和图片邻近文字会使重排结果难以判断；这仍需进一步核验。模型下载后中位检索耗时约 5.9 秒。

## 实现

- 保留关键词和向量两路的候选，避免在重排之前只按人工加分裁剪。
- 启用重排时，把一般问题的证据门槛移到交叉编码器之后。逐段过滤低相关性证据，不把未经重排的尾部候选补回结果。
- 通过 RRF 融合原结构排序与模型排序；精确匹配的图号、表头保留独立的资源定位依据。
- 图号按完整编号匹配，`图7.2` 不再匹配 `图7.20`；不存在的编号不能获得精确资源的门槛豁免。
- 记录候选、原排序、重排分数、融合排序、门槛及模型失败原因。模型失败时恢复原排序和原证据门槛。

融合方案在已保存的开发集评分上 Hit@2 为 24/25，Hit@3 为 24/25，两道教材外题无出处。h20 的目标小节被找到，但表格未被选中，仍记为失败。这是开发结果，不是独立成绩。原始逐题记录见 `artifacts/rag-fusion-development-cached.json`。

## 验证与复现

16 项回归测试覆盖重排前误拒、低分证据过滤、未知图号、完整编号匹配、非法模型评分降级，以及原有图、表和教学入口检查。测试使用可控评分器验证边界；实际模型质量通过独立题集另行评估。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest tests.test_rag_upgrade -v
.\.venv\Scripts\python.exe -X utf8 -m scripts.eval_rag_holdout --cases tests/data/rag_blind_reranker_2026_10_10.json --output artifacts/rag-fusion-blind-reproduce.json --reranker BAAI/bge-reranker-base --trace
```

`RAG_RERANK_MIN_PROBABILITY=0.15` 表示 sigmoid 后的相关性分数门槛，该分数未经概率校准。当前数值来自开发阶段，独立评分后不继续调参。新题集包含 12 道教材内题、4 道教材外题，覆盖十章；SHA-256 为 `4da09bbc2bbe918ea7dd0d69a37c4618110d467918c512ec6aac3fe16b8666f8`。题目和标注由同一开发助手编写，属于未见题评估，不能替代独立人工评审。

指标仅验证章节、小节与指定资源类型，不代表最终回答准确率。证据门槛也不是事实核验器；教材提取残缺、图表解释和证明正确性仍需要单独验证。

## 新题集的首次评分

| 方法 | Hit@2 | Hit@3 | 教材外仍给出处 | 中位单题延迟 |
| --- | ---: | ---: | ---: | ---: |
| 旧关键词检索 | 6/12 | 7/12 | 4/4 | 17.6 ms |
| 原混合检索，未启用重排 | 9/12 | 9/12 | 0/4 | 157.6 ms |
| 融合排序与重排证据门槛 | 10/12 | 10/12 | 0/4 | 7,596.2 ms |
| 无向量索引加融合重排 | 9/12 | 10/12 | 0/4 | 4,659.4 ms |

含向量模式比原混合检索多命中一题，即 c04 的命题否定。原系统被问句中的“关系”引导到第九章，融合版找到第四章。c01 的有序对问题仍落在第九章序关系；c11 的 `A∧B` 真值问题找到逻辑相关内容，但没有命中标注的联结词小节，二者均记失败。无向量模式另有 c08 的树定义落在第三位。这些新失败未用于调整代码、阈值或标注。

两组重排评估曾同时运行，因此延迟包含 CPU 竞争，不能作为严格的性能基准；已确认本机重排会增加数秒检索耗时。此次全部重排调用正常，无模型失败降级。

逐题报告保存在 `artifacts/rag-fusion-blind-results.json`、`artifacts/rag-fusion-lexical-blind-results.json`。本机 `.env` 已启用 `BAAI/bge-reranker-base` 与 0.15 门槛；清空 `RAG_RERANK_MODEL` 后可恢复无模型重排的模式。示例配置仍将模型设为可选，避免新安装自动下载大模型。

这轮确认了阶段控制缺陷被修复，并取得有限的未见题提升。12 道正例和 4 道反例不足以证明总体召回可靠，后续应由独立人员补充问句与答案证据标注，重点评估换符号、应用题及残缺数学公式。

## 真实接口抽查

启用本机重排配置并启动服务后，首页与 `/health` 均返回 HTTP 200，`mock_mode=false`。使用独立临时测试账户调用真实 `/api/chat`：

- c16 动量守恒定律：返回未检索到相关教材依据，教材出处和图片引用均为空。
- c04 命题否定：正确解释原命题与否定命题真值相反，引用第四章 `4.1.2 逻辑联结词`，后续选择题 A/B/C/D 完整。接口质量检查通过。

完整回复见 `artifacts/reranker-api-ood-smoke.json` 和 `artifacts/reranker-api-in-scope-smoke.json`。两个抽查不代表总体回答正确率；测试账户随后清理，不影响真实用户记忆。
