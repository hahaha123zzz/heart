# 第四阶段：教学观察与可追溯规则反思

沿用已批准的六部分调研路线，按 brainstorming 梳理边界后在现有事件事务内扩展。

选择：本阶段先做确定性的观察/反思闭环；直接添加 LLM 总结会新增延迟和未经核验的推断，整体接入 LangMem 则需要迁移运行时。后台 LLM 任务队列留下一阶段。

## 约束

- 学生本轮作答评价上一轮实际教学动作，不能评价尚未发生的本轮动作。
- 每个已提交回合新增一条 strategy_observations，来源绑定 observation_event_id、teaching_event_id、当前原文证据 ID。无上一轮同知识点已提交教学、不独立、没有数值变化或变化不足阈值时 outcome=unknown，不作为失败。
- 工程观察分类：掌握估计上升至少 0.08 为 progress，下降至少 0.08 为 regression，否则 unknown。这不是教学因果效果或校准后的成功概率；提示后作答 conservatively unknown。
- 保存知识点、上一轮难度/提示级别、模型核验类别、理由和 policy_version。旧事件缺少策略元数据时 unknown；不伪造回填。
- 来源过滤学生/知识点。对同一学生、知识点、动作按难度/提示分组展示，默认至少三条已测量观察才形成微弱权重，且只采用与当前规划难度/提示相符的样本；未知不进分母。旧画像 EMA 保留数据，但正常决策不再直接使用没有来源的旧值。
- 固定规则反思只解释计数和未知原因，不编造跨轮规律；作为历史数据进入统一预算。
- 事务、幂等、质量拒绝、并发冲突、学生删除继承前阶段保护。近期教学动作改为从已提交事件恢复，避免重启丢失。

## 实施

新增表及独立 strategy_memory Repository mixin；MemoryManager 在短事务内创建观察，暴露统计/规划画像入口；Orchestrator 保存实际动作上下文，规划时读取有来源的画像；Router 在规则候选排序中采用弱权重。反思上下文与策略观察遵守现有 JSON 字符预算。

## 验证

内存 SQLite 和模拟代理覆盖上一轮归因、未知、重复提交、跨学生/知识点/难度/提示隔离、来源失效、重启恢复、事务回滚、删除级联、历史 EMA 不被继续更新以及普通教学接线。禁止真实 API/生产数据库操作。
