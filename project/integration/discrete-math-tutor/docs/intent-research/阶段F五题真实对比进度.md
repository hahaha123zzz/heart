# 阶段F：五题真实模型对比进度

日期：2026-10-12。

## 范围

冻结开发样例为 tests/data/intent/paired5.jsonl，来自已有 task12 的定义、先例子后证明、教材选区提示、小题提示、对象缺失五个场景。标签由 Agent 编写，待独立审核；不是盲测，不能用五题宣称发布达标。

本批只评任务识别，不评回答正确性、提示泄露、教材召回或引用质量。旧路由不消费新版对象上下文，后续对比体现整条识别路径的功能差异，不是同能力输入条件下的纯模型比较。

## 逐题发现

1. “什么是交集？”：旧流程字段全部匹配。
2. “先给一个例子，再解释定理7.7的证明”：旧路由认为需要上下文，标签为不需要。必须先明确 needs_context 表示依赖会话/冻结对象，还是包括教材检索；这一差异不能直接定性为模型错误。旧路由无法输出两项任务及执行顺序。
3. “这段选区只给一个提示，不要完整答案”：旧路由归为 statement，未识别为学习提问，且没有选区对象消费能力。
4. “当前小题只给提示，不要完整答案”：同样归为 statement，没有小题对象及提示约束字段。
5. “这个为什么成立？”：旧路由在理由中承认对象缺失，却输出 continue，未触发 clarify_task。这个样例的学习意图 proof/explain 标签也存在歧义，后续须独立审核，不通过修改标签刷分。

## 新版实测结果

首次尝试被自动审批拒绝，没有执行。用户随后明确回复“可以发”，授权将这5条开发样例发送到现有配置 https://api.deepseek.com；重试已完成。结果见[新路由真实报告](阶段F五题新路由real.json)。实际调用尝试5次，全部成功；本批新旧合计10次尝试，无需修复输出或重试。

|指标|旧路由|新路由|
|---|---|---|
|流程 intent 标签匹配|4/5|5/5|
|student_move 标签匹配|3/5|3/5|
|needs_context 标签匹配|2/5|5/5|
|必要澄清召回|0/1|1/1|
|无歧义题误澄清|0/4|0/4|
|学习任务及顺序匹配|无此字段|4/5|
|对象引用匹配|无此字段|5/5|
|回答约束匹配|无此字段|5/5|

|多意图顺序匹配|无此字段|1/1|
|识别延迟中位数|约1.12秒|约1.19秒|

两次使用相同样例、模型及路由/评测代码哈希，模型与网络仍存在波动。空对象/空约束也计入各自5题分母：明确对象绑定实际仅2题，提示约束实际仅2题，多意图顺序仅1题，不应将5/5解释为全面覆盖。

新版已正确绑定选区和小题，并识别 hint、hint_only、no_full_answer；“先例子后证明”保留 example、proof 的顺序及 example_before_proof；对象缺失输出 clarify_task 与 missing_slots=[target]。

## 剩余差异及执行核对

两条提示请求仍输出 student_move=statement，与预设 question 标签不一致。新版已独立识别 hint 任务，源码中 execution.align 在策略选择后应用明确任务。把这两条真实录制的任务字段送入执行适配层，均得到 give_hint，因此不能把 statement 标签差异等同于未识别提示需求；分类定义仍应在独立审核时明确。

“这个为什么成立？”的学习意图为 explain，标签为 proof。对象缺失已正确澄清，在对象确认之前无法确定用户要概念说明还是形式证明，暂记为标签不匹配并保留原标签，不能据此增加关键词硬规则或宣称该项已通过。

本批未修改识别 Prompt，也未改 Gold 标签，不为5题成绩调参。上述执行适配检查不代表最终生成的答案不会泄露；真实回答与完整HTTP教学链路仍须另验。
