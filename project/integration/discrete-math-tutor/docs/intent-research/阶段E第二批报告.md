# 阶段E第二批：小题聊天对象接线

日期：2026-10-12。

## 改动与使用方式

每个小题的“提示”“AI讲解”旁新增“针对本小题提问”。点击后先保存草稿，再在聊天输入框上方显示练习组、题号和小题标签，预填“只给提示”的问题。用户可以修改提问文字。

发送时传递 exercise_target 的 question_id、part_id、version，走已有任务识别、练习辅导、记忆和质检流程。前端不上传整份答案给聊天接口；后端按已确认小题读取服务端草稿。发送前若仍在同一题目版本，强制保存新修改的作答，避免650毫秒自动保存延迟导致读取旧答案。

切换小题不会自动修改聊天引用；再次点击入口才显式更换。替换引用先取消原待澄清任务；移除小题卡片后可重新提问。教材选区与练习对象互斥，用户聊天消息显示对象摘要。保存失败不绑定新对象，保存期间切换整题则丢弃迟到的准备结果。

补充旧任务时不传当前 reader_location、selection 或 exercise_target，交由服务端使用原已确认对象。这修复了用户选择澄清选项后，当前阅读位置可能再次覆盖所选对象的问题。网络重试保留原对象与原请求编号；422等参数错误显示“重新提问”，不按网络故障重复发送失效版本。

更新 app.js 和 practice.js 静态版本。没有改写原判分、提示层级、学习进度或数据库表。

## 验证与证据

扩展 tests/browser/task-clarification.cjs，加载实际 index.html、app.js、workspace.js、practice.js，用临时静态服务和浏览器 API 替身测试。本批浏览器保留前八组检查，新增两组实际练习入口检查，共十组通过：

- 选择小题前保存草稿；更改当前小题后聊天仍引用原小题；显式更换先取消旧任务；移除引用；发送前保存最新答案；请求只含一个明确对象。
- 草稿保存失败不绑定小题；再次保存成功后可以准备提问。

另在场景中断言：澄清选项请求不带当前阅读位置；422题目版本错误显示重新提问而非重试原请求。所有浏览器 pageerror 为空。本机 Edge，API为替身，未加载 PDF/MathLive 模块，未访问真实学生数据或调用模型。

后端 test_task_resource_execution 与 test_task_api 共17项通过，覆盖已有练习执行、当前小题草稿、无作答拒绝检查、澄清中止、质检拒绝、PDF约束与任务接口。输出见[阶段E第二批后端测试输出.txt](阶段E第二批后端测试输出.txt)。node --check 与 git diff --check 通过。

复现浏览器命令沿用[阶段E首批报告](阶段E首批报告.md)。技能运行器需要在技能目录创建临时文件；本批最终测试的一次自动审批因连接故障未完成、操作未执行，随后通过同一审批流程重试成功，没有绕过权限检查。

## 范围及下一步

本批完成小题聊天对象、对象摘要及显式更换/移除接线。版本失效时用户需重新加载题目后再次选择；未自动升级旧版本作答。

前端功能已可进入联合验收，但不能把替身测试视为真实模型效果。真实 PDF 选区、数学输入组件及前后端联合验收仍未完成，阶段E保持未勾选。接下来准备隔离验收环境和固定样例，补齐真实模型基线/效果评估，再实施阶段F的灰度开关与回滚验证。
