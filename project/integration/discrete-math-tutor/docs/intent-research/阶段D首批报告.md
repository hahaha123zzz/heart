# 阶段 D 首批：任务执行接线与回答约束

日期：2026-10-12。状态：普通教材、PDF选区、练习按钮及聊天小题辅导的执行接线完成。任务类型驱动的检索排序和真实模型效果仍待后续验证；阶段 D 总勾选保持未完成。

## 1. 本轮变化

新增 agents/task_execution.py，统一消费服务端校验后的 TaskUnderstanding。

- 仅提示：最终计划固定为 give_hint / progressive_hinting，旧的直接讲解、图片讲解或卡住策略不能覆盖。生成与质检同时收到 hint_only/no_full_answer；不因原问题含“完整证明”而启用完整证明提示词。
- 解释、例子、证明、总结、比较及练习：映射到现有合法教学动作；保留多意图顺序、example_before_proof、include_prerequisites，并要求质检核对这些要求。
- 保守指代检索：完整保留原消息、公式、定理号，再追加已校验对象的标题与有限摘要。背景小节不拼入整节正文；不采用模型自由改写。比较的两个对象同时传入检索与证据充足性检查。
- 生成/质检长度预算对齐：证明需求允许约 480 字生成预算、500 字规则上限，保留既有独立证明核验；仅提示仍采用短回复预算。给出证明预算不等于擅自把“解释这一步”扩展成完整证明请求。

原有 RAG 索引、混合召回、重排、证明单元扩展、前置定理引用及 PDF 定位路径继续复用。本轮没有重建教材索引或替换模型。

## 2. 三条路径

|入口|实现与边界|
|---|---|
|普通教材聊天|从 TaskContext 取当前会话历史和教材对象；任务动作优先于旧策略；将同一执行约束传给 ResponseGenerator 和 QualityChecker|
|PDF选区|保持当前原图与引用；使用同一提示/证明约束；需要另一个历史选区或多对象比较时返回 unsupported_task，避免实际解释当前图却声称解释了另一个对象|
|练习按钮|复用 TaskContextBuilder.button_task，按已验证的小题和按钮动作确定任务，不增加模型分类；仍使用 ai_parts 辅导|
|聊天中的 exercise_target|新增 agents/exercise_task_tutor.py；分类一次，澄清时不生成；只读当前学生、当前版本、指定小题的草稿；复用 ai_parts，不自行评分|

检查答案需要练习页已保存的该小题草稿，否则返回 answer_required。当前不将聊天文本随意解析成正式作答，也不把自然语言解释当作规则评分。

练习辅导新增任务质检，未通过只返回拒绝说明，不展示草稿或资源，也不记录为已获得提示。聊天得到的小题提示/讲解写入已有 ExerciseHelpRow，防止之后的作答被误算为独立作答；辅导本身不更新掌握度或推进学习步骤。按钮保存增加账户存在性与删除 epoch 检查，问答和辅导记录同事务保存。

## 3. 本轮修复的具体问题

1. 旧的解释策略会覆盖提示要求：任务约束在策略分支后再次落实，生成与质检共享最终计划。
2. PDF质量结果 passed=true 但 issues 非空时仍放行：先用测试复现，再统一为两者都通过才发布，失败不会保存草稿。
3. 比较指代只有检索知道对象、证据检查仍只看“这两个”：把相同的有来源对象补充同时交给证据检查及证据恢复。
4. “先举例再证明”被 260 字旧限制拒绝：统一任务预算，证明题按钮也从已校验题型启用证明预算与核验。
5. 聊天获得提示未纳入原练习辅导记录：复用现有记录表，不另建独立能力判断路径。
