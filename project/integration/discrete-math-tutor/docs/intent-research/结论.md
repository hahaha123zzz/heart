## 第1部分：总体判断与来源纠偏

### 本项目实际

agents/conversation_router.py 已有 5 类 student_move、5 类流程 intent、topic、confidence、needs_context。handle_turn 在教材检索前调用它；换话题置信度低或目标为空时使用固定澄清句。现有路由输入是当前点、学过的点、最近 4 条对话和最新消息，没有显式选区、题目和待澄清槽位。

因此原文“教材→Chunk→LLM”的现状描述过时。需要增强现有理解层，不能新建一套学生记忆或绕过已有教材证据门控。student_move、学习目标、回答需求、流程动作应分开；理解意图也不应推断或修改学生掌握度。

### 论文核验

[Uncertainty-Aware Clarification in LLM Agents with Information Gain](https://proceedings.mlr.press/v306/deng26l.html) 确实存在，核心包含训练澄清器与信息增益奖励，评估在工具任务环境。它不是“给 Prompt 加一句信息增益”就复现的无训练方法，也没有直接证明中文教材教学收益。当前页面未列作者代码链接，代码复用暂未证实；本项目先借鉴“问能区分候选任务的关键问题”的原则。

### 本段决策

升级现有 ConversationRouter 为结构化理解结果：任务对象、教学需求、缺失项、需要前文与需要澄清分别输出；先做单次模型调用和程序决策。所有短句不必澄清，“继续”可由当前任务解释；有唯一可靠选区时“这个”可解析。显式当前请求优先于画像和历史偏好。

GitHub CLI 在当前环境未登录，已改用公开只读 GitHub 接口及网页核验，无需登录或令牌。未读取仓库的 env 文件。

## 第2部分：状态、澄清循环和能力路由

### 原方案的适配

学习状态与画像已经由 MemoryManager、StudentState 和预算化 MemoryContext 提供，不新增 student_state/conversation_memory 平行表。原文的“代码执行环境”“实训页面”不是当前离散数学 Demo 已有能力，不进入首批路由。

[EduAgent workflow.py](https://github.com/Varsha-art126/EduAgent/blob/main/graphs/workflow.py) 用确定性条件边执行 Planner 的分类结果，适合借鉴“模型理解、程序决定允许路线”的边界；其现有五类 ChatIntent 也不证明十几类越多越好。建议独立字段表达 explain/proof/example/hint/check_answer/practice/summary/compare/continue 和原五类流程动作，避免兼容性破坏。

[Tutor-Agent main.py](https://github.com/ghdkim/tutor-agent/blob/main/main.py) 实际保存的是 current_agent；评估 Prompt 通过工具转交。这不是原文所示的完整 StudentState 数据库。其 graph.compile 未配置持久 checkpointer，不应误称已有可靠跨会话澄清状态。

### 澄清状态的最小需求

拟增加学生及会话隔离的 pending_task：原问句、候选任务、缺失槽位、对象引用、选项 ID、回合版本、轮次数、到期/取消状态。补充回复“第二个”“证明”应合并原任务，不能当作新教材问题检索。对象依据优先级：当前显式选择/题号 > 本轮明确实体 > 有效待澄清任务 > 最近有效任务；画像只影响解释方式。

[LangGraph interrupt 官方文档](https://docs.langchain.com/oss/python/langgraph/interrupts) 要求持久 checkpointer 和同一 thread_id；恢复会从节点开头重跑，需要幂等副作用。本项目可先用 SQLite 短事务状态机复用现有删除/版本保护，无须为澄清先重写全部编排。未来若确需长任务暂停，再评估集成官方组件。

### 决策

区分“缺上下文”“缺关键条件”“问题有多个对象”“模型输出无效”“教材证据不足”；它们不能共用一个 need_clarification 开关。一次询问最有影响的缺失项，给 2–3 个真正区分任务的选项及自由输入；设置有限澄清预算，取消或新明确任务到来立即结束旧 pending。此处为拟定方案，未实现。

## 第3部分：结构化对象理解与保守问句改写

### 核验到的项目缺口

main._run_turn 对 selection 单独进入 pdf_selection_tutor.explain_selection，跳过 ConversationRouter；普通消息进入 handle_turn。这意味着统一意图层必须兼容两入口，并在 resolve_selection 校验教材版本后理解选区，不可只升级普通聊天。

orchestrator._retrieval_query 当前主要是“当前知识点 + 原话”，或者直接保留原话，不具备指代恢复、澄清回复合并或来源可追溯的语义改写。LLMClient.chat_json 是提取 JSON + 重试，不是供应商强制 JSON Schema；现有 RoutingResult 的字符串字段和默认值会掩盖部分不合规输出。

### 可复用研究

[CANARD](https://github.com/aagohary/canard) 和 [QReCC 论文](https://aclanthology.org/2021.naacl-main.44/) 将上下文问题改成独立可检索问题，适合借鉴训练/评估任务定义；其英文开放域模型不能直接作为中文数学理解效果保证。

[ContextualSP incomplete_utterance_rewriting](https://github.com/microsoft/ContextualSP/tree/master/incomplete_utterance_rewriting) 是中文不完整话语改写的候选实现；当前公开目录接口与文件抓取尚未成功，未据此确认推理 API 或直接复用结论。应保留为待进一步核验项，不能把 README 当源码已读。

### 本段决策

拟定 TaskUnderstanding：original_query、dialogue_action、learning_intents（有序列表）、target_refs、context_required、missing_slots、ambiguity_kind、candidate_tasks、rewritten_query、rewrite_sources、schema_version。使用 Literal/Enum、有限数、字符串/列表长度和字段一致性验证；模型异常与合法 unknown 分开。

改写只补回有来源的对象与已有条件，保留图号/定理号/公式/页码。原文“关系闭包”改成“闭包与传递闭包的区别”可能增添用户未要求的比较任务，不应采用。比较问题保留两个对象，先原问句与保守改写双路检索并对照检索收益，继续复用现有证据门控。

三类字段不能混淆：问题复杂度、用户本轮解释需求、证据支持的技能状态。重复提问不能自动写成“某概念薄弱”；沿用此前记忆证据质量和误区确认规则。模块上可分接口，首版不意味着必须串行调用五个模型。

## 第4部分：Prompt 与评估，不采用自报概率固定阈值

[Clarify When Necessary 原论文](https://arxiv.org/html/2311.09469v1) 将是否澄清、问什么、如何利用回答拆开，且看固定交互预算下的任务收益。它适合设计评测，不应简化成“概率大于80%就答”。[Clarify-AI intent-sim.ts](https://github.com/sirutisb/clarify-ai/blob/main/lib/clarification/intent-sim.ts) 会生成问题、采样10份模拟答复、请求独立NLI服务并聚类；采样批次并行不消除模型生成和推理成本。首版在线流程不采用这一重链路。

### 可验证的当前问题

已对当前 Router._validate 做纯函数探查，无真实 API/数据库写入，结果在 [router-validation-probe.json](router-validation-probe.json)。空 JSON 变为 continue，非法 intent 被静默替换；NaN 的 confidence 被截成 1.0。需要明确 parse_error/unknown 和有限数校验，而不是默认当作正常继续。此处仅记录，尚未修代码。

### Prompt 和标注建议

采用中文离散数学对照样例：同一句“这个为什么”在无对象、单个选区、多个历史对象时应有不同结果。增加只要提示、先举例后证明、答完题说继续、情绪+有效数学问题、否定纠正、换章节、含错误前提的问句。声明对象必须对应输入提供的稳定 ID；参考资料及对话中指令不能改变路由能力白名单。解释程度可按显式请求推断，但不写成学生掌握证据。

首批建议100–150段多轮案例，不沿用1000条平均分配的泛领域模板。按完整会话及问题模板划分开发/盲测，防止同一对话相邻回合泄漏。由人工审核任务、对象和是否必须澄清；允许多意图与多个合理标注。

原文所谓 Clarification Rate 实际更接近澄清召回率。需同时报告必要澄清召回、无歧义误澄清率、任务对象准确率、流程动作宏F1、改写实体/公式保真、补充回复合并成功率、取消/过期处理、P50/P95延迟、调用数、成本。概率/熵只作为待校准排序信号，按澄清成本与任务损失在开发集选择策略，盲测不调阈值。

### 评估源码复用

已读 [QReCC evaluate_retrieval.py](https://github.com/apple-aiml-research/ml-qrecc/blob/main/utils/evaluate_retrieval.py)。Apache-2.0 可适配 MRR/Top-k 命中指标；原脚本通过答案跨度F1启发式判相关，不适合直接评数学证明。教材应人工标注页/单元/前置定理作为相关证据。数据的 CC BY-SA 许可与代码许可分开；英文数据仅作方法验证，不能充当本项目主验收集。

## 第5部分：后端示例不能直接粘贴，采用可恢复任务状态

### 原代码的问题

原文 IntentResult 未声明 need_rag，后面 router 却读取它；coding_agent 返回值没有在条件边字典注册。Rewrite 示例使用未绑定 llm，并在 async 方法里 await invoke。缺少 request/task ID、澄清回复关联、到期取消和失败状态，因此不是可直接执行的后端方案。

回答完问题直接 mastery_change +0.05 与当前项目证据驱动记忆机制冲突，必须删除该建议。学习事件可记录“请求解释”，掌握度仍按现有可靠证据更新。

### 实际可借鉴组件

[Rasa Forms 官方说明](https://legacy-docs-oss.rasa.com/docs/rasa/forms/) 与 [forms.py](https://github.com/RasaHQ/rasa/blob/main/rasa/core/actions/forms.py) 将 required_slots、槽位验证、请求下个槽位和退出条件分开，是适合澄清循环的工程结构。本段仅借鉴这些状态机原则，不引入完整 Rasa/NLU 训练和领域配置；源码许可需连同目标版本 LICENSE 一起核实后才可复制。

[Pydantic 数值类型](https://docs.pydantic.dev/latest/api/standard_library_types/#floats) 可直接复用有限浮点约束；本项目已有 Pydantic，无需为此替换 LLMClient。应把 JSON提取、Schema校验、字段一致性、允许路线决策分为不同步骤，供应商原生结构化输出仅作为支持时的优化。

### 拟定后端接线

_run_turn → ContextBuilder（校验选区/题号、取当前任务、有限相关记忆）→ 单次 TaskUnderstanding → 程序 ClarificationPolicy → 回答澄清或既有教材/选区/练习流程。需要澄清时保存 pending_task，返回 awaiting_clarification、task_id、question/options，不进入教材生成/测量记忆；用户回复后合并槽位、重新校验再执行。

复用现有同学生锁、短事务、事件幂等与删除 epoch；加入版本比较，模型调用在写事务之外，晚到输出若任务已取消/删除不得恢复。任务 state 对 student_id+session_id 绑定；当前主要按学生隔离，新增会话字段必须有兼容默认值和明确测试。

保留 FastAPI 与 SSE。流程状态通过阶段/完成事件展示，不公开模型内部推理。教材不足走既有 ContextSufficiency，不靠路由模型的 need_rag=false 跳过教材证据门控。LangGraph 若以后引入，优先复用官方存储/恢复组件，先证明不会破坏本项目删除及事务保证。

## 第6部分：任务理解与教学诊断分开，不重复建设诊断 Agent

### 对原结论的修正

原文“已解决80%问题”没有本项目测评数据支撑；“问过指针所以根源是不理解指针”也只是诊断假设。任务识别回答本轮用户要做什么，教学诊断回答有哪些证据支持某知识缺口，不能混为一个标签。

本项目已有 EvidenceExtractor、StateAnalyzer、TeachingPlanner 和教学策略白名单。源码确认：证据抽取与状态观测共用一次模型调用；StateAnalyzer 进行状态融合，TeachingPlanner 输出受程序策略约束的结构化计划。无需再平行创建原文的 Student Problem Diagnosis Agent。后续应检查新任务字段如何传入这些现有模块，并沿用来源引用及误区证据门控。

### 论文与源码核验

[MathDial 论文](https://aclanthology.org/2023.findings-emnlp.372/)研究教学对话，并区分学生完成任务与教师过早透露答案，适合借鉴教学评测维度。已读官方仓库的 [evaluate.py](https://github.com/eth-nlped/mathdial/blob/main/interactivetutoring/evaluate.py)、history.py 和 teachers.py。评估实现主要匹配数值答案，不能直接判断离散数学证明是否成立或提示是否泄露证明。history.py 是简单消息列表，没有本项目需要的澄清任务和取消恢复状态。

仓库 README 声明 CC BY-SA 4.0，未发现独立宽松代码 LICENSE；不能将其误报为 MIT。本轮采用教师动作标注及“完成效果/答案泄露”双指标的思路，不复制脚本或将英文小学数学数据作为中文教材验收集。

### 本段决策

TaskUnderstanding 增加显式回答约束，例如仅提示、不要答案、先例子后证明；将教学策略作为下游计划，不反推学生能力。复合输入“我很烦，解释这条定理”保留有效数学任务，情绪另作为观测。学生请求具体公式解释时先处理明确任务，有证据的前置缺口才触发短诊断或补课。技能观测来源、版本与未校准性质保留；不把少量规则题估计扩展成全章能力概率。验收增加仅提示违约率、错误前提识别和基于未证实缺口的错误转向率。


## 第7部分：以标注与离线优化为先，微调依据效果和成本决定

### 原资料的修正

Prompt v1/v2/v3 的70%、82%、90%只是原文示例，不是本项目实测结果。5000–10000条也不是通用微调门槛。把“初学者”直接作为每轮意图标签，会混入学生画像；Bloom认知目标可作为任务描述参考，不能据此推定学生已经达到某能力层级。“树”在离散数学图论章节已有明确上下文时，不宜机械澄清二叉树/B树。

原文 EduChat 指向 THUDM/ChatGLM-Edu，来源应纠正为 [ECNU-ICALK/EduChat](https://github.com/ECNU-ICALK/EduChat)。已读官方 README：教育对话/教学模型资源并不是中文教材任务识别金标准；代码、数据、模型条款分别审查，README 数据声明 CC BY-NC 4.0，且有研究用途限制文字，不能将全部资源视作可无条件复制。当前不引入其模型或大数据集。

### DSPy 源码复用判断

已核验 [MIPROv2 源码](https://github.com/stanfordnlp/dspy/blob/f1260ff14610286cb295c7d3a5ee2cbfd0ba5cb9/dspy/teleprompt/mipro_optimizer_v2.py)及 MIT LICENSE。compile 接收 trainset、valset 和搜索预算，使用 Evaluate 在验证集评估候选；可联合搜索指令及示例。源码在省略 valset 时按列表切分 trainset，不会自动保证会话/模板隔离，需要本项目显式提供划分。源码还估算候选搜索的模型调用量，不能把它当免费一次调用的优化。

后续可直接复用 DSPy 库作为离线实验工具，通过适配器调用现有模型，保留本项目在线 LLMClient。首轮先人工优化并建立基线；100–150段案例只用于初始诊断，正式结论同时报告样本数及不确定性。优化指标必须包含对象解析、必要/误澄清及结构校验，不能只奖励意图分类准确率。保留独立盲测，优化过程不得查看其标签。

### 反思与微调边界

[Reflexion 原论文](https://arxiv.org/abs/2303.11366)利用反馈形成文本反思，并不等同每轮自动纠正就一定正确。作者仓库已定位，但本轮核心源码读取超时，代码复用尚未核验。可借鉴离线失败分析；模型自评、学生“还是不懂”和历史偏好都不能直接成为意图金标准，尤其不能覆盖当前明确请求。首版不增加每轮在线 Reflection Agent。

积累人工审核的真实纠正、教材口语变体与多轮澄清案例，标记来源和审核状态；合成样本不与人工金标准混为一谈。分类、对象及回答限制分别标注，保留未知与可接受的多种解释。复用已有事件及删除机制，不新增无限留存的完整学生对话库。

有 GPU 可测试本地小模型，但选型需要实测现有检索模型占用、延迟和任务正确率，不能据此前信息默认某个7B模型可并行部署。Prompt/示例在盲测上仍有稳定错误且调用成本确有瓶颈，再做小模型/LoRA对照；微调、DPO是候选实验，不是必须逐级执行的路线。本轮未下载或运行模型。

## 汇总结论：本项目意图识别升级路线

建议保留 FastAPI、现有 RAG、LLMClient、MemoryManager 和教学规划，增强现有 ConversationRouter。首版优先统一普通问答、教材选区和练习任务的上下文，由一次结构化理解输出任务/对象/回答需求，程序执行澄清和能力白名单。

### 实施顺序与验收

1. **P0，修正校验与建立基线**：禁止 NaN/Inf、非法枚举和空输出静默变 continue，记录 unknown/parse_error；人工标注第一批案例，冻结一部分盲测。只测识别，先不用完整回答链。
2. **P1，统一任务上下文**：接入当前章节、选区/题号稳定 ID、上一题/当前步骤及有限相关记忆，保留原五类流程字段兼容。对象必须来自服务端校验的资源，不接受模型随意生成的 ID。
3. **P1，澄清状态**：pending_task 按学生/会话隔离，支持补充、纠正、换话题、取消、过期和版本比较；复用锁、短事务与删除 epoch。不得把澄清交互写成掌握证据。
4. **P2，保守改写与 RAG 接线**：保留原问句，改写仅补充有来源的指代，按任务对定义/证明/例子提供排序提示；不把章节猜测做排他硬过滤，不绕过证据门控。
5. **P2，Prompt/模型实验**：开发集优化后冻结配置，独立盲测；必要时 DSPy 或 GPU 小模型对照，改善不足再讨论微调。

关键验收：任务对象准确率、动作宏F1、必要澄清召回/误澄清率、补充回复恢复成功率、公式/实体保真、提示限制违约、跨会话隔离、删除/取消后的晚回调拒绝、检索命中变化及P50/P95延迟。初始指标先实测，再制定可接受阈值；当前没有升级后的效果或工期保证。
