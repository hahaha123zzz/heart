# 阶段F：灰度开关与回滚

日期：2026-10-12。本批实现及本地验收完成，阶段F整体尚未完成。

## 配置与依赖

新增 agents/intent_policy.py；在 API 的 TaskService 与任务恢复入口读取服务端配置。默认保持当前新版行为，不改用户实际 .env。

|配置|默认|作用|
|---|---|---|
|INTENT_ROLLOUT|all|all全部；test仅数据库测试账户；allowlist仅白名单；off回退旧字段|
|INTENT_STUDENT_ALLOWLIST|空|allowlist所需，逗号分隔学生ID|
|INTENT_CONTEXT_ENABLED|1|扩展对象/偏好上下文；关闭后同时停用扩展任务理解及持久澄清|
|INTENT_TASK_ENABLED|1|扩展任务Schema和Prompt；关闭回退严格旧路由|
|INTENT_CLARIFICATION_ENABLED|1|持久化多轮澄清；关闭仍可执行明确的新任务|
|INTENT_REWRITE_ENABLED|0|自由改写尚未实现，设置1会明确报配置错误|

灰度类别取数据库账户类别；既有账户保护会拒绝把正式账户以test身份使用。未知范围、非法布尔值、空allowlist及未实现的改写开关不静默启用，启动时检查配置。

扩展任务开关是服务端 TaskContext 内部字段，既不从 ChatRequest 接收，也不送入模型。独立 CLI/评测器继续按其显式路由选项运行，不受API灰度配置影响。

## 回滚行为

关闭新版或澄清后，在当前会话恢复/发问时惰性撤销 awaiting_clarification 任务：变为cancelled，revision递增，释放scope_key，清除原问题、对象上下文及路由资料，保留任务行、收据及task_disabled结果用于阻止复活。不删除表和学生数据，也不批量撤销其他会话。

旧task_id补充、关闭时发现旧pending的隐式补充返回task_disabled。恢复入口已撤销pending后，已知编号式选项短回复（“第一个”“2个”等）也被阻止，避免重试进入旧路由；不承诺理解所有任意自由文本的历史补充，用户应完整重新提问。再次开启不会复活已撤销任务；未访问的会话在关闭期间尚未惰性撤销，仍按既有30分钟TTL处理，不能把此机制称为全库即时失效。

仅关闭澄清时，识别出的信息缺失返回clarification_required并保存failed，不生成答案、不推进教学，也不产生pending。明确任务仍走新版理解。回退旧路由仍采用阶段A的严格有限数、枚举与异常检查；幂等、任务guard、删除epoch及资源版本检查保留。

前端恢复时展示失效提示，task_disabled时清除旧澄清交互并重新恢复；更新 app.js 缓存版本。

## 操作步骤

1. 灰度试用：在服务环境配置 INTENT_ROLLOUT=test；或使用 allowlist 加指定学生ID。重启服务并刷新页面。
2. 回滚：停止接收新请求，等待当前回合结束；设置 INTENT_ROLLOUT=off，重启服务并刷新页面。
3. 遇到待补充任务失效，完整重新提问。恢复新版设置原先范围，不复活已撤销任务。

配置从进程环境读取，修改 .env 后需要重启；不是在线热更新。等待在途请求完成是本次回滚的操作前提，本批未实现多进程在线配置广播。独立练习按钮、教材证据门控及资源读取保留；旧字段识别不具备新版多意图、对象指代和回答约束能力。

本批未修改实际 .env，未替换或重启8000日常服务，未写真实学生数据库，未调用外部模型。
