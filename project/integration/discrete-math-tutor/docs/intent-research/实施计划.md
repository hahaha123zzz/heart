# 意图识别升级实施计划 v1.0

日期：2026-10-11。状态：2026-10-12 已启动阶段A，首批20段离线回归完成。本文件依据 [分步调研结论](结论.md) 和当前源码编写；阶段验收表是计划，不代表功能已经完成。

## 1. 目标与范围

升级离散数学助教的 ConversationRouter，使它识别“用户当前要做什么、针对哪个教材/题目对象、需要什么形式的回答、是否缺少必须的信息”，并把结果接到既有教材、PDF选区和练习辅导流程。

首版完成：有限结构输出、任务上下文、澄清恢复、保守指代改写、回答约束、最小前端接线及可复现评测。保留现有 FastAPI、SQLite/SQLAlchemy、LLMClient、MemoryManager、RAG与教学规划。复用 Rasa 的槽位状态思路、EduAgent 的结构化结果与确定性分流思路；Pydantic 直接复用现有依赖。

首版不包含：整体界面改版、新建知识追踪系统、在线多 Agent 反思、引入完整 Rasa/LangGraph、模型微调、教材重建索引。DSPy 和 GPU 小模型留作后续有基线的对照实验。

### 方案选择

|方案|收益|代价与结论|
|---|---|---|
|只修改 Router Prompt|最快补少量问法|缺少对象与澄清状态，无法满足圈选/多轮需求|
|增强现有 Router，增加上下文和状态机|适配现有模块，能分阶段上线|需要接口与小规模存储变更；采用此方案|
|迁移完整 Agent/NLU 框架|可利用编排功能|迁移存储、删除保证和前端成本高；暂不采用|

## 3. 设计契约

### 3.1 输入上下文

新增 models/task_context.py（拟定文件）。由服务端 ContextBuilder 组装：

- student_id、session_id、request_id；学生身份继续沿用项目现有账户机制，本轮不将客户端student_id当新增认证方案。
- 原始消息、当前章节/小节、当前课程步骤、已验证选区、练习question/part/version、上一轮可指代对象。
- 同会话pending_task；少量相关记忆及其来源。明确请求优先于画像偏好。
- 有界历史与输入预算；只提供当前学生资料，不将全部记忆或教材拼入Prompt。

客户端传入的ID只是线索，服务端检查存在、版本及允许访问；模型只能引用已提供的候选对象。PDF内容、历史和记忆作为资料，不能决定能力白名单。

会话优先级：当前明确新目标/纠正→当前选区或题目→当前会话唯一对象→相关历史。多个合理对象且选择会改变回答时才澄清。

### 3.2 输出结果

新增 models/task_understanding.py（拟定文件），schema_version=1：

|字段|含义与限制|
|---|---|
|status|ok / unknown / parse_error / unavailable，模型异常与合法未知分开|
|dialogue_action|保留continue/switch_topic/new_goal/off_task/clarify_task兼容语义|
|student_move|保留现有五类，便于后续证据路径兼容|
|learning_intents|有序、去重的explain/proof/example/hint/check_answer/practice/summary/compare；最多3项|
|target_refs|从上下文候选ID引用，允许比较的两个对象；不接受生成的新资源ID|
|answer_constraints|仅提示、不透露答案、先举例后证明等有限枚举或明确顺序|
|context_required|是否需要已有上下文，不等同必须澄清|
|missing_slots、candidate_tasks|缺失项及少量候选解释，由程序策略判断是否可执行|
|rewritten_query、rewrite_sources|保守改写与其来源；没有来源时使用原消息|
|confidence|若保留，必须有限且在0到1之间；只是模型信号，不能独立授权切换或能力更新|

unknown不增加到旧intent枚举，使用独立status，兼容适配器仅在status=ok时输出合法旧结果。学生“懂了”不自动变成掌握证据。首版常规理解目标为一次模型调用；解析失败最多一次受限修复，与LLMClient已有重试合并预算，不能两层叠加无限重试。

### 3.3 澄清状态与响应

新增服务 task_service 与任务Repository，具体模块名见阶段表。状态：ready→awaiting_clarification→executing→completed；可进入cancelled/expired/failed。首次已明确任务可直接ready→executing。

pending保存原问题、已解析槽位、待补项、候选对象、schema/prompt版本、revision、delete_epoch和时间；按student_id+session_id查询。默认30分钟过期，最多2次澄清，均为可配置初始值。达到上限后提供明确选项或说明缺失信息，不猜测执行。

补充请求携带task_id与task_revision；不匹配、过期或已取消返回task_conflict/task_expired业务状态，不混入数学回答。首次升级前旧客户端缺session_id时映射独立legacy会话；新版每个浏览器标签用sessionStorage持有随机ID，退出学生账户时重置。仅保证新增任务和指代状态隔离，当前以学生为粒度的课程/知识状态不在本轮承诺完全会话化。

澄清响应保留现有answer字符串，并新增answer_status=awaiting_clarification、task_id、revision、clarification.question/options、理解摘要。SSE继续沿用现有progress/result事件，进度显示“确认问题”“等待补充”，不展示模型内部推理。HTTP与SSE均采用相同业务契约。

练习提示按钮已经明确action和part_id，服务端直接构造受校验任务；不为了统一接口强制增加一次分类调用。重新识别选区后的解释/证明等任务，但保持现有PDF解释及引用实现。

### 3.4 持久化及并发

使用SQLAlchemy新增LearningTaskRow及必要的唯一键/索引；兼容现有数据库初始化/迁移方式。添加会话任务上下文存储时只保存指代需要的ID及短摘要，不复制长期记忆库。

- request_id按学生/会话去重，重复请求返回既有状态/结果；不重复写学习证据。
- 状态更新带revision条件比较，防止晚回答覆盖新任务；当前学生锁保留。
- 模型调用在写事务外；执行前与写回前校验任务状态、对象版本与删除epoch。
- 账户删除、知识点遗忘与测试账户清理纳入新表清理；删除后晚回调不可重新建任务。
- 不持久化GPU/模型对象或整份图片到任务表；图片通过已验证资源引用。

## 5. 验收门槛

硬门槛：有限数/Schema、资源ID校验、跨学生/会话任务隔离、幂等、取消/删除后回调、过期版本拒绝的确定性测试100%通过；旧API可用；既有证据门控及引用路径保留。

建议开发集目标：任务对象准确率≥90%，必要澄清召回≥90%，无歧义误澄清率≤10%，明确对象的澄清恢复率≥95%；真实提示样例人工评审不得出现直接泄露完整答案。上述是发布候选门槛，不是现状成绩；盲测报告必须附每类分母，30段盲测只能给初步证据，发布前针对低样本类别补充独立案例。

已有动作宏F1与教材Hit@k/MRR不得有未解释的下降。公式/定理号精确保真样例应全部通过；数学等价转换若必要单独人工审核。性能在阶段A记录后，于阶段B开发集固定增量预算再进入盲测，避免凭空承诺秒数；常规路径不增加多模型串联，报告schema修复的重试调用。

质量检查按任务对齐：仅提示不泄露结论、比较保留两对象、含错前提不顺从、明确新请求不被旧偏好覆盖。质量失败时沿用已有拒绝/降级机制；不能只靠Prompt宣称已保证。

## 6. 回滚与发布边界

- 先关闭改写，再关闭新理解/澄清入口；保留阶段A的严格校验修复。各开关组合有明确兼容路径并测试。
- 回退时pending标记暂停/失效并提示用户重新提问，不能由旧Router把槽位短回复当独立任务。
- 迁移采用新增表/列；回滚保留新表而停用，不递归删除数据库。正式迁移前按项目备份方式创建可恢复快照。
- 旧账户清理与新表级联/epoch一起验证；测试数据库和真实学生数据库分离。
- 不在生产请求日志保存完整学生Prompt和教材图；默认记录版本、结构化诊断、耗时及错误类型。人工评测样例另行脱敏管理。
