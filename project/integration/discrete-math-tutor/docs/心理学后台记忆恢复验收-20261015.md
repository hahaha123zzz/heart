# 心理学后台记忆恢复验收

## 结论

现有持久队列和后台 worker 可以复用，无需新增记忆框架或修改生产逻辑。本轮新增跨进程回归，连同现有后台任务回归共21项通过；增强“崩溃任务”测试为真实领取后再令租约过期，单项复跑也通过，不将复跑相加计算。

## 验收方法

使用三个独立 Python 进程、临时心理学 SQLite 和合成学生，未读取真实学生数据，未调用外部 API。

1. 第一进程通过原 `commit_learning_turn` 创建三个学生的有效学习事件及后台任务。其中一项通过原领取接口进入 running，再将测试库的租约时间调到过去；另一项保持 queued；第三项通过原删除接口删除知识点记忆，然后进程退出。
2. 第二进程通过生产 `memory_lifespan` 启动真实后台线程，处理可恢复任务，随后退出 lifespan 并确认线程停止。
3. 第三进程读取持久结果，核对摘要、任务次数和学生原文；再运行一次 worker 确认无重复工作。

| 检查 | 结果 |
| --- | --- |
| 排队任务跨进程恢复 | completed，领取1次 |
| 领取后退出的任务恢复 | 租约过期后完成，累计领取2次 |
| 删除记忆后恢复 | 无旧任务、无派生记忆写回 |
| 原文与生成方式 | 摘录与合成学生原文一致，generation_mode=rule |
| 学生和知识点隔离 | 无关学生、其他知识点均读不到摘要 |
| 幂等性 | 两条有效任务仅产生两条摘要，再次运行无新增 |
| 服务生命周期 | worker 启动和停止均有效 |

## 范围

验证的是当前默认规则摘录模式，不是模型自由生成摘要、自动提取画像或证明学生已掌握知识。崩溃通过“领取任务后进程退出、测试库租约调到过去”模拟，未强杀正式服务或等待90秒租约自然过期。线程竞争、晚到 worker 拒绝、来源变更和失败重试由现有后台任务测试覆盖，未做多人负载测试。本轮没有变更正式服务代码或教材资料，也无需为测试重启正式服务。

教材替换和本轮代表性记忆验收已完成；下一步适合按甲方实际学习路径试用，优先修复具体章节、页码和对话反馈，不据此扩大为新一轮框架改造。
