# 自动图解与重点排版

## 平台调研与取舍

- [CopilotKit Generative UI](https://docs.copilotkit.ai/concepts/generative-ui-overview)：由 Agent 输出工具调用、状态或声明式组件规格，前端呈现相应界面。
- [assistant-ui Markdown text](https://www.assistant-ui.com/elements/markdown-text)：文本消息使用 Markdown 组件呈现，支持定制 `strong`、段落、代码等元素。
- [CopilotKit Markdown rendering](https://docs.showcase.copilotkit.ai/google-adk/custom-look-and-feel/markdown)：文本呈现和非文本组件分开处理，流式文本可使用专门的 Markdown 渲染器。

本项目沿用已存在的结构化图解生成、模板验证和组件生命周期。未引入 React 框架；借鉴上述平台的呈现分工，当前仅实现本次需要的短语加粗、高亮和行内代码，不宣称支持完整 Markdown。

## 实施

1. 自动选择器根据题目、已核验回答、教材判断图解需要，无需“可视化”“画图”等关键词，也不要求确认；问候、导航、简单事实、无合适模板不生成。提示与测验的答案保护继续生效。
2. 所有讲解提示词要求最多三处短语加粗、一处重点高亮，不整段强调。取消普通回答的“禁止 Markdown”规则和末端清洗时删除加粗标记的逻辑。
3. 普通问答、选区解释、练习讲解和恢复的历史讲解统一显示。`**短语**` 显示为 strong，`==短语==` 显示为 mark，行内代码保留；公式片段不进行强调解析。
4. 所有模型文本先转义，再由固定代码添加有限标签；不执行模型 HTML、链接或脚本。

## 验证

- 42 项相关 Python 测试通过，含不使用可视化关键词的自动选择和加粗保留。
- Node 检查强调、安全转义、公式和代码保护、未闭合标记。
- 浏览器验证真实 strong/mark 元素、处理记录展开状态、练习讲解历史恢复及桌面/移动布局。
- 真实 DeepSeek 输入“U={1,2,3,4}，A={1,2}，B={2,3}。A∩B是什么，为什么？”自动选择 sets 并通过内容核验；未发送学生历史。该测试覆盖图解生成链路，未重复完整检索与回答流程。

## 边界

图解仍须满足现有模板范围与核验，不是每条回答都出图。旧回答没有强调标记时保持原样；新回答由模型选择重点。未实现完整 Markdown 标题、列表或任意 HTML。
