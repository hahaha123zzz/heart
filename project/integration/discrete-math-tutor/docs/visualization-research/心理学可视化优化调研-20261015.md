# 心理学教材对话可视化优化调研

日期：2026-10-15。阶段：调研，不修改产品代码。目标：围绕唯一正式教材《实验心理学（第3版）》，重点概念与实验预制，低频问题通过受控模板和 Skill 按需生成；保持自动出现、低操作负担。

## 一、教材与当前项目核对

### 1. 核对范围与依据

读取正式教材 `manifest.json` 的11章37节目录，检查各章 `document.json` 中的概念和实验片段，并核对现有 `visualization/templates.py`、`on_demand.py`、`skills/experimental-design/SKILL.md` 和前端分步渲染器。尚未逐页人工复核全部原图。

### 2. 与离散数学教材的差异

| 角度 | 原离散数学可视化 | 当前心理学教材更需要的表达 |
| --- | --- | --- |
| 对象 | 集合、关系、图、真值、公式 | 刺激、被试、条件、操作、心理过程、测量指标 |
| 讲解主线 | 结构和规则逐步计算 | 问题与假设→操纵/控制→呈现与测量→证据解释 |
| 时间 | 主要表示推理顺序 | 时间间隔、刺激次序、线索与目标、重复试次本身就是研究对象 |
| 结果 | 确定性规则可由代码验证 | 数据有变异，需分清教材数据、模拟数据、学生体验数据 |
| 对照 | 对象之间的关系 | 条件之间的差别、个体差异、练习/疲劳/顺序效应 |
| 可得结论 | 前提成立时推导结论 | 相关不等于因果，实验条件与指标决定解释边界 |
| 交互 | 曾提供自由选边、改参数等 | 默认由系统编排，只点下一步；需要时才提供短体验 |

因此不宜把所有内容继续转成节点箭头图。心理学可视化的核心应是“看懂实验如何产生证据”，而不只是记住概念名称。

### 3. 当前已经具备与实际缺口

- 已有三种心理学模板：`variable_map`、`experiment_flow`、`design_matrix`。已有自动选择、结构校验、教材出处绑定、图解事实核验、下一步高亮、历史保存与失败回退。
- `variable_map`和`experiment_flow`实际都走通用节点/边渲染；`design_matrix`逐步高亮行列。它们适合变量、分组和程序，但没有专门的刺激时间轴、阶段数据曲线、信号分布/判准、阅读窗口等表达。
- 按需生成最多选择两种模板、共享40秒预算，包含选择、生成和核验，最多修订一次；候选失败可能只展示文本。预制能减少这类重复生成与失败，但不能直接绕过教材身份和适用条件核验。
- 当前缓存键包含学生和当轮上下文，不是按教材知识点组织的全书预制资产库。
- 当前 Skill 已明确不自由生成HTML/JavaScript、不捏造样本或显著性、学生仅点击下一步。后续应保留这些约束。

## 二、外部源码调研

已对六个公开项目读取指定提交的源码与许可证。快照在 `psychology-source-audit-20261015/`；`sources.json`保存仓库、提交、文件路径和原链接。没有运行这些外部项目，也没有验证它们在本项目的实际兼容性。GitHub CLI初次受配置文件读取权限限制，获准以只读方式访问公开仓库后完成核实。

### 1. DeepTutor：可视化类型目录与分离的渲染协议

- 仓库：[HKUDS/DeepTutor](https://github.com/HKUDS/DeepTutor)，核查提交`6cf793bd868ba5ecbe64722936d4be8fab5a01df`，Apache-2.0。
- 核读：`deeptutor/visualizers/{README.md,protocol.py,tool.py}`、`agents/visualize/prompts/en/analysis_agent.yaml`、前端`VisualizationViewer.tsx`。
- 实现：类型清单说明适用任务、载荷schema和渲染入口；提交工具是经过验证后进入画布的入口。原生组件和可选组件共享版本化协议。另有分析路线按“解释机制、比较数量、展示步骤”等任务选择SVG、图表、Mermaid或HTML，而非只根据学科词选图。
- 对我们最有价值：每种心理学可视化明确“教什么、何时用、输入什么、不能表达什么”；实验时间轴与信号检测有自己的数据协议，不再都塞进流程图。
- 复用判断：优先借鉴manifest、schema和统一提交口，沿用我们现有`CATALOG`、`VisualPlan`及来源核验。其工具依赖`UnifiedContext`和整套Agent协议，不能原样替换我们的生成入口。静态图够用时不启动额外生成；本书原图可局部高亮。
- 注意：它的可视化包协议允许受限前端渲染代码，不等于允许AI生成代码直接进入我们的主页面。

### 2. OpenMAIC：先安排教学场景，再承载可交互内容

- 仓库：[THU-MAIC/OpenMAIC](https://github.com/THU-MAIC/OpenMAIC)，提交`ecb940c136cc5b4ea56dc81b2505e64eff1dea29`，MIT。
- 核读：`lib/prompts/templates/interactive-outlines/{system,user}.md`、`components/scene-renderers/{interactive-renderer,InteractiveIframeHost}.tsx`。
- 展示角度：讲解、图示、模拟场景承担不同教学任务；规划时先明确widget类型和内容。渲染器把实际iframe交给稳定宿主，重挂载时尽量保留场景状态，并检查消息来源与组件状态。
- 可借鉴：把一个实验拆成有目标的场景；图文与当前步骤同步；离开卡片再回来可恢复同一步。第一屏有内容，图形不能只换说明文字。
- 不照搬：当前interactive-outlines/user提示词包含70%交互场景、至少两项simulation、至少一项game等配额，还鼓励玩家控制。这不适合本项目用户已经明确的“下一步即可”。不能因为项目做得丰富就复制其交互密度。
- 复用判断：MIT允许在保留声明条件下改编代码；但组件依赖React、Zustand及其课堂状态结构，我们现有卡片主体在原生JS中。先借鉴生命周期、恢复状态与场景分解，暂不引入整套课堂前端。

### 3. jsPsych：心理实验的刺激—响应—反馈—汇总

- 仓库：[jspsych/jsPsych](https://github.com/jspsych/jsPsych)，提交前缀`5887b4a50f`（完整值见sources.json），MIT。
- 核读：`packages/plugin-html-keyboard-response/src/index.ts`、`examples/demo-flanker.html`、`docs/overview/timing-accuracy.md`、`license.txt`。
- 实现：timeline组织试次，插件处理刺激呈现、允许按键、记录响应和反应时，并在结束时清除监听；Flanker示例按一致/不一致条件保存数据，最后分别汇总正确率与反应时。插件的模拟数据接口是测试能力，不是被试真实数据。
- 可借鉴的可视化角度：先让学生看懂一个trial，再理解为什么要比较两种条件，最后看指标如何被计算。这比单独画“注意→反应”更贴近教材。
- 复用判断：如果后续确实加入按键微体验，优先按包依赖复用所需插件和运行时，不从零写计时器、按键收集或随机试次。第一期被动分步讲解不必先引入整个实验运行时。
- 限制：[官方timing说明](https://www.jspsych.org/latest/overview/timing-accuracy/)明确讨论浏览器显示与响应误差。课堂短体验不证明本人的心理特征，不保证复现统计效应；不能把少量试次当正式实验结论。涉及精确阈限或刺激起始异步时间的任务应单独验证设备与时序。

### 4. lab.js：用Sequence和Loop复用实验程序

- 仓库：[FelixHenninger/lab.js](https://github.com/FelixHenninger/lab.js)，提交`b8206ad7e558476a7222adc91c0bc184329832d9`。
- 核读：`packages/library/src/flow/{sequence,loop}.ts`、`tasks/Stroop (code-based)/experiment.js`、根`license.md`及library、builder各自license。
- 实现：Sequence顺序执行组件，Loop在不同条件下重复组件；Stroop示例复用“注视点→刺激/响应→反馈”的trial模板，再分练习与正式阶段。
- 可借鉴：同一个实验拆成固定阶段，内容可换但控制流可复用；程序顺序与实验条件不是同一个维度。
- 复用判断：运行库是Apache-2.0；图形builder是AGPL-3.0。若采用其代码，要按实际文件所属部分保留声明并核对义务。当前项目不需要新的实验编辑器，优先借鉴阶段编排；如果选择jsPsych做体验，就不再同时接一套lab.js运行时。

### 5. CopilotKit OpenIntelligentUI：回答中自动选择文本、原生组件或自定义UI

- `CopilotKit/OpenGenerativeUI`现已重定向到[CopilotKit/OpenIntelligentUI](https://github.com/CopilotKit/OpenIntelligentUI)，本轮解析到提交前缀`8391a94c1c`，MIT；不能继续把旧仓库名称当独立项目。
- 核读：`docs/architecture.md`与`apps/app/src/lib/sandbox/sandbox-functions.ts`。
- 实现：工具/Skill决定回答形式，支持原生组件或隔离生成UI；宿主只暴露受校验的消息和链接桥接。架构文档明确：UI本地控件状态不会自动同步给Agent，后续提问必须明确传入相关状态；进程内checkpoint不等于持久存储。
- 可借鉴：组件内部的当前步骤、选中条件与数据来源应成为可追溯上下文；追问“这一步为什么”必须明确引用卡片ID、版本和step_id。
- 复用判断：参考桥接校验和Skill组织方式。现有FastAPI和原生前端无需为此改成Next.js/CopilotKit，也不建议为了低频例子默认开放自由HTML/JS生成。

### 6. A2UI：AI返回受约束的组件描述，客户端负责画出来

- `google/A2UI`已重定向到[a2ui-project/a2ui](https://github.com/a2ui-project/a2ui)，提交前缀`1657e70119`，Apache-2.0。
- 核读：`README.md`、`catalogs/basic/v1/basic_catalog_implementation_guide.md`、`LICENSE`。
- 可借鉴：组件目录、数据与显示分离、只接受客户端支持的类型。我们可以采用同类原则，让AI仅输出`renderer + payload + steps + source_refs`。
- 复用判断：本项目已有较小的schema与渲染入口，当前更适合借鉴协议设计，无需直接接入完整A2UI标准。通用按钮、文本组件并不会自动提供心理实验教学模型，专业渲染器仍需设计。

### 7. 工程研究佐证与边界

- [jsPsych论文（JOSS，2023）](https://joss.theoj.org/papers/10.21105/joss.05351)：支持模块化实验插件与可复用实验代码这一工程路线，不证明我们的教学效果。
- [lab.js论文（Behavior Research Methods，2022）](https://doi.org/10.3758/s13428-019-01283-5)：说明浏览器实验与组件化构建方法。本文没有据其直接宣称所有浏览器测量均达到实验室标准。
- 本轮未找到可直接导入、已对齐本书11章且符合“低操作、自动出现、教材引用”的完整开源资产库。结论不是没有此类系统，而是本次核查的六个项目不能直接提供这种成品。

### 本部分结论

借鉴学习Agent的“选形式与编排场景”，借鉴实验工具的“刺激/条件/测量组件”，复用我们自己的“教材引用、核验与聊天卡片”。不为展示丰富而增加学生操作，也不重建项目。具体采用外部代码前，固定版本、保留许可证与版权声明，单独验证依赖兼容性。

## 三、路线比较与推荐

| 路线 | 优点 | 实际代价 | 判断 |
| --- | --- | --- | --- |
| 全部临时生成 | 问法和题材灵活 | 延迟、内容核验失败、同一实验反复生成；难保证每步画面变化 | 不适合作为唯一方式 |
| 全部预制 | 版式、事实和翻步稳定 | 容易变成固定课件库，不能直接回答任意学生题目，维护成本随变体增加 | 不逐题穷举 |
| 预制重点主题包＋受控按需生成 | 核心体验稳定，长尾仍可覆盖；沿用现有框架 | 需明确资产匹配、适用条件、来源和回退 | 推荐 |

### 推荐结构

```text
已核验回答＋当前教材锚点＋本轮教学目标
             ↓
       判断图示是否有教学价值
             ↓
  匹配已审核的预制主题包及适用条件
       ↙ 命中                 ↘ 未命中
  固定画面/条件，个性化短讲解    读取相关Skill＋选择受控渲染器
       ↓                       ↓
  校验版本/题目适配         AI输出参数和步骤→结构/来源/事实核验
       ↘                       ↙
        原聊天中的分步卡片，逐步高亮
          ↓失败或不适配
       保留正常回答和教材引用
```

预制内容不用每次重画，不代表任意提到术语都触发；学生只问定义且文本足够时可以不出卡片。学生要求提示、检查答案或正在测评时继续遵守当前意图约束，不直接展开完整解法。

### 什么应该预制

预制的是一个完整教学主题包，不只是一段system prompt或一张截图：

- 教材概念/实验身份、适用问法、前置知识、不能覆盖的情况。
- 经过核验的条件、材料、实验操作、解释边界和常见误解。
- 4—6个左右可回放画面状态；每步有明确“发生了什么变化”，必要时可更短，不能凑步骤。
- 教材版本、章节/块身份、PDF选区、原图或表格资源；教材数据和辅助示例分别标记。
- 渲染器及资产版本、允许的有限变体、验证样例。

AI可以调整文字长短、连接学生刚问的问题；教材数值、实验条件、曲线性质和结论不能为了个性化任意修改。若学生给出的条件与预制案例不同，应明确这是教材对照案例，或走生成模板，不能暗中替换学生题目。

### 高频如何判断

本轮没有读取真实学生聊天作为调研资料，也没有可用的匿名主题频次报告，因此无法证明某个实验已是项目高频。初始按教材学习重点、难理解程度、跨章复用、视觉收益和开发验证成本排序，再请甲方确认；上线后用最少量的主题调用计数、失败率与人工反馈调整，不为收集频次额外存储学生原文。

## 四、建议优先建设的12个主题包

“主题包”可以包含多个相关场景，不等于已经完成12项，也不要求一口气全部制作。

| 编号 | 主题包与教材位置 | 学生实际看到什么 | 主要难点/风险 |
| --- | --- | --- | --- |
| P01 | 变量角色与混淆，第2章第2—5节 | 并排展示两个实验版本，逐步标出操纵、测量、保持不变和一起变化的条件 | 不把相关线画成已证实因果 |
| P02 | 被试间/内/混合设计，第4章第1节、第5章第1、5节 | 同一组人物标签在不同实验条件中分配/重复出现，用泳道和矩阵说明每人接受哪些条件 | 人物图标只代表角色；未知人数不得伪装成真实样本 |
| P03 | 完全随机与随机区组，第4章第2节 | 先按已有属性组成区组，再在区组内对照处理，用连线与矩阵同步高亮 | 分组、匹配、随机分配不是同一件事 |
| P04 | ABBA与拉丁方，第5章第4节 | 条件卡沿时间轴排列，每步突出位置与累计趋势，给出未平衡/平衡对照 | 不能宣称所有顺序影响均被消除；按教材适用条件解释 |
| P05 | 主效应与交互作用，第4章第3节 | 2×2条件表与两条均值线联动，对照“改变因素A的效果是否随B变化” | 线相交不是交互作用的必要条件；示意曲线不声称显著 |
| P06 | A-B-A单被试设计，第6章第2—3节 | 时间序列逐步展开，基线、处理、撤去处理的阶段带同步点亮 | 不把三个阶段变化本身当作对所有情况的充分因果证明 |
| P07 | 三种阈限测量法，第7章第1节 | 同一尺度下展示递增/递减、被试调整、预设刺激随机序列，再说明判断如何得到阈限估计 | 三种方法不能共用一个假想流程；慢速演示不是真实时序 |
| P08 | 信号检测与ROC，第7章第3节 | 噪声/信号分布、判断标准、四格结果和ROC点分步联动 | 固定分布下改变判准与改变感受性应分开；不任意捏造实验统计 |
| P09 | 减数法与相加因素法，第8章第1、3节 | 两种任务的加工阶段条带对齐，突出增加阶段、测得时间差及推断前提 | 反应时差不自动等于孤立心理阶段，解释必要假设 |
| P10 | 空间线索、Stroop与负启动，第9章第2节 | 分别预制注视点—线索—目标、字义与颜色冲突、前一试次与后一试次的对照 | 这三种是同包内不同范式，不混画为同一个实验；注意第9章block77、120、135起的原文 |
| P11 | 斯伯林部分报告，第10章第1节 | 字母矩阵出现/消失，提示行突出，比较报告方式如何区分看见与报告 | 机制慢放须标明；声音提示可用文字/视觉辅助手段，但不能声称完全等价复现实验 |
| P12 | 阅读移动窗口与边界范式，第11章第2—3节 | 预设注视点移动时遮罩变化，边界前后预视内容切换，两种范式分别讲解 | 注视轨迹是演示，不读取或推断真实眼动 |

### 首轮只做6个成品主题包

建议先选P01、P02、P04、P05、P08、P10。理由：覆盖基础概念、设计差异、顺序控制、结果解释，以及两个有明显心理学特色的范式；也能验证“矩阵/泳道、曲线、刺激舞台”等不同表达。P07等紧接第二批推进，不是被认定不重要。甲方如更重视心理物理学，第一个专题批次可用P07替换P10。

开发顺序先让P01/P02复用现有模板，再以P08/P10验证新增渲染能力，最后整合P04/P05；不先扩充几十种模板再发现没人使用。

## 五、特色最终效果与低负担交互

### 1. 信号检测：每一步真的改变画面

1. 先认识两种刺激状态，显示分布及坐标含义；无原书数值时标注理论示意。
2. 出现判准线，把“回答有信号”的区域和判断规则标清。
3. 同步点亮命中、漏报、虚报、正确拒绝四格和对应区域。
4. 在固定分布下自动切换预设判准，区域和四格映射随之变化。
5. 用同一组理论条件显示ROC点的位置；明确这种变化不是感受性改变。
6. 展示另一组预先审核的分离程度，比较判准变化与感受性变化；以教材允许的假设为限。

学生默认只点下一步，不拖阈值线、不填写概率，不要求自己配置分布。解释与高亮对象一一对应，避免图一直不动。

### 2. 空间线索：把“先后与位置”画出来

注视点→线索在一侧出现→目标出现在线索化位置→重放非线索化位置→并排对照条件与因变量。画面中的位置、边框和时间轴同步变化。教材给定的时间标作实验条件；为了看懂而放慢的播放明确标成示意，不把慢放时间记录为反应时。短体验如后续加入，使用固定条件，不提供参数面板。

### 3. 阅读窗口：理解测量方法，而不是伪装眼动仪

先展示正常句子，再出现固定注视点，随后高亮随注视点移动的窗口；下一场景切到边界前后的预视替换。预设轨迹与遮罩让学生理解“哪些信息可见、何时变化”，不启用摄像头，不把鼠标位置当真实眼动。

### 4. 交互统一约束

- 卡片自动出现在相关回答内，输入框上方不增加预制功能按钮。
- 默认只保留上一步/下一步和教材出处；首次进入就能看见主要对象与当前学习目标。
- 每步必须改变至少一种有教学意义的视觉状态：焦点、遮罩、刺激、条件、曲线区域、阶段带或数据对应关系。纯换文字不能算合格分步卡。
- 暂不把“改参数、自由拖拽、图形编辑、游戏闯关”当默认操作。课堂实验如需真实按键，单独提供“开始短体验”，这是记录体验的开始，不是确认是否显示可视化。
- 核心是自动匹配与预设步骤；不静默采集按键体验，也不自动把体验结果写成学生能力画像。
- 高亮不只靠颜色：结合边框、标签、形状或下划线；支持键盘操作、减少动态效果，保留可读文字摘要。音频范式需要等价教学说明，不能默认为所有学生可听清。
- 对每个范式保持一个主要讲解画面；文字与图相邻，收起后台处理记录，避免长对话中堆满多张并行图。

## 六、按需生成与Skill如何落在现有项目

### 1. 渲染能力按需要补，不按章节重复造

先复用现有图/矩阵，新增能力分批验证：

- `trial_timeline`：注视、线索、刺激、响应、反馈、间隔；同一舞台切换状态。
- `stage_series`：A-B-A等阶段带与时间序列。
- `condition_plot`：条件矩阵与均值/曲线联动，示意与真实数据显式区分。
- `signal_detection`：分布、判准、四格和ROC的专用约束。
- `reading_window`：文本、遮罩、预设注视点与边界切换。

这些是候选能力，不等于立即新增五个库。当前前端主要依赖Cytoscape，没有已接入的Chart.js/D3；少量形状和遮罩优先SVG/CSS，曲线能力确有需要再决定是否增加图表库。真实短试次体验优先复用jsPsych所需模块，避免同时引入jsPsych和lab.js。

### 2. Skill管理教学约束，不承担绘图引擎

沿用`experimental-design`，按需求增加psychophysics、attention-trials、memory-paradigms、reading-paradigms等知识包。每个包包含适用问题、教材概念、允许的renderers、参数schema、正确/错误示例、证据要求及禁止推断。Skill不是下载即正确的实验，也不是LLM可自由执行脚本的许可。

长尾问题由AI选择知识包并填写结构化参数和步骤；服务器计算确定性结果、校验来源和范围，可信前端渲染。实验原图、教材表格、必要公式可复用，避免AI重新画错。若需要超出受控协议的新表现形式，先返回文本/原图并记录缺口，另行审核增加渲染器，不默认自由执行代码。

### 3. 预制匹配与失效规则

- 键以`course_id + concept/experiment_id + textbook_version + asset_version`为主，不以几个关键词作为唯一依据。
- 用章节、明确实验对象、当前问题/意图和题目条件共同确认；提到“记忆”不能调用Agent记忆示意替代心理学记忆实验。
- 资产需要自己的稳定教材锚点；预制包缺失的段落可定向补取，不能只依赖本轮原有五条生成材料。
- 引用版本不匹配、证据缺失或题目不适配时不显示旧资产；不能把缓存中的旧卡片当新教材内容。
- 保存卡片ID、渲染/资产版本、当前步骤及讲解引用。下一轮追问明确绑定这些字段，不指望前端局部状态自动进入模型。
- 完整审定过的资产可在匹配与引用校验通过后复用，不再每次重新审整份画面；AI改动实验条件/数据的变体仍需重新核验。

## 七、建议落地顺序和验收要求

### 建议顺序

1. 与甲方确认首批6个主题包，逐个绑定正文、原图/表与生成PDF位置，做静态分镜草稿。
2. 实现最小预制包读取和匹配，复用已有来源核验、历史保存和卡片入口；先完成变量与设计对照。
3. 增补信号检测及刺激时序的表现，验证真实画面变化，再完成首批其他主题。
4. 给同一套渲染器配Skill和长尾参数生成，最后决定是否加入可选jsPsych短体验。
5. 用代表性问法、错误命中和教材更新进行验收，再扩展第二批主题包。各批依据结果调整，不按章节机械铺满。

### 关键验收

| 检查 | 通过标准 |
| --- | --- |
| 自动出现 | 无需用户输入“画图”或点预制按钮；相关讲解能匹配，简单事实和无关问题不过度展示 |
| 真正分步 | 每步有明确视觉变化，上一/下一步可逆，切页/缩放后不丢对象 |
| 条件一致 | 不把教材原例冒充学生题目；被试/水平/顺序与正文一致 |
| 心理学正确性 | 区分相关与因果、判准与感受性、主效应与交互作用、体验与实验结论 |
| 证据 | 每包能回到正确教材版本、章节和高亮区域；示意数据清楚标注 |
| 恢复 | 历史回放与追问仍指向同一资产/步骤；教材更新后旧版本不冒充新版本 |
| 失败 | 预制未命中可受控生成，生成失败仍保留正常文本和教材引用 |
| 教学收益 | 简短试用后学生能回答“操纵什么、测什么、比较谁、说明什么”，不只评价好看 |

预制命中应单独测量选择、加载和绘制耗时，与现有实时生成延迟对比；本轮没有性能基准，不承诺固定秒数或成功率。

## 八、本轮最终建议

认可“重要/高频预制、低频模板/Skill生成”的方向，但建议预制可追溯的实验教学主题包，复用专业表现能力，由AI按当前教学目标编排。第一轮做6个完成度高的主题，比先制作全书所有图更容易验证效果。保留原项目、原问答链路和低操作界面；把新增投入集中在教材的实验条件、时序、测量与证据解释上。

本轮完成教材结构与代表性原文核查、六个项目指定源码核验和方案比较。尚未制作卡片、运行外部项目、做浏览器视觉验收或证明教学效果。下一步是首批主题与分镜设计确认，不自动开始全书预制或重建前端。
