# 欧拉回路真实问答故障修复

日期：2026-10-12。

## 原题与症状

用户提供四顶点环的完整边集，要求结合教材解释为什么有欧拉回路并引用定理。
第一次 112 秒后质量拒绝，第二次 15 秒后证据拒绝且界面误显示“已完成”。

## 证据与根因

1. 实际检索已召回定理 7.11，并通过 GPU reranker 的相关性门槛，但同小节去重与两个片段的配额把它排除。入选的是定理 7.12 和路径定义，不足以支持回路判定。仅增加欧拉回路与欧拉图的术语关联不能解决这个筛选问题。
2. 真实失败任务将实例解释标成 explain + proof，主质量器扩大成一般定理证明任务。第一次的独立 proof audit 实际通过，主质量器仍拒绝实例应用。
3. 证据拒绝分支缺少 answer_status，前端默认显示完成。
4. 修复后真实复测发现定理 7.11 后的 [1] 错指向定理 7.12，需继续核对引用编号，不能只以模型质量检查 passed 作为引用正确的依据。

## 修复

- 建立欧拉回路与欧拉图的检索术语关联，不将欧拉路径混为同一概念。
- 对已通过门槛、属于明确概念小节的结构化定义/定理保留优先级，允许同小节的不同单元共同入选；显式定理编号仍优先，不放回已拒绝片段。
- Router、任务执行指令和质量器区分应用定理解释实例与证明一般定理；保留数学质检和证明审核。
- 证据拒绝显式返回 evidence_rejected 和 step_advanced=false，界面显示“处理未完成”。
- 生成提示明确摘录序号；增加编号单元紧邻引用的确定性检查。错配进入原有修订流程，不静默改写教材或强行放行。
- 更新 app.js 缓存版本。

## 验收

- 41 项 unittest 全部通过，覆盖检索选择、显式编号优先、缺失证据停止、任务执行、质量拒绝以及新增引用检查。
- 浏览器实际 app.js 与 SSE 替身回归通过：证据拒绝显示处理未完成，既有消息组件、焦点、折叠状态与滚动行为保持。
- 使用配置中的真实 DeepSeek 模型、GPU reranker 和隔离 SQLite 调用同一 chat 入口，原问题不改写，不注入标准答案。
- 引用修复后的完整复测 24.44 秒：answer_status=answered，quality.passed=true，regenerated=0，evidence_check=sufficient，learning_intents=[explain]。
- 回答确认图连通、各顶点度为 2，应用定理 7.11[2]，给出 v1-v2-v3-v4-v1；PDF 引用中 source_index=1 对应定理 7.11，source_index=0 对应定理 7.12。
- 详细结果保存在 artifacts/euler-real-verification.json；该文件仅含本次独立测试账户数据。
