# 对话可视化升级实施计划 v1

日期：2026-10-13。状态：阶段 A/B/C 已完成，阶段 D 测试账户验收与本机预览部署完成。详见[阶段 A 报告](阶段A消息生命周期报告.md)、[阶段 B 报告](阶段B图论互动报告.md)、[图提问与真实对话修复](三条真实对话与图提问修复.md)、[阶段 C/D 验收报告](阶段C测评与阶段D验收报告.md)。范围为欧拉图单组件，不代表全章节可视化完成。

依据：[分段调研结论](结论.md)。本文将六批调研转为可执行阶段；新增范围是对话中的互动示意图，沿用教材阅读器、RAG、TaskService 和 MemoryManager。

## 一、首批目标与技术选择

用户学习欧拉通路与回路时，可以打开一个辅助示例图，增删边、移动节点，明确点击“解释当前图”或“给我一个提示”。后台读取实际图状态、教材证据和学生记忆，回答针对当前图的问题。刷新页面后恢复图；继续聊天或收到进度事件时，图不丢失。

|路线|项目适配判断|
|---|---|
|模型生成任意 HTML/JS|首批不用；难以统一验证数学结果、保存状态及控制提示泄露|
|整体迁移 React 聊天框架|首批不用；会扩大现有引用、公式、SSE、澄清流程的回归范围|
|现有聊天 + 固定组件注册表 + 后端验证|采用；先改消息生命周期，再接入 Cytoscape.js 和 NetworkX|

直接使用开源库；借鉴 OpenDSA 的提交/提示记录、json-render 的规格白名单和 OpenIntelligentUI 的生命周期思路。新增代码集中于本项目的数据契约和教学接线，不自行重写图引擎。

已有 MathLive、KaTeX、SymPy 保留。首批不新增模型，不把图数据交给 GPU 模型做确定性计算。安装前核对 Cytoscape.js/NetworkX 的兼容版本、许可证与锁文件，固定实际版本。

### 首版范围

- 仅无向简单图；固定节点集合，允许增删边与拖动布局。
- 初定 2–12 个节点、最多 30 条边；数值是首版工程限制，实施时固定在服务端和组件契约中。
- 禁止自环、重复边、未知端点；零边图与孤立点返回明确边界结果。
- 首个审核模板：四节点环，允许添加一条对角边。添加后没有欧拉回路，但仍有欧拉通路，不能解释为“不能一笔画”。
- 先核对教材对孤立点及欧拉图的定义。NetworkX 默认语义不能直接替代教材语义；必要时显式检查非零度子图，同时给出所用约定。
- 图标记为“辅助示例”，与教材原图、教材引用区分。首批不从教材截图自动还原邻接关系。
- 暂缓有向图、多重图、自由代码执行、通用证明拼图以及全章节组件建设。

## 二、阶段 A：稳定消息和画布生命周期

### 代码接线

主要位置：`frontend/app.js` 的 `messagesFromHistory`、`renderChat`、`sendMessage`，后端历史响应及对话保存路径。

1. 历史响应提供稳定的 conversation row ID；前端保存该 ID。流式消息先使用客户端生成的稳定键，完成后映射持久化 ID，不能因此重新挂载画布。
2. 将聊天渲染改为按消息键更新；进度、正文、引用、澄清及互动组件分别更新。避免每个 SSE 事件替换整个聊天容器。
3. 新增组件注册表，接口包含 mount/update/dispose；删除消息、离开页面时释放监听和实例。
4. 保留现有数学渲染、引用跳转、重试和滚动行为。文本更新不能覆盖画布节点；滚动仅在用户接近底部时跟随。

### 完成条件

- SSE 连续更新、追加消息、重试及公式渲染期间，同一个画布实例和图状态保持不变。
- 来回切换页面不重复注册事件、不留下已销毁实例。
- 历史恢复时消息 ID 稳定；尚无互动数据的旧消息照常显示。

本阶段先使用本地假组件验证生命周期，不需要调用模型。

## 三、阶段 B：图组件、数据契约和状态恢复

### 建议新增模块

|位置|职责|
|---|---|
|`models/visualization.py`|Pydantic 规格、操作、提问目标、结果白名单|
|`visualization/graph_validator.py`|NetworkX 确定性验证、教材语义适配|
|`visualization/service.py`|模板创建、权限/版本校验、状态操作、展示投影|
|`database/models.py` 与专用 repository|规格、状态、快照和提交持久化|
|`frontend/visualizations/`|注册表、图组件、提示和错误交互|

以上为计划文件名，实施前按现有导入结构确认。

### 核心契约

|对象|必要内容|
|---|---|
|Artifact|artifact_id、schema_version、component_type、origin、template_id、owner、session_id、message_id、知识点、来源关联|
|GraphState|稳定 node/edge ID、规范化端点、revision、教材语义版本|
|LayoutState|节点位置；与数学状态分开保存|
|Operation|request_id、expected_revision、明确操作类型和端点|
|Attempt|attempt_id、图快照、学生预测/解释、hint_used、反馈、验证器版本、时间|

客户端不传权威正确答案、掌握度或教材证据。来源 ID 必须存在，由服务端确定章节和知识点。origin 首版固定为辅助示例，不将生成图充当检索证据。

规范化去重无向边；同 request_id 重试不重复执行。增删边使用 expected_revision 原子检查，过期操作返回冲突并让客户端加载最新状态。拖动仅更新布局，不增加数学 revision，不触发 AI。

### 存储和删除

- Artifact 关联已持久化的 assistant message ID；现有 append_exchange 只返回布尔值，需补充可取得对话 ID 的内部保存接口，并保持旧调用兼容。
- 学生、会话及知识点范围在服务端检查。当前历史接口不能据此被宣称已实现整个聊天会话隔离。
- 删除学生/关联消息时清理互动数据；忘记知识点时处理对应规格、状态、提交与任务引用。
- 复用 memory_epoch 防止删除或忘记后，延迟响应重新写回数据。新增表必须接入现有清理和事务路径。
- 刷新恢复规范图状态和布局；算法结果重新计算，不能仅信任缓存 verdict。

### API 行为

- 创建：服务端审核模板生成 Artifact；不会执行模型返回的任意代码。
- 读取：检查归属和会话，返回允许该教学模式展示的字段。
- 操作：增删边执行 revision 检查、规范化与数学校验，再提交新状态。
- 提交：保存独立 attempt 与该时刻快照；重复提交幂等。

具体 URL 随现有 main.py 路由约定确定，接口语义先固定。

## 四、阶段 C：接入教材检索、记忆和 AI 提问

主要位置：`models/task_context.py`、现有聊天请求模型、`agents/task_service.py`、ConversationRouter、main.py、MemoryManager。

1. 为 TaskObject 添加受控可视化对象类型；请求增加 `visualization_target`，包含 artifact_id 和 expected_revision。与其他选择目标的组合规则显式验证，首批一次只指向一个互动对象。
2. 后台读取 Artifact 与规范图状态，计算度数、连通性和相关结果，生成有界上下文；不使用客户端发来的结论。
3. 保留用户原问题，将图、章节、知识点与提问意图接入现有 TaskService 和检索链。教材依据照常引用，辅助图不占教材引用编号。
4. 根据知识点从现有 MemoryManager 取相关记忆；不另建一套学生记忆数据库。
5. 为请求冻结图 revision 和快照；回答写入前检查图 revision、任务 guard 与 memory_epoch。图被修改、任务取消或知识点被忘记时，拒绝过期回答写入，提示重新提问。
6. 版本检查和最终写入置于同一事务保护范围，避免“检查后、写入前”发生变更。布局拖动不使回答过期。
7. 恢复澄清任务时重新核验对象与版本，不让旧任务引用不存在或已变化的图。

仅“解释当前图”“给提示”或学生明确提问触发模型调用；增删边由本地交互与后端数学计算处理。

### 教学模式与展示控制

|模式|展示/写入规则|
|---|---|
|探索|允许查看计算结果和辅助解释；操作记录不代表独立掌握|
|提示|先展示图和所需步骤；服务端展示投影隐藏最终判定及完整路径，按提示阶段开放信息|
|测评|提交前隐藏最终结论/路径；提交后给反馈，标记是否使用提示|

模式由服务端教学流程决定，客户端不能随意解除限制。提示控制同时应用于 API 返回字段、图层和 AI 输出，而非只靠 prompt。

明确提交的预测/解释才可能产生学习证据；拖节点、点按钮、AI 展示答案不能增加掌握度。带提示的提交接入现有 evidence_policy，不能标为独立正确；后续独立测评建立新 attempt。

## 五、阶段 D：验收与灰度

先做约 20–30 个有区分度的检查，不用重复测试数量代替覆盖。

|检查范围|关键用例|
|---|---|
|数学边界|环、路径、环加对角线、超过两个奇度顶点、两个不相连的环、孤立点、零边图、自环/重复边拒绝|
|组件生命周期|SSE 更新、数学渲染、追加消息、页面切换、历史恢复、滚动位置|
|一致性|重复操作、revision 冲突、双标签页、提问期间改边、拖动期间提问|
|隔离与删除|跨学生/会话对象拒绝、删除消息、忘知识点、取消任务、延迟写回拒绝|
|教学约束|提示模式不泄露完整路径、测评提交前不显示答案、带提示提交不记独立掌握|
|兼容|旧历史、PDF 圈选、图片/教材引用、澄清恢复、重试、功能关闭|

后端使用现有 unittest；前端检查包含真实浏览器实例与状态，而非仅断言生成的 HTML 字符串。

工程检查通过后，再进行约五条实际对话验收：解释环、解释加对角线、只给提示、纠正“偶数度就一定有回路”、指代不清时澄清。记录图快照、检索来源、输出与提示泄露情况；本计划阶段不发送真实学生数据。

### 灰度和回滚

- 新增默认关闭的可视化开关，先测试账户，再明确白名单。复用现有账户类型判断，不能仅信任客户端声明。
- 与现有 task rollout 配置协调：互动提问依赖被关闭时，后端拒绝新提问及旧澄清任务恢复，页面说明状态。
- 功能关闭后旧图可显示静态快照/不可互动状态，不删除历史数据；无规格或加载失败时保留文字回答。
- 切换配置按现有重启流程处理在途请求，不假设热更新已实现。
- 灰度前完成必要数据备份、迁移和回退说明；不修改真实配置或重启服务直到实施到相应阶段。

### 放行标准

数学边界、提示泄露、跨用户隔离、删除后写回和图状态丢失等关键检查全部通过；五条真实对话人工审查通过。记录失败原因与修复，不更改题目标签来提高通过率。

上述仅证明工程与内容可用。学习增益另做文字/静态图/互动图的小规模对比，并使用迁移题衡量；不能根据操作次数宣称学习效果提升。
