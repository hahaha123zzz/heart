# 对话可视化分段调研结论

日期：2026-10-12。参考原文：E:/项目/heart/对话可视化.md。仅调研，不改教学代码、配置或学生数据。

## 结论速览

建议方向：先稳住消息/组件生命周期与状态恢复，再做图论单组件的有限互动及提问闭环。直接复用Cytoscape.js、NetworkX与已安装的SymPy、MathLive、KaTeX；借鉴OpenDSA的可评分步骤、json-render的组件白名单与OpenIntelligentUI的生命周期控制。

调整原文建议：不同时实现三四类P0组件；不为首批整体迁移React聊天框架；不运行自由生成HTML/JS；不把拖动次数当掌握度；不把学习科学论文的结论冒充本项目学习增益。当前最具体的工程障碍是renderChat整段innerHTML重建会销毁画布，以及缺少互动规格/状态的历史恢复契约。

## 第1批：目标、层级与首篇论文

### 项目现状（源码证据）

- frontend/app.js 的 renderChat 转义文本，已有公式渲染、教材图片、PDF裁图、引用跳转及澄清选项；不是零可视化基础。
- renderProgress 与 main.py 的SSE已有阶段反馈，不应重新开发“思考展示”，也不需要暴露模型内部推理。
- renderChat 每次对聊天容器设置 innerHTML；若直接插入有状态画布，后续进度/聊天更新会销毁节点及学生操作。须先处理组件生命周期。
- ConversationRow主要保存文本，历史引用通过已有专用路径恢复；目前没有通用的可视化规格、互动状态、操作事件与版本存储。
- TaskContext已经支持section/pdf_selection/exercise_part，新可视化对象尚不在资源白名单中；意图升级仍有真实回答验收未完成。

### 原文建议的判断

同意将数学对象变成可观察、可操作、可验证的内容；不同意直接把L3+L4当首批全面建设目标。当前应先确保公式/表格/引用稳定，再做一个有界互动试点；组件重绘、状态恢复、数学核验和任务引用均未准备好，直接全科L4会扩大风险与成本。

建议区分教材原始图与AI辅助示意图：前者属于RAG证据，后者是根据可验证规格绘制的教学示例，不能冒充教材原图或自动占用教材引用编号。

### 外部核验与代码复用

[Learning Interactives论文](https://arxiv.org/abs/2609.20738)确实存在，v1提交于2026-09-17；摘要描述结构化生成及教育工作者评价。它支持教学目标和专家审核的重要性，尚不能据摘要推断学生学习增益已在课堂随机对照实验中证实。下一批论文核验须继续查看正文方法与限制。

[CopilotKit/OpenGenerativeUI](https://github.com/CopilotKit/OpenGenerativeUI)当前重定向到OpenIntelligentUI；原文项目名已变化，应核对现行源码，不据旧名称假定接入方式。

[Cytoscape.js官方文档](https://js.cytoscape.org/)提供图交互/算法与MIT核心许可；属于绘图引擎，不等于教学Agent或学习效果证明。后续检验算法和事件源码后再决定直接复用范围。

首批工程判断：保留FastAPI、现有SSE与记忆/任务控制层，优先“固定组件 + 校验数据 + 确定性数学结果”，暂不在每次对话运行自由生成HTML/JS。此为项目适配建议，不是已实施设计。

## 第2批：实际教材与互动场景

已核对 knowledge/course.py：十章是集合代数、两个数学基本原理、计数、命题逻辑、谓词逻辑、形式系统、图、特殊图、关系、函数。原文声称没有完整目录属于原调研当时的信息缺口；本项目已有可核对目录，不能继续按典型教材假设。递推/数论不作为独立首批主题；仍须按实际小节核查是否出现相关内容。

### 场景取舍

|主题|建议|原因与范围|
|---|---|---|
|图的度数、连通性、欧拉性质|首个互动试点|已有第7章PDF与图引用链，容易构造可复现小图|
|命题真值表|第二个组件候选|小变量逻辑可穷举验证；公式渲染已存在|

|函数/计数/证明卡片|后续逐项试验|图形能否揭示数学关系比覆盖主题数量重要|

不同意原文把四类场景同时列P0。首批建议只做一个闭环；不要同时接四个绘图库。图论首批限制为小规模无向简单图，节点ID稳定，增删边、度数与连通性可检查；暂不让学生无限自由造图，也不直接将教材截图识别为精确邻接表。

### 源码核验与重要修正

已读取[NetworkX euler.py](https://github.com/networkx/networkx/blob/main/networkx/algorithms/euler.py)的is_eulerian：无向图检查全偶度与连通性，有向图检查入出度相等及强连通性；含孤立点会判False。[官方接口文档](https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.euler.is_eulerian.html)明确这个约定。直接复用函数之前必须与教材“是否忽略孤立点”的定义对齐，还需单独处理空图、自环、多重边与边ID；“偶数度”本身不是充分条件。

原文四顶点环加对角边的例子确实会产生两个奇度点，但结果是失去欧拉回路、仍可能有欧拉通路，反馈不能写成“不能一笔画”。无向例子不能推广为有向图判定。

[SymPy逻辑文档](https://docs.sympy.org/latest/modules/logic.html)可支持truth_table与satisfiable；寻找等价失败的反例应检查两个公式异或的可满足性，而非只检查某一公式可满足。建议复用逻辑算法，不执行用户/模型传入的任意Python表达式；限制语法树、变量数量和复杂度。

最小验收需包含断连偶度图、两个奇度点、空图/孤立点约定和版本不匹配。这里只提出验收要求，未安装库或运行新的数学测试。

## 第4批：聊天协议与组件生命周期

同意原文把LLM、数学引擎、渲染器分开；原文VisualizationSpec是建议伪代码，不是合法JSON或现有返回值，不能直接交给前端使用。还缺消息/对象稳定ID、状态版本、来源版本、允许操作与判定结果的服务端归属。

### 实际候选框架的区别

- [json-render](https://github.com/vercel-labs/json-render)当前README用catalog/schema/registry限制组件与动作，提供多种框架渲染器。这证明声明式组件路线可行，不证明数学正确；我们原生JS聊天无需为一个图切换React/Vue，首批借鉴小型固定组件注册表即可。
- [A2UI](https://github.com/a2ui-project/a2ui)当前从google/A2UI重定向到新组织；协议和渲染适配仍须固定版本。首批无跨平台需求，暂不迁移通用协议。
- assistant-ui的Tool UI属于React聊天组件路线；当前主体不是React，暂不整体引入。本文仅核对官方项目路线，尚未验证迁移成本。
- 已读取OpenIntelligentUI的visualization_router.py：其展示选择调用JEV_URL=https://api.typesafe.ai/v1/systemone，并使用LangChain中间件。开源应用并不意味着整个选择器可本地免费复用；复制该模块会引入新的外部服务与调用成本。只借鉴有限类型分流、按消息ID防重复选择的思想。
- websandbox-loader.ts定义iframe、run和destroy；renderer.tsx用节流和稳定引用。这对我们当前整段innerHTML重建是直接启发，但不是完整沙箱安全审计，也不建议此刻运行模型生成JS。

### 本项目建议数据流（未实施）

原任务识别与教材取证 → 规则/已确认意图选择一个模板 → 有限VisualizationSpec校验 → 确定性数学判定 → 同消息挂载稳定组件。

学生操作先更新局部状态；鼠标拖动不调用LLM。明确点击“解释当前结果/给提示”才发送对象ID、revision和简短问题，后端重新加载与验证状态，再接TaskService的对象引用和现有回答质检。

规格建议字段：artifact_id、schema_version、component_type、origin（教材复刻/辅助示例）、source_refs及资源版本、数学数据、allowed_actions、validator_id、hint_policy。判定结果不能采信客户端自报true/false；教材原图只有经过人工或服务端结构核对才标为复刻，普通图标为辅助示例。

首批无需新增“每轮必须再问一次模型”的可视化规划Agent。明确例子/图请求和支持主题可用已有learning_intents与模板规则决定；不适合绘图时正常回答。

### 当前代码必须补的接口

1. 为消息建立稳定标识、按ID挂载/更新/销毁画布；流式进度只更新进度DOM。聊天滚动/更新不能重置学生已修改的边。
2. 历史接口保存并恢复可视化规格与最后已确认状态，独立于文字；不把通用JSON塞进content后用innerHTML执行。
3. 新对象进入TaskContext需扩展白名单与所有权/版本核验，不能把客户端图当无条件可信教材证据。
4. 复用TaskService的session/request/revision、取消和删除epoch；互动状态也纳入账户删除与知识点遗忘。
5. 聊天窄栏显示小图和关键结果；复杂操作可在同页展开，保留当前对话与教材跳转。不要把“必须完全塞在气泡里”作为设计硬约束。

证据：[展示路由源码](https://github.com/CopilotKit/OpenIntelligentUI/blob/main/apps/agent/src/visualization_router.py)、[沙箱加载接口](https://github.com/CopilotKit/OpenIntelligentUI/blob/main/apps/app/src/components/generative-ui/open-generative-ui/websandbox-loader.ts)。上述适配路线属于工程判断，还需要小原型验证重绘与状态恢复。

## 第5批：教学工具、记忆与论文证据

### 不照单全收的部分

原文四个Skill更适合作为教学模式/策略枚举，首批不必建立四套独立Agent或安装Codex技能。运行时教学Tool与当前开发环境SKILL.md是不同概念。首个图组件只需要创建规格、更新状态、核验性质、请求针对当前状态的解释；教材图读取复用已有接口，不新建重复取图系统。

node_moved只改变布局；edge_added/removed改变数学图；answer_submitted表示学生提交判断。点击或拖动次数不能当掌握证据。当前memory/evidence_policy.py已经区分独立与辅助作答，可复用此边界；新增互动事件还要记录题目、尝试、提示次数、显示答案状态与判定版本，再决定是否形成学习事件。不能让LLM直接调用“记录掌握度”函数。

图形反馈也会泄露答案：hint_only时若界面直接显示“欧拉回路A→B→C…”或自动补出传递性缺边，即使AI文本只给提示仍已泄露。需要分别设计探索模式、提示模式、测评模式，控制结果和见证显示，质检同时覆盖视觉内容与文本。

“证明拼图”不是一般证明验证器：同一证明常有多种合法顺序，只能针对已审查的有限推理依赖核验，不能用单一参考序列判所有其他顺序错误。“添加一条边即可满足条件”挑战还须验证允许操作下确实有解。

### 原始论文核验

Google论文[正文§2–4](https://arxiv.org/html/2609.20738v1)指出部分以细节记忆为主的生物学主题退化为教材序列；不是所有学科都自然适合动态模拟。正文确实检查在Chrome运行的界面，未指明Playwright。公开样例不等于完整生成流水线的开源授权，本文尚未确认可复用的完整流水线仓库。文中单轮生成与多轮修订的通过率属于其特定批评准则，不能外推为本项目数学正确率。

### 产品与验收建议

首个活动采用“先预测 → 操作一条边 → 观察可允许显示的结果 → 自己解释原因”。AI追问必须可跳过；学生当前只要一个提示时不强制整套闯关。不把原文五种趣味交互都列为需求。

技术验收先测结构正确、提示不泄露、刷新不丢状态、跨会话/删除无串扰、AI解释针对当前revision。教学效果另测同难度迁移题、独立完成、提示依赖与理解解释；满意度、点击次数、停留时长单列，不代替学习效果。小规模可用性试验只提供问题发现，不能假装随机对照证据。

## 第6批：综合方向与推进条件

原文整体方向可借鉴，但优先级需要按现状调整：本项目已经有MathLive输入、KaTeX聊天渲染及React PDF阅读器，不应把“安装MathLive”“引入React”重复算成新工作。reader/package.json确认React18.3.1、react-pdf-highlighter7.0.0、MathLive与KaTeX；React存在于阅读器，不等于整个聊天已经使用React。requirements.txt已包含SymPy1.14.0，可复用现有后端依赖。

原文以CPU为主要环境的描述已过时，用户此前明确有GPU；本批未重新检测硬件与驱动。小图验证和真值表不需要GPU，GPU应服务已有embedding/reranker等模型，不因可视化而增加在线渲染成本。动画预生成仍有价值，但理由是可审查和低延迟，不能单靠“机器没GPU”。

### 建议路线（研究结论，尚非获批实施计划）

|阶段|具体产物|进入下一阶段的条件|
|---|---|---|
|0 基础与契约|稳定消息DOM、可视化规格/状态/来源、失败纯文本回退|进度更新不重建画布；引用和数学文本正常|
|1 图论垂直试点|Cytoscape.js小图+NetworkX验证；明确模板创建|数学边界正确、提示模式不泄露、状态刷新恢复|
|2 对话闭环|提交预测与当前状态→TaskService→AI解释；提示与独立提交分别记录|对象版本一致、会话隔离、删除保护、AI不编造图中边|
|3 有证据再扩展|真值表→关系图/矩阵→集合/函数|各组件都有定义、核验器与试验收益，不只增加图形种类|

“先一个组件”不意味着只做静态截图：试点中应有必要的增删边和一个显式提问按钮，但先限制数据规模与可用操作。避免先建设完整可视化平台后才发现学生无法恢复对话。

### 推荐技术栈

现有FastAPI、SQLAlchemy/SQLite、TaskService、SSE、RAG/Memory → Pydantic VisualizationSpec + 组件/动作/核验器白名单 → NetworkX及现有SymPy → 原生JS组件注册表 + Cytoscape.js + 现有KaTeX/MathLive。

保留同页聊天与阅读器；如生命周期原型表明局部React组件岛更容易维护，可复用reader的构建设施，但应比较打包边界、消息通信与重复依赖后再决定。没有证据要求整体切换assistant-ui/CopilotKit。

[assistant-ui当前官方工具文档](https://www.assistant-ui.com/docs/tools)已采用toolkit路线；旧Tool UI教程与接口可能发生迁移，不能把旧示例直接视为当前最佳接口。[json-render](https://github.com/vercel-labs/json-render)的声明式catalog可作为以后多组件组合的对照；首批不引入通用生成框架或自由HTML/JS。

### 验收与收益判断

不同意一开始用“100–150题”作为没有覆盖说明的门槛。先建设约20–30个明确边界的工程用例，按数学语义、规格异常、生命周期、并发、提示、引用分类；覆盖不足再增加。题数是建议，不是已完成结果。教学试验先选少数同一知识点的等难度任务，比较文字、静态示意、互动与反馈；控制提示、用时、内容一致性，记录迁移题而不只问好不好玩。

决定继续或暂停扩展的指标：无已知数学错误与答案泄露；刷新/重试状态可恢复；引用不把辅助图冒充教材；学生能解释性质变化；模型调用数量和延迟可接受。如果互动只增加操作负担而不改善任务完成和解释质量，就缩减组件，而非继续增加动画。

### 待核验清单

1. 本地图引擎版本、打包体积、浏览器兼容、触屏/键盘替代和窄栏可读性：尚未运行原型。

3. 首批辅助图模板与习题绑定是否泄露答案、如何做独立测评：需人工审查。

5. 意图识别真实回答与引用验收仍未全部完成，可视化不得掩盖这个未完成事项。
