# 全教材多形式可视化调研：最终成果与复用判断

日期：2026-10-13。状态：调研与路线建议；尚未实施全教材覆盖。
> 路线更新：用户随后明确要求模板与Skill按需生成，本文第6节的全量离线制作方案不再作为主实施路线。以[按需可视化Skill与模板源码调研](按需可视化Skill与模板源码调研.md)为准。


## 1. 结论

采用多种可视化载体、统一简单播放方式。每道习题都进入覆盖清单，按题目实际结构选择图解、推导、流程或步骤对照；不要求每题都有运动动画。难点知识清单需结合教材定义/定理/例题、先修关系及学生实际困惑审核，不能凭关键词宣称全部难点已识别。

展示优先嵌在相关AI讲解中，学生主要点击下一步/上一步。概念关系图与章节总览可作为教材伴随资料。测验练习保持独立；未提交测评或只给提示时，不提前打开完整答案。

本次依据公开源码、官方示例与截图分析，没有安装运行第三方整套系统。公开demo存在不等于其输出对本教材已经正确。网页搜索缓存与当前main可能不同，源码读取固定到下列commit。

## 3. 源码复用边界

- DeepTutor当前注册器还包含mindmap和GeoGebra类型；分析模型的六类输出枚举不是全部插件目录。不能只看枚举便称它没有其他形式。
- DeepTutor的visualizer协议以manifest与JSON Schema约束输入，renderer在iframe内接收payload；适合借鉴我们的VisualSpec/RendererRegistry设计。
- DeepTutor的interactive block生成HTML后检查格式。能显示并通过格式检查不代表数学论证正确；本项目应另保留教材定位和确定性数学验证。
- OpenMAIC的交互iframe以sceneId保存，组件卸载时隐藏但保留实例，内容改变才重载。我们已有局部挂载生命周期，可借鉴其避免状态丢失的原则。
- DeepTutor本次commit许可证Apache-2.0，OpenMAIC为MIT。它们的React/Next.js组件不能直接放进当前原生JS聊天前端，须适配。可复用小范围契约/验证逻辑，保留来源与许可证；本轮没有集成其代码。
- MAIC-UI与Mathigon仓库API未识别许可证，不能据公开可读推定可自由复制；先借鉴方法。Manim输出内容及外部素材也需分别核对。
- 当前Cytoscape、关系闭包/图论验证器、KaTeX和引用定位可保留。多形式可以先用受控SVG、HTML表格和KaTeX完成，无须同时安装所有工具。

## 4. 本教材的真实规模

catalog.json包含10章、341道大题、788个小题。按现有输入题型统计（这些分类并不等同于教学概念）：

| 题型 | 小题数 | 推荐解释载体 |
| --- | ---: | --- |
| choice | 77 | 选项对照、区域或条件高亮 |
| fill | 97 | 对象/公式分步补齐 |
| proof | 275 | 前提—推理—结论流程、逐式推导 |
| expression | 98 | 公式变换、计数结构与计算表 |
| written | 187 | 条件拆解、实例/反例、方法流程 |
| judgement | 16 | 成立条件与反例对照 |
| matrix | 19 | 图矩阵联动、活动单元格 |
| graph | 19 | 图/树路径与算法状态 |

有275个proof小题，说明仅扩展图论或真值表组件不能完成覆盖。目前首批教材场景是审核过的固定实例，尚没有通用逐题可视化清单；已有题目ID、章节/小节、原题blocks和来源版本，可作为离线制作与追溯基础。

## 5. 我们建议交付的多种最终成果

下表是本项目拟采用的方案，不是声称开源项目已实现这些离散数学题目。

| 展现形式 | 教材用途 | 下一步时的实际画面变化 |
| --- | --- | --- |
| 集合区域/元素图 | 交并差补、子集、德摩根律 | 逐次突出区域、元素归属及运算结果 |
| 对象分组/计数树 | 鸽巢原理、排列组合、加乘法原理 | 按条件展开分支，标示重复计数或被排除分支 |
| 归纳与递推图 | 数学归纳、递推过程 | 基础情况→归纳假设→归纳步；展示范围和推导依据 |
| 真值表与逻辑结构图 | 命题、蕴含、范式、逻辑等价 | 逐个子表达式计算，再揭示本行最终值 |
| 有限论域与量词覆盖图 | 谓词、全称/存在、量词顺序 | 依次检查对象，突出见证或反例；明确有限例子不证明无限论域 |
| 公式推导板 | 等价变换、计数、形式系统 | 高亮本步改写片段、适用规则与下一式 |
| 图/树算法演示 | 路径、欧拉、生成树、特殊图 | 标记当前节点、路径、候选边和算法状态 |
| 关系图矩阵对照 | 性质、闭包、等价关系、偏序 | 同步突出序偶与矩阵格；展示分组或覆盖关系 |
| 映射箭头/逆像图 | 单射、满射、双射、复合、逆函数 | 依次追踪输入到输出，显示冲突、遗漏或中间映射 |
| 判定/证明流程图 | 定理适用、解题步骤、证明结构 | 逐步点亮经过的分支或推理节点，保留条件标签 |
| 概念关系/章节总览 | 定义、定理、前置知识串联 | 聚焦当前知识节点及它的直接前置；关系须有教材依据 |
| 分镜/短动画 | 静态步骤难展示的连续变换 | 点击下一步播放一个短片段或显示下一张分镜 |

## 6. 全覆盖的实现路线建议

1. 建立覆盖目录：全部788个小题登记题号、原文条件、教材出处、候选形式、制作状态、核验状态；正文定义/定理/例题另建概念目录。章节总览按小节整理先修与方法关系。
2. 建立多形式渲染协议：在现有guide/frames基础上扩展集合、树、映射、公式、矩阵与流程图；统一下一步操作和教材出处。相同Renderer可以呈现不同题目的实际条件。
3. 离线批量生成草稿：读取原题+相关正文，提取条件与讲解步骤，再选择合适形式；与数学验证器或审核标准核对，存为版本化教材资产。
4. 逐章发布：以题目ID/知识单元ID定位，而不是依赖关键词命中某个固定示例；每章报告已审核/待审核/尚不支持数量，不把草稿算作完成。
5. 在线复用：AI解释或学生请求解析时载入相应已审核资产，绑定本轮上下文与引用。只给提示与未提交测评采用独立的可展示步骤范围。

证明题用流程图组织推理，但流程图本身不验证证明；每个节点要保留前提、适用条件和教材依据。题意含糊、缺少答案标准、无法解析公式的内容先标待核验。

## 7. 建议的最终学生体验

学生阅读或问一道教材题→AI讲解自动出现最适合的图解→下一步突出当前对象/条件→下一步显示推导和结果→可点击教材出处。同一讲解可依次使用两种载体，例如先集合图给直觉，再公式推导给严格依据，不让学生选择渲染器。

全教材覆盖以每个内容单元都有合适的可视解释为目标，不将每题必须有视频、3D或游戏作为验收条件。章节流程图分清学习先修关系、概念组织关系和判定分支，避免画成同一种无条件连线。
