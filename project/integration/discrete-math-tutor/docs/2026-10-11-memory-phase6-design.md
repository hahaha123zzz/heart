# 第六阶段设计：用户记忆管理

继续已批准的渐进路线，借鉴受约束记忆变更和删除传播，采用当前设置页内可折叠面板；不增加全新页面或外部依赖。

## 能力与边界

- 查看当前学生的显式偏好、知识点状态、误区、证据来源、最近事件及摘要。新接口仅面向已有 test 账户，与当前本机 Demo 对齐；学生 ID 范围过滤不是生产身份认证。
- 更正具体误区：用户说明进入 user_memory_correction 事件与 student_statement 证据，目标标 dismissed；这是用户否认候选判断，不证明能力，不修改其他误区或掌握度。
- 现有设置保存改为原子记录显式偏好来源。可清除单个偏好；旧修订快照中的该键同步清理。
- 删除以整个知识点学习记忆为单位，明确包括该知识点原始对话、证据、状态、计划、误区、策略观察、摘要、任务和检索索引。不是精细删除某条能力证据后假装能无损重建后续掌握度。
- 做题成绩保留业务记录，但该知识点当前已关联的提交加入记忆排除表，索引重建不会重新召回。之后的新提交可形成新记忆。
- 删除保留无正文的 epoch 控制记录，加入版本快照，阻止进行中的旧聊天写回。后台任务和向量写回继承来源/哈希检查。修订快照同步移除被删除知识点内容，避免旧快照保留副本。
- 对话有明确事件/选区关联的才能按知识点删除；无法还原归属的旧孤立对话不猜测删除，界面和结果文档说明。

## 模块

MemoryControlRow、MemoryExclusionRow、MemoryChangeRow；Repository mixin memory_management；MemoryManager 管理入口；memory_api 路由；现有 preferences 接口接线；设置页折叠管理面板。所有 mutation 使用短事务及 scope 校验，无 LLM 调用。

## 验证

隔离 SQLite / FastAPI 测试：误区逐项否认、学生范围、偏好溯源/清除、删除原子性、跨知识点保留、旧聊天版本冲突、后台晚到结果、向量晚到写回、索引重建排除旧练习、后续新提交、修订快照清理、API 422/403/404、前端语法与交互处理。
