# 离散数学平台前端改造计划

初稿日期：2026-10-10  
补充日期：2026-10-11  
状态：已于 2026-10-11 按用户授权实施。原计划与补充要求保留；执行结果与验证范围见 2026-10-11-frontend-redesign-results.md。

## 1. 目标与已确认设计

采用接近 Codex 桌面端的三栏工作区：左侧功能导航与章节目录，中间教材，右侧对话。灰白底色，浅蓝用户消息，灰蓝选中状态与按钮，减少装饰和卡片嵌套。

视觉依据是用户确认的配色修订效果图：artifacts/ui-redesign/2026-10-10-approved-workspace.png。效果图中的教材页码、图和聊天文字均为示例；实施必须使用真实教材与真实接口数据，不能把效果图作为页面背景或复制其中的示例学习记录。

本次优先覆盖学生端。改造目标是提高阅读、提问与练习的连续性，并统一其他页面风格。

## 2. 当前基础与实施路线

目前主页面是 frontend/index.html、frontend/styles.css 与 frontend/app.js；练习交互在 frontend/practice.js。React PDF 阅读器源代码在 reader/src/reader.jsx 与 reader/src/reader.css，frontend/pdf-reader 是构建产物。

建议沿用现有页面、练习组件、PDF 阅读器与后端接口，分阶段调整布局和共享状态。无需为了这次视觉改造把整个项目迁移到 React。

备选路线：整体迁移 React 有利于长期组件化，但会扩大改造范围与回归风险；只调整 CSS 见效快，但不能解决目录位置、圈选跳页、重复阅读器等结构问题。选择现有技术上调整结构并做必要模块拆分。

## 3. 页面结构

### 3.1 左侧导航

展开宽度默认 216px，可收起为约 56px 的图标导航。功能入口为：继续学习、教材阅读、练习与复习、学习记录。设置放在底部。

教材模式下，章节目录放在同一左栏的功能入口下方，支持展开、收起、滚动和当前节高亮。导航与章节目录不占用两列。最近对话区域暂不承诺独立会话功能：先核对后端是否有会话标识和查询能力；若只有对话消息历史，则通过学习记录提供入口，不伪造会话列表。

原“智能答疑”入口兼容跳到工作台右侧对话并聚焦输入框。原“学习统计”和“我的学习”整合为学习记录中的分类内容；偏好设置完整保留。

### 3.2 中间教材

顶部为真实章节路径，工具区保留页码跳转、缩放、文字选择和区域圈选。正文使用现有 PDF 阅读器，维持教材本来的图、公式、表格和排版。

教材与笔记切换保留已有笔记能力，不把现有章节笔记直接宣称为个人笔记。课件、例题线索等已有入口移至工具菜单或次级标签，仍然可访问。

底部提供进入相关练习的按钮。教材中继续只展示阅读内容，习题在交互练习页面完成。

### 3.3 右侧对话

标题体现当前讨论主题；显示当前章节和已选内容。用户消息用浅蓝气泡，助教正文采用普通文本流，公式、图片、引用和检索状态按内容分组。

圈选后显示文字或截图预览，允许修改问题、移除选区，再发送。保持教材页码、缩放与滚动位置。引用点击回到教材对应页面或选区。

使用真实流式进度与错误信息。处理中保留输入草稿、明确发送状态，支持失败重试。将逐步提示、举例等已有快捷操作统一排版。

当前已经支持多条教材来源、跨章节 PDF 引用及学习记忆摘要；新版对话必须保留每条已核验引用的独立页码按钮和裁图。回答未完成、证据不足等状态不能套用普通成功回答样式。具体契约见第 12 节。

“新建对话”“保存个人笔记”等效果图按钮需要接口支持。未确认支持的能力不作为第一阶段可点击入口。

### 3.4 其他页面

继续学习：以恢复阅读位置、未完成练习、真实复习入口为主，移除大幅宣传横幅。没有历史记录时显示简洁的开始学习入口。

练习与复习：使用同一左栏与视觉系统，中间作为作答区域。题干、公式、矩阵、图编辑器继续使用已有组件；长题默认聚焦当前小题，允许展开整题；右侧展示与当前题目关联的提示和解释。

学习记录：整理学习进度、提交记录、确认错题、相关对话和待复习内容，保持来源与状态准确。

设置：保留现有学习偏好及新增学习记忆管理，使用一致的表单、保存反馈和错误提示。记忆管理包含知识点选择、来源查看、误区更正、清除偏好与删除知识点记忆；这些功能必须有明确入口。

## 4. 栏宽与响应式规则

桌面默认左栏 216px，余下宽度按教材 60%、对话 40% 分配。此比例不包含导航。

教材和对话之间提供拖动分隔条，以及“阅读优先 70:30、均衡 60:40、对话优先 50:50”快捷布局。记住当前学生在当前浏览器的设置；缩窄窗口时重新约束合法宽度。

建议桌面最小正文宽度 560px，对话最小宽度 360px。空间不足时先收起左栏，再改为教材和对话标签切换，避免挤出横向滚动。

建议断点：1280px 及以上默认三栏；1024–1279px 默认左栏收起，仍优先双内容栏；低于 1024px 使用阅读/对话切换与抽屉导航。实现时根据最小栏宽动态降级，而非仅靠固定断点。

分隔条支持键盘调整和可访问名称；按钮具备焦点状态。移动端目录和输入框不遮挡正文，阅读/对话切换保持上下文。

## 6. 状态与数据衔接

整理一个共享学习上下文，至少包含：当前视图、章节、节、PDF 版本与源页码、阅读滚动定位、缩放、选区、输入草稿、当前练习与小题、布局偏好。

源教材页码与拆分后的阅读 PDF 页码继续通过现有 page_map 转换，引用不能误跳到显示页码对应的另一页。选区和阅读位置以教材标识、版本和章节作为作用域。

跨章导航：目录高亮、内容元信息与阅读器跳转由同一成功加载结果更新；取消或忽略过期请求，防止连续点击后旧请求覆盖新章节。加载失败给出错误反馈，不能仅改变目录高亮而正文未变。

圈选提问：保留 /api/pdf/selection/preview 流程，删除课程页圈选直接离开教材的交互；改为打开或聚焦右侧助教。切换章节时，已附加选区保留原章节来源并明确显示；发送使用选区的真实来源，避免误绑定到新章节。

对话：继续使用 /api/chat/stream 及现有教材检索、学生记忆流程，保留 textbook_sources、pdf_references、selection_ref、image_refs、pdf_image_refs、memory_summary 和 answer_status 的现有数据语义，呈现接口实际返回的内容。学习记忆不以假示例填充；没有返回依据时不声称“已关联某条记忆”。

阅读与练习：沿用 startPractice 的章节和选区来源规则。进入练习前保存阅读位置，返回时恢复；练习按原草稿与提交恢复机制处理，不重置作答。

布局与普通输入草稿可按学生标识存储在当前浏览器；学习数据和批改结果仍以现有接口为准。全局搜索保留，可放在左栏紧凑入口或搜索弹层中。

## 8. 分阶段实施任务

### 阶段一：基础盘点与设计映射

- 记录当前可用入口、DOM 绑定、接口和阅读器生命周期；以 2026-10-11 当前文件为实施基线，不能用旧版本覆盖新功能。
- 优先补齐多引用、质检失败、记忆操作、技能来源、符号题作答与题库版本的现状清单。
- 对照效果图确认控件与真实功能映射，识别尚无接口支持的按钮。
- 记录改造前关键流程的基线截图和行为；只使用必要场景。
- 形成精确文件修改清单与回退方式。

完成标准：能说明现有每个主要功能在新界面中的入口，暂无孤立功能。

### 阶段二：三栏与视觉系统

- 建立共享页面外壳，左侧合并导航与章节目录。
- 落地灰蓝配色、字体层级和基础表单样式。
- 实现栏宽调整、快捷布局、偏好保存和窄屏切换。

完成标准：三栏布局接近确认稿，默认比例清晰，内容不溢出；鼠标与键盘均能调整布局。

### 阶段三：教材与对话连续衔接

- 接入单一主要阅读视区与共享对话面板。
- 实现跨章定位、阅读位置恢复、圈选预览、侧边提问、来源回跳。
- 保留真实检索进度、图片公式显示、失败和重试；覆盖多来源、跨章节及刷新后的引用。
- 将质量拒绝与网络失败、证据不足分别表达，具体以真实返回状态为准。

完成标准：阅读、圈选、提问、引用回跳可以在同一工作台连续完成。

### 阶段四：练习及辅助页面

- 统一练习页风格，增加当前小题聚焦与整题展开。
- 接通题目提示/解释与右侧面板，提示仍关联具体题目，不能混入教材聊天状态。
- 接通阅读与练习双向恢复。
- 整理继续学习、学习记录、搜索、设置入口；迁移现有学习记忆查看、更正、删除和技能来源展示。
- 保留动态 answer_format、规则题固定空数、符号解析待核对状态及题库版本处理。

完成标准：真实题型组件、草稿、提交与反馈保持可用，其他页面采用同一设计系统。

### 阶段五：验收与交付

- 对照确认稿检查桌面、窄屏实际渲染，记录合理差异。
- 执行下表关键交互回归，修复发现的问题。
- 更新 README 与交付记录，提供可查看的运行页面。

## 10. 风险与回退

主要风险为 DOM 重组后事件绑定失效、PDF 重挂载丢位置、拆分页码映射错误、练习提示与普通对话上下文混用、持久化布局在窄屏不可用。

按阶段保留可回退变更，不覆盖已有数据。前端资源版本号随正式构建更新，避免浏览器缓存旧脚本。构建前确认 reader 的产物路径与引用保持一致。

## 11. 本轮交付边界

编写计划时仅保存计划与视觉参考。用户后续明确授权执行，现已完成前端改造、阅读器构建与本机服务更新，详见交付记录。

## 12. 2026-10-11 最新前端变化与补充要求

### 12.1 核对范围与依据

本补充直接核对 frontend/index.html、frontend/app.js、frontend/practice.js 及相关交付记录。当前仍是原来的卡片页面结构，新增交互主要集中在引用、记忆管理与练习反馈；用户确认的三栏视觉方向保持有效。

本轮未运行浏览器或服务，也未重新测试模型、记忆删除或练习提交。以下“已有”指当前代码存在对应实现；历史验收结果仅作为参考，正式改造须重新验证。工作区存在大量其他未提交修改，实施时只能基于最新文件增量改造，不能恢复旧版整文件。

| 当前变化 | 代码依据 | 新界面中的安排 |
| --- | --- | --- |
| 多来源教材引用 | renderChatReferences、renderPDFReference、messagesFromHistory | 对话内来源列表与独立定位按钮，裁图按来源展开 |
| 跨章节引用定位 | data-pdf-reference 选择对应 selection_ref | 中间阅读器切章定位，右侧当前对话保留 |

| 学习记忆管理 | settings-view 的 memory-management、refreshMemory | 设置中的明确管理入口；学习记录可提供只读来源入口 |
| 偏好清除与误区更正 | data-forget-pref、data-memory-correction | 每项操作就近放置，保留请求中和失败状态 |
| 删除知识点记忆 | memory-forget-point 操作及后续刷新 | 明确删除范围，保留练习成绩，成功后同步当前展示 |
| 规则练习技能 | detail.skills、independent_items、sources | 学习记录/记忆详情中的技能摘要及来源，不显示全章已掌握 |
| 符号答案与动态空数 | practice.js 使用 blank_count、answer_format.instruction、verdict=uncertain | 从 API 渲染控件与说明，保留规则无法确定的待核对结果 |

### 12.2 多引用显示与定位约束

1. 正文 [1]、[3] 等编号对应 textbook_sources 的原 source_index，不因 UI 排序或折叠改成连续编号。
2. 所有已经版本核验并进入 pdf_references 的证据入口继续展示，不能因模型漏写正文编号就隐藏主证明或前置材料。对未核验背景来源沿用当前过滤规则。
3. 每条引用使用自身 selection_ref、章节、版本、页码与裁图。不能全部按钮共用主选区。
4. 兼容只有 selection_ref 的旧历史；旧记录没有保存的来源不由前端猜测补全。
5. 跨章定位只改变中间教材，不再强制跳到首页；保持右侧回答、草稿和用户主动附加的选区。当前代码把引用写入 pdfDraft，这次改造需要拆分“阅读焦点”和“下一次提问附件”：点击查看引用不能自动污染待发送附件。
6. 避免把同一裁图在主选区、多引用和普通图片区域重复显示；去重按来源标识和图片 URL，不能合并不同来源编号。

### 12.3 学习记忆管理与状态表达

当前管理入口位于设置的折叠区域，迁移时必须保留现有完整操作：

- GET /api/students/{student_id}/memory 与 point 参数：查看概览、知识点详情、证据、事件、后台候选摘要和技能来源。
- DELETE /api/students/{student_id}/memory/preferences/{key}：清除明确保存的偏好，并刷新偏好表单和记忆展示。
- POST /api/students/{student_id}/memory/misconceptions/{id}/correction：提交学生更正说明，并更新误区状态。
- DELETE /api/students/{student_id}/memory/points?point=…：删除选定知识点记忆，沿用现有删除范围确认和练习成绩保留语义；成功后刷新对话历史、画像与记忆面板。

误区状态保持对应含义：hypothesis=候选判断，supported=有支持记录，confirmed=多次支持，dismissed=已否认，resolved=已纠正。只有接口允许的状态提供更正入口，不能用模糊的“已解决”覆盖全部状态。

技能估计与概念掌握估计均未校准；独立规则小题、得到提示后的规则作答、AI 暂定结果、学生陈述和后台候选摘要应分开表达。后台摘要不能成为数学依据或能力结论。列表默认呈现学生能理解的概览，事件编号等详细来源放在可展开区域，仍允许核对。

DOM 重组时重新绑定记忆事件，避免当前文件尾部直接绑定旧节点导致初始化报错。refreshMemory 的请求序号机制保留，防止快速换知识点后旧结果覆盖新选择。

### 12.4 练习新增契约

当前交付记录报告规则覆盖扩展到 41 个小题、15 项技能；这只是本次核对时的版本信息，UI 不能写死该数量，应以运行时题库与接口为准。

动态 blank_count 和 answer_format.instruction 是控件依据。例：第7章图删除题现在由 API 返回四个空；不能按旧导入题面恢复成一个空，规则题也不提供随意增加或删除空数的按钮。

符号答案超过支持格式时可返回 uncertain；显示“规则无法确定，待核对”，不能归为 incorrect，也不能把 score=null 显示成 0 分。

小题聚焦不能改变提交语义：现有提交仍针对已作答的小题，隐藏的小题答案继续保存并参与原有提交。若聚焦视图卸载 MathLive、表格或构图组件，须先保存当前状态并在回切时重建。提示和 AI 讲解的帮助标记继续关联原 question_id、part_id、version，不能因移动到右栏丢失独立性记录。

题库/判分规则版本变化时沿用服务器校验，提供重新加载提示；不把旧版本草稿、分数或技能来源静默迁移到当前题库。

### 12.5 状态与回归补充

网络失败、证据不足、质量拒绝和作答待核对分开呈现。先盘点当前 API 的实际状态字段及兜底返回，再写 UI 映射；不得只按颜色或字符串中是否有“错误”判断。重试保留原问题和选区，作为用户明确重试发送，不自动循环，也不重复显示已保存的回答。

新增回归重点：

- 同一回答包含 [1] 和 [3]，分别定位两页；即使正文只写 [3]，已核验的主来源入口仍存在。
- 跨章节引用在正文区定位，刷新后来源保持，旧历史正常降级。
- 查看引用后，下一次提问附件未被自动替换。
- 质检拒绝显示未完成，保留实际处理反馈；不据此宣称所有记忆写入已回滚。
- 快速切换记忆知识点不会串页；更正、清除、删除失败时可恢复操作，成功后展示刷新。
- 图删除题四空、计数符号题格式说明、部分正确和规则待核对准确展示。
- 小题聚焦切换不丢 MathLive 输入、图/矩阵数据及帮助记录；旧题库版本不会绕过校验。
