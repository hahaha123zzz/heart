# 教材目录止血与默认 LightRAG 实施计划

日期：2026-11-24
执行工作树：`.worktrees/student-frontend-reuse-20261117`
本机起点：8000 当前发行 `textbook-first-v3-20261124`

## 目标与顺序

先交付目录修复并独立验收，再把学生端普通教材检索默认接入 Heart 已有的 LightRAG 1.5.7。普通概念题先以 `naive`、关闭重排做候选配置，基于真实回合的证据质量和耗时定稿。需要教材证据时保留教材优先、授权校验与可点击引用。本文仅为实施计划。

原始回归题为“给我解释一下几种不同类型的自变量，然后要解释的详细一旦”。原回合服务端耗时 351.9 秒，5 次 `rag` 分 3 批约 210 秒。目录输出 497,438 字符，模型请求输入从 6,876 增至 261,809 token。这些数字作为历史故障基线。同机 A/B 另用相同模型、教材版本和测试账号建立对照。

## 阶段一：独立交付目录修复

- [ ] 在 `tests/test_heart_rag_citations.py` 增加目录回归。用含 `pages[].text`、`page_count`、章节标题和授权范围的清单夹具，覆盖正常目录、筛选、无匹配、只授权部分章节及历史清单缺少 `page_count`。断言正文哨兵既不在工具输出，也不进入模型工具消息。
- [ ] 修 `integrations/deeptutor/heart_rag.py` 的 `HeartCourseFilesTool`。按允许访问的版本过滤章节，仅投影章号、标题、节数、数字页数、文档 ID。缺少 `page_count` 时可从页面列表数量取值。直接按字段生成目录，按条目限制输出，截断时报告省略条数。明确工具只服务目录、章名和文件范围查询。
- [ ] 用已有浏览器或请求录制夹具核对实际模型入参，覆盖主动问目录和概念题中误调目录。补测旧会话恢复时是否会重新注入历史巨型工具结果。若可复现，复用现有历史投影，仅对模型输入重建轻量目录或省略过时目录正文，保留历史记录和合法工具消息关联。
- [ ] 验收通过后打包单独的目录修复发行，在本机 8000 核对登录、目录、普通教材问答和原有引用。记录发行 ID、耗时、目录结果大小和模型请求输入 token。将这个版本登记为第二阶段的回退点。

## 阶段二：普通教材检索默认接入 LightRAG

### 2.1 打通普通聊天入口和授权

- [ ] 以登录后的 8000 原生聊天建立定向集成测试。记录普通聊天能否拿到现有 `learning_tool_scope` 所需的 `NativeTaskCheck`，并验证宿主固定教材后端已就绪。现有 `CoursePipeline.search` 依赖任务授权。若普通聊天缺少该上下文，沿实际回合入口补齐服务端授权绑定，保留学生、请求、会话、版本和课程范围的校验。桥接令牌只承担服务身份校验。
- [ ] 将固定教材 `rag` 转到已有 `course_rag_provider.py`、`course_search_api.py` 和宿主的常驻 LightRAG 后端。通过真实 WS 聊天确认实际后端和模式。共用原有来源投影、权限过滤和引用核验。验证课程外闲聊、已有阅读选区调用和其他知识库入口的既有行为。
- [ ] 用 `tests/test_course_search_bridge.py`、`tests/test_tool_policy_course_first.py` 及相关授权测试覆盖跨用户、未授章节、过期回合、版本变更和取消。分别处理无证据、后端未就绪和超时。正常入口以 LightRAG 为默认，发布回退使用上一发行，不通过静默转回旧引擎掩盖后端异常。

### 2.2 收敛检索次数与证据大小

- [ ] 普通概念题优先使用原问和当前可信章节线索做一次 `naive` 查询。通过 `QueryParam` 实测 `chunk_top_k=5–8`、关闭重排的候选配置。记录实际传入的模式和参数，核对候选能覆盖问题。跨章综合题对照 `hybrid` 或 `mix`，按结果确定默认路由。
- [ ] 复用 provider 的回合缓存、同查询合并和来源去重。服务端普通题默认一批，第一批缺少明确要点时允许定向补查一批。用调用轨迹确认重试、并行调用和缓存命中都受同一个回合预算约束。取消或超时后验证后端资源能释放。
- [ ] 保留可点击引用和原文高亮。核对当前 `CitationIndex` 是否已随相同教材版本发布。若普通回合仍走实时 PDF 定位，复用现有索引生成与发布流程开展对照，通过页码、引句和高亮测试后启用预建索引。模型证据只投影短引文与稳定来源引用，目录和证据合计以 3,000 token 作为普通题首轮实验预算。
- [ ] 在现有事件中记录实际 provider、模式、召回数、证据数、缓存命中、工具输出大小、模型输入 token 和各阶段耗时。检索证据量与整个模型请求输入分开统计。首段有效正文、完整输出和最终落库单独计时，并行区间按墙钟时间统计。

## 验收与发布

| 检查项 | 通过条件 |
|---|---|
| 目录 | 能列出授权章节和正确页数，工具消息和后续模型输入均无逐页正文。 |
| 原问题 | 命中实验心理学教材的分类依据，回答覆盖教材的分类及相应要点，默认一批 LightRAG，角标能跳页和高亮，助手答复成功保存。 |
| 扩展样本 | 跨章、指定页或选区、无证据、后端不可用、权限、旧会话回放和取消均通过。跨章样本按已标注的必需出处核对证据覆盖。 |
| 性能 | 同题、同教材版本、同模型分别测目录修复版与 LightRAG 候选版。报告冷启动、预热单请求和双并发。普通题预热后 RAG 以 10 秒内作为初始实验目标。未达到时用阶段计时定位瓶颈，并在切换前记录差异。 |

按现有本机发行流程打包、校验和切换。LightRAG 候选版通过质量、权限、时延与落库检查后，才设为 8000 的默认版本。如果该阶段触发回退，切回已验收的目录修复发行，保留学生对话和教材数据。
