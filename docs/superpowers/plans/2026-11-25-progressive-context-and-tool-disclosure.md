# 学生问答的上下文与工具定义渐进式披露实施计划

日期 2026-11-25
目标工作树 `student-frontend-reuse-20261117`
当前运行发行 `textbook-prefetch-20261125`

## 交付目标

在现有 DeepTutor、LightRAG 和学生端入口上，一次交付教材证据按需展开、历史按任务回放、工具定义分层发送。保留默认教材授权、现有教材引用与高亮、阅读器跳页，以及服务商实际截断时的续写。代码分步验收，通过后一起打包。

前置工作以现有「学生端默认教材与生成前预检索」实现为基础。该旧计划里的教材 4,000 字符硬截断和每轮两批检索限制，以本计划为准。工作树已经移除 `HeartCourseRagTool` 的两批上限并通过相关测试，当前发行仍有旧限制。打包时核对候选包含这项改动。此前测到「自变量是什么」的一条 RAG 消息 5,002 字符中有 4,036 字符是链接，短 ID 离线计数为 3,720 → 885 tokens。该数据用作基线，实际改善以真实请求为准。

## 0. 建立基线

- [ ] 锁定当前发行、教材索引和账号授权、实际模型与思考配置，记录冷或热状态。标明既有样本所属发行，候选前后用同一组问题和可比配置。
- [ ] 复用 `agents/loop/context_budget.py`、`LLMRequestSnapshot` 与现有 usage 记录，在实际发往模型的边界采集逐次请求。统计固定提示词、工具文字清单和 schema、历史、当前问题、选区或图片、首轮证据、当轮工具结果、续写分别占多少。可估计的分项注明 tokenizer，供应商实际 tokens 独立记录。只记录体积、计数、类型、阶段和耗时。
- [ ] 记录每轮模型调用、检索调用、补读、工具加载、截断与续写次数，以及缓存命中、首字时间和端到端时间。记录返回证据数、实际披露数和最终引用数。

## 1. 统一证据、短引用和按需读取

主要入口是宿主 `knowledge/fixed_book.py`、`knowledge/pdf_reader.py`、`integrations/deeptutor/{legacy_reader_turn,course_rag_provider,heart_rag,native_delivery}.py`，以及 vendor 的 `agents/loop/pipeline.py`、`agents/loop/agent_loop.py` 与 `tools/builtin/__init__.py`。

- [ ] 复用已有固定教材启动核验，在候选进程对外就绪前建立并校验章节文档、页码、原文和坐标映射。宿主与 worker 使用同一份已核验发行标识和资源映射，运行期间按只读使用。请求通过内存映射检查授权、文档归属和页码坐标。只有启动校验覆盖到的固定教材路径才移除在线 PDF 文件哈希，其他材料路径沿用原校验。避免引入第二遍教材全量扫描。
- [ ] 复用已有结构化 `sources` 和来源身份。稳定来源 ID 供历史回查，每回合另分配 `[S1]` 形式的短 ID。短 ID 在本轮范围唯一，不因重复查询、并行结果或续写而变化。章节、原文和定位存在服务端，本轮实际披露的证据才进入可引用映射。
- [ ] 让首轮教材预检索、后续 `rag`、选区及 `read_source` 共用证据投影。预检索优先使用选区或对应题型的教材范围。普通教材题用现有 LightRAG 预检索。首轮按相关性和子问题覆盖挑选证据，按完整条目控制输入量，替换教材分支的字符串硬截断。定义保留限定条件，公式保留变量约定，表格保留结构、表头、单位、脚注或对应图片。某条放不下时保留可恢复的来源和位置提示。
- [ ] 让 `HeartCourseRagTool` 消费提供方的新增证据投影。相同证据跨预检索和后续检索复用原短 ID，重复结果只带短提示。对授权范围内已选定的来源，`read_source` 按 ID 补读完整相关段落。缺的是不同概念或比较维度时允许定向 `rag`。无可靠依据时沿用既有可核验引用和通识兜底规则。
- [ ] 在学生实际流式发布边界解析短 ID。处理 ID 跨流式块、句尾多个引用、模型输出无效 ID 和代码块中的示例 ID。只有本轮授权且已披露的来源生成正式链接。统一实时答案、最终结果、已保存历史和重新打开后的版本。继续支持旧答案已有的链接，保留章、页码、定位及高亮。
- [ ] 测不同章节同页码、同来源不同查询、并行检索、预检索和补查重叠、超长完整段落、无依据、越权 ID、两个账号或分支的引用隔离，以及过往链接的浏览器回跳。

## 2. 修复阅读选区重复

主要入口是 `web/features/heart/LegacyTextbook.tsx`、`web/features/chat/ChatStateAdapter.tsx`、宿主 `legacy_reader_turn.py` 和 vendor `capabilities/reading/capability.py`。

- [ ] 文字选区默认问题保留用户意图，提交选区定位与标识。首轮教材原文由服务端核验后统一注入一份。保留用户手动编辑的文本，重试与历史重放也使用同一份已核验选区，避免新旧载荷都被拼入。
- [ ] 框选表格、公式和图时保留裁图及模型所需文字。模型能从现有选区解答时，不重复读取整页。需要上下文时继续通过原有阅读工具补读。
- [ ] 保留 `reader_goto`、现有阅读工具的调用提示和前端动作。浏览器验证明确跳页、已有自动跳页和用户点击引用三条路径。

## 3. 按当前任务构造历史视图

主要入口是 vendor `services/session/{context_builder,model_history}.py` 及 `agents/loop/pipeline.py`。

- [ ] 保留已有 `model_turn` 和会话分支记录。只调整发给模型的历史视图。普通会话优先保留用户问题、已发布回答、必要状态及来源索引。会话内短问与历史明显无关时，省略旧教材工具正文。相关追问可以根据当前分支的来源索引恢复原文。
- [ ] 在最近回合内部就限制旧工具正文的回放，覆盖「最新一整组会优先保留」的情况。旧版超大目录结果或已完成的重复工具输出降为结构化引用或简要结果。若保留历史工具协议，保留调用与结果的有效配对。当前正在执行的工具轮、必要的 provider 状态、澄清暂停、重试与编辑分支单独回归。
- [ ] 从已有历史、已保存引用或可访问的教材资源恢复证据。旧记录缺少可恢复 ID 时，用现有章节与引用信息回查或定向补查。跨账号、跨分支、已失去授权的内容不能因 ID 复用进入本轮。
- [ ] 用旧版 `kb_files` 约 497,438 字符的样本验证最近回合内的工具正文裁剪，分别断言「今天几号」不再发送旧目录正文和「上一轮第二条是什么意思」可恢复所指证据。

## 4. 按场景筛工具，再分层披露定义

主要入口是宿主 `integrations/deeptutor/tool_policy.py`，以及 vendor `agents/loop/pipeline.py`、`runtime/providers/view.py` 和 `runtime/registry/deferred_tools.py`。

- [ ] 由同一份本轮工具选择结果控制实际 `tools`、提示词目录及新工具调用的执行权限。教材概念题首轮提供需要的检索或补读能力，过滤 `kb_files`。明确的目录和章节查询提供目录工具。阅读模式保留原有跳页与阅读能力。短问尽量不挂教材工具。混合意图仍可按需补齐相关能力。现有权限与能力独占规则继续生效。
- [ ] 目录层只呈现可发现工具的名称和一句用途。可调用层提供精简但有效的 schema，保留参数名、类型、必填项、枚举和影响正确性的约束。详细层由现有 `load_tools` 按需加载完整定义、长说明或边界示例。常用工具直接进可调用层，避免在每个普通问题上新增发现往返。
- [ ] 使用现有注册表和 `DeferredToolLoader`。服务端缓存工具定义。当前任务内已加载的定义可以继续使用，新任务按场景重新选择发送范围。合并或重载同名 schema 时只留一份，保持顺序稳定。按真实请求验证权限拒绝、发现、加载后调用、跨任务收回和目录文字一致性。

## 5. 移除学生聊天固定的 8,000 输出预算

主要入口是 vendor `agents/loop/{pipeline,agent_loop}.py`、`runtime/agentic/client.py` 及当前 provider 适配层。

- [ ] 在学生聊天链路取消默认发送的 8,000，检查普通生成、自动续写和兜底收尾。输出参数缺省时，确认请求构建器、SDK 和 provider 适配层不会再补回项目默认值。保留明确配置的其他能力预算和服务商限制。
- [ ] 有真实 `finish_reason=length` 时继续走现有恢复。当前无显式请求上限时，纯推理耗尽检测以服务商信号为依据，避免将用量和已移除的旧阈值比较。保留已有超时、取消、回合边界、流式拼接和 DeepSeek 思考状态传递。
- [ ] 对实际序列化请求断言没有固定 8,000。覆盖自然结束、服务商明确截断、纯推理、续写和强制收尾。详细题同时比较输出长度、续写次数和总耗时，短问的跑题用历史与工具视图解决。

## 6. 联合验收与发行

| 用例 | 通过条件 |
|---|---|
| 自变量定义与教材目录 | 概念题无 `kb_files`，目录题读目录且不携带正文。概念题引用原文完整。 |
| 多概念对比、跨章出处、证据不足 | 首轮证据覆盖主要维度，缺口可补查，重复原文只展开一次。没有把未披露证据当作引用。 |
| 拖选文字、框选图表、读当前页 | 选区正文一份，裁图与正文落在正确章页，问答保留必要的条件和单位。 |
| 导航与发布 | 原有 `reader_goto` 和点击旧新引用都能正确定位。流式、保存和刷新后的引用一致。 |
| 长答后的相关追问与日期 | 相关证据可恢复。日期答复不携带旧长工具正文，不继续教材任务。 |
| 详细题与服务商截断 | 实际请求无项目固定 8,000，输出和工具调用正常。服务商截断时续写不重复前文。 |
| 失败、取消、重试、授权和分支 | 各入口能按现有协议收尾。不同账号和分支互不串用引用与工具。 |

- [ ] 先跑宿主课程检索、引用、选区、工具策略与原生交付测试，以及 vendor 的 Agent Loop、历史构建、模型历史、上下文预算与延迟工具测试。用现有测试账号通过学生端实际入口执行上述样本，查看真实请求、工具事件和浏览器行为。
- [ ] 对照基线报告每类题的实际输入、未命中缓存输入、模型往返、首字与总耗时，并核对原文条件、引用定位和选区完整性。先确保质量和权限回归通过，再验收输入体积下降、热路径无不必要的工具加载往返。
- [ ] 用现有发行控制脚本构建独立候选。候选通过健康、教材就绪、浏览器和真实模型检查后再切换 8000。保留当前已验证发行用于回滚。出现引用错页、权限串用、流式内容重复或核心问答回归时切回原发行并复验。历史保留与旧引用兼容应允许回滚无需改写会话数据。
