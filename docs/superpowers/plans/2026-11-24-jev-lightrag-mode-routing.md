# DeepTutor 接入 Jev 路由 LightRAG 六种模式的实施计划

日期 2026-11-24  
目标工作树 `student-frontend-reuse-20261117`

## 目标与现状

在学生端原生 `/ws` 回答链路里，由 Jev 为实际发生的课程 `rag` 查询选择 LightRAG 模式。每个新查询决策一次，同回合相同查询复用决策和检索结果。目标是在保持教材原文支撑与引用跳转质量的前提下，缩短学生看到首条正文的时间。

8000 最近的发行验收已证明普通课程题会调用 `rag`。工作树中的 `CoursePipeline` 已增加普通 WebSocket 学生的宿主桥接，`course-search-native` 能检查用户、工作区、会话和活跃回合。工作树的默认模式是 `naive`，由 `HEART_COURSE_RAG_MODE` 配置。开始实施时先通过真实回合确认部署实际后端和模式，以实测结果建立基线。目录修复和 LightRAG 默认接入沿用已有计划，独立记录发行与验收结果。 [默认 LightRAG 接入计划](2026-11-24-default-lightrag-and-textbook-catalog.md) · [8000 教材优先验收](2026-11-23-mandatory-textbook-retrieval.md#验收记录2026-11-24)

## 接入位置与执行顺序

`/ws → DeepTutor rag → CoursePipeline 回合去重 → 宿主课程检索授权 → Jev Choice → 指定模式检索 → 教材原文和引用 → DeepTutor 生成`

- 首轮上线范围为学生工作台走 `/course-search-native` 的课程查询。宿主在确认课程、学生身份、工作区、会话和活跃回合，并确认后端就绪后，调用 Jev 决策。把选择结果通过现有 `mode` 传给宿主常驻 LightRAG，复用已有索引与 `aquery_data`。
- 在内部请求契约区分「自动选择」与「显式模式」。普通学生 `rag` 请求默认进入自动选择，指定模式的测试、诊断和已有内部调用仍按指定模式执行。自动调用继续复用 `CoursePipeline` 的结果缓存和进行中任务合并，键包含查询、范围、授权作用域及自动或显式模式。一次进行中的自动查询只创建一个 Jev 请求和一份主检索任务。
- Jev 的输入使用本次实际检索词、可信的章节范围和可用的短上下文线索。TypeSafe 调用仅发送路由所需信息，账号身份、附件、完整会话、记忆和教材原文留在项目侧。服务端优先复用已部署且可验证的 Jev 服务，否则用项目侧 `TYPESAFE_API_KEY` 调用官方 `POST /v1/systemone`。固定评测使用的模型版本。使用 `Choice` 的 `criteria` 描述模式的证据要求，解析并校验 `choice`、`probabilities` 和 `confidence`。 [TypeSafe Choice](https://docs.typesafe.ai/primitives/choice) · [TypeSafe API](https://docs.typesafe.ai/introduction/quickstart)
- 教材选区和当前页先走原生阅读工具。只有伴读实际扩大到课程 `rag` 时才启动 Jev。现有 `read_material`、`search_material`、练习判题、图谱页面和 DeepTutor 的主回答循环继续走原有入口。

## 六种模式及允许条件

| 模式 | Jev 选择依据 | 执行方式 |
| --- | --- | --- |
| `naive` | 术语、定义或具体事实预计可以从一个或几个教材文本块获得直接证据 | 文本块向量检索 |
| `local` | 明确围绕一个实体或概念，重点找与它直接相连的内容 | 以实体为入口做图谱检索 |
| `global` | 重点找教材主题、概念之间的关系或较宏观的结构 | 以关系为入口做图谱检索 |
| `hybrid` | 同时需要实体附近的细节和主题关系 | 组合 `local` 与 `global` |
| `mix` | 同时依赖图谱关联和直接文本命中，例如跨章比较还要找明确的原文例子 | 组合知识图谱和文本块向量检索 |
| `bypass` | 仅用于服务端已确认本轮无需检索且允许直接生成的场景 | 跳过检索并走 DeepTutor 原生生成。隔离评测单独覆盖 SDK 的 `bypass` 行为 |

课程 `rag` 请求已经明确需要教材证据，Jev 在这类请求内只得到前五个可执行选项。第六种模式在独立的无检索场景验证，保持教材检索接口现有的五模式白名单。已经能由系统规则直接处理的闲聊和权限明确的直接生成请求，无需进入课程检索路由。正式启用第六种决策分支时，须在原生生成前通过服务端证据要求检查，并断言一轮只有一次正文生成。 [LightRAG v1.5.7 模式定义](https://github.com/HKUDS/LightRAG/blob/v1.5.7/lightrag/base.py)

## 任务一　固定真实基线

- [ ] 用隔离学生账号走 `/ws` 回放定义、连续追问、实体邻域、主题关系、跨章综合、指定页、无证据和非课程题。确认实际后端、请求实际模式、教材修订号、引用跳页及高亮。
- [ ] 复用教材检索题集与引用判据，为问题标注必须覆盖的教材证据。固定模型、教材、范围、候选参数和运行环境，记录实际部署的默认模式。离线用五种检索模式分别跑同一题，建立「满足证据条件的最快模式」参考。另用隔离的无需检索样本验证 `bypass`。
- [ ] 对无结果区分「确无教材证据」「候选被授权过滤」和「后端失败」，同一问题的基线及实验共用判定口径。

## 任务二　实现 Jev 客户端与模式选择

- [ ] 在集成层增加小型 Jev 客户端和模式选择逻辑。增加 `off / shadow / active` 配置，默认 `off`。`shadow` 记录 Jev 建议及耗时，回答路径沿用基线模式且无需等待旁路结果。限定旁路任务并发与生命周期。
- [ ] 在 `course_rag_provider.py`、`native_contract.py` 和 `course_search_api.py` 接通自动选择意图。宿主在授权后、启动检索前调用路由器，并在返回前保留原有来源授权过滤。复用现有桥接和取消链路。
- [ ] 给 Jev 设置独立且可配置的短超时。超时、限流、服务异常、低置信度、响应无效或模式不在本轮白名单时，直接执行已验收的固定基线模式。阈值和超时由基线与留出题集校准。交互关键路径上的 Jev 调用采用一次尝试。
- [ ] 已选择的模式证据不足时，由现有补查预算限制最多一次定向回补。回补使用预定策略并复用相同授权和教材版本。权限拒绝、版本失效和取消按现有状态退出。即使 Jev 建议直接回答，需教材依据的请求也应保留证据约束。

## 任务三　测试与观测

- [ ] 单测覆盖五种允许的类别、需教材时拒绝 `bypass`、无检索场景和单次生成、低置信度、无效响应、超时和显式模式。用替身验证同回合同查询只决策一次，取消会结束关联任务，跨账号与跨作用域结果隔离。
- [ ] 集成测试覆盖真实入口的桥接、未授权时 Jev 调用次数为零、模式实际传入 SDK、空结果回补、版本变化及引用跳页。对照现有 `test_heart_rag_citations.py`、`test_lightrag_deepseek_query.py` 和课程桥接测试。
- [ ] 使用回合 ID 关联 Jev 耗时、选择模式、实际执行模式、回退原因、检索耗时及次数、证据覆盖、模型调用次数、浏览器首条正文和 `done`。统计并行阶段采用墙钟时间，日志使用查询哈希及结构化计数。
- [ ] 将「工具调用模型请求」「Jev 请求」「LightRAG 本身」「正文模型请求」分开计时，以免把额外决策时间或现有模型往返算成检索提速。

## 任务四　对照实验、灰度与回退

- [ ] 对照三组。A 为当前已验收的固定模式，B 为按问题线索选择模式的确定性规则，C 为 Jev 路由。用校准题选阈值，用留出题判定收益。同一批问题交错执行，覆盖预热后的单请求与双并发，冷启动单列。
- [ ] 发版门槛。教材必需出处覆盖、引用页码和高亮、无证据处理及授权负例全部通过。含 Jev 和回退耗时的首正文 P50 必须优于固定模式和规则组，P95 不得劣于两组中表现更好的基线。按题型同时报告完整答案耗时、调用数、回退率和样本量。样本不足以支持 P95 结论时，保持影子模式并补齐样本。
- [ ] 先影子运行，再限定测试账号启用实际决策。只在通过质量和时延门槛的场景开启。保留同一发行内的 `off` 回退开关和已验收的固定基线模式，验证切回后无需改索引、教材或会话数据。
