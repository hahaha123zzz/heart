# 固定教材启动分段计时实施计划

日期 2026-11-25
工作树 student-frontend-reuse-20261117
运行基线 lightrag-native-v4-20261124，宿主重排和 embedding 均为 CPU

## 目标和测量范围

用同一轮真实启动的分段记录回答两个问题。哪些步骤在同一轮对同一份资产做了等价工作，哪些步骤占用最长的启动时间。首轮实施只加计时与统计，维持现有初始化顺序、设备和就绪条件。报告将测量结果交给后续初始化优化和旧索引退役计划。

当前宿主 /health 只返回 fixed_book.startup_seconds，本机基线为 98.72 秒。之前的 111.86 秒和 31.28 秒说明不同运行条件下波动较大。独立复跑中，第二次扫描正式教材目录耗时 0.43 秒，旧本地检索的样例查询耗时 28.64 秒。两项可作为重点观察对象，启动耗时排名以整轮记录为准。

## 1. 给三个进程和教材初始化加时间点

- [ ] 在本机部署控制脚本记录同一次启动中的开始、每次发行校验、服务进程创建、worker 就绪、宿主健康且 fixed_book.ready、Web 可登录。若探测按顺序阻塞，控制脚本继续按现有顺序执行，辅助采集器单独并行探测三个端口，以区分首次实际可用与控制脚本首次观测到可用。
- [ ] 用同一个 startup_id 关联控制脚本、宿主和 worker 记录。主机日志记同一时区的事件时间，每个进程内部用单调时钟计算持续时间。固定教材内部另记初始化入口、self.ready 赋值、FixedBookRuntime.start 完成、/health 首次通过四个时间点。self.ready 为内部状态，宿主应用完成启动后，外部才可成功调用健康接口。
- [ ] 在下表列出的现有函数调用边界布置计时。优先复用已有 warmup 和结构化日志出口。采样时不增加文件哈希、数据库查询、模型调用或远程连接。辅助探测计入单独口径。
- [ ] 每条记录包含阶段名、父阶段、调用序号、耗时、完成状态和已有的计数。目录操作记录根路径类别、用途、文件数和已有的版本标识。数据库操作记录命名空间和已有计数，模型操作记录设备和实际 provider。日志不落教材原文、个人数据或密钥。失败和取消也记录已走过的阶段，避免把未执行的步骤报告为零耗时。

| 分段 | 需要有的独立计时 |
| --- | --- |
| 发行和输入核验 | 控制脚本各服务的发行文件校验。宿主的 LightRAG 清单核验可拆为 PostgreSQL 基线记录和表核对、冻结输入扫描、正式教材扫描、控制文件摘要。 |
| 正式教材资产准备 | 原文来源映射、冻结图表目录、正式教材发布快照、目录加载、正式教材图表目录、再次 inventory 建哈希表。每项分别记录。 |
| 引用坐标 | 记录已有固定路径、命中按版本缓存、缺失后新建三种分支。新建计时包含构建与原子发布。已有文件只记录解析和存在检查等实际发生的工作。 |
| 宿主 LightRAG | embedding 配置与兼容性检查、角色绑定、常驻查询线程调度、SDK 和 PostgreSQL 存储初始化、逐章来源绑定。逐章统计入库包校验、文档元数据读取、图表公式 sidecar 读取，汇总章数和最慢章节。 |
| 后续预热 | 图谱标签装载、旧 SQLite 与 LlamaIndex/BM25 加载、重排器会话加载、旧样例查询、客户端池准备、图片词表生成。旧样例查询沿用现有 embedding、召回和重排计时。 |
| 启动后的第一问 | 使用复核账号走正常 /ws 发预设教材题，记录首个实际 LightRAG 检索、第一段正文、来源返回和 done。同一题再测一次以观察常驻模型和缓存的影响。 |

对应接线文件以 knowledge/fixed_book.py、knowledge/lightrag/retrieval.py、knowledge/lightrag/course_input.py、knowledge/lightrag/storage.py、memory/background_worker.py 和部署控制脚本为主。现有 /health 总耗时保留原口径，分项采集输出按 startup_id 检索。

## 2. 核实重复工作

- [ ] 同一轮内，把两次正式教材目录遍历按根路径、文件范围、校验用途和处理量对齐。优先核对 verify_active() 中的 inventory 与 FixedBookRuntime.start 中保存 self.hashes 的 inventory。确认可以共享完整哈希结果后，再给出可合并的耗时范围。
- [ ] 分别检查每个服务启动前的发行包全量校验、原文映射与逐章入库包校验、图表资产和词表的多次读取、旧本地检索预热与线上 LightRAG 预热。记录共享了哪些输入、输出各给谁使用。相同读取、重叠读取和不同用途按证据说明，便于判断哪一步能复用。
- [ ] 结合已有输入身份、文件数量、调用次数和读取阶段验证重叠。只凭函数名相似或使用同一本教材不足以确认可省时间。跨线程的等待与执行分开看，父阶段与子阶段分别展示，同一墙钟区间只算一次。

## 3. 采样与报告

- [ ] 在隔离候选部署使用同版本教材、同一索引版本、同模型设备和同预热配置。至少完成三次进程重启，记录每次缓存状态。单独记录正常首次启动或明确的冷启动样本。没有确认操作系统缓存状态的样本标为进程冷启动。
- [ ] 用一次启动失败或取消场景验证记录可以定位最后阶段。给采集器做一次开关对照，确认计时没有改变调用次数和原有顺序。
- [ ] 为每次启动输出分段原始记录，以及从控制脚本启动到对话可用的时间线。汇总表列出各阶段耗时、调用次数、占宿主教材初始化比例和执行位置。有多次样本时报告中位数和范围，单次样本直接列实测值。
- [ ] 报告列出三个结果。其一是耗时最大的三个阶段和变化范围。其二是可确认的重复工作及其输入与耗时，并说明是否影响就绪。其三是就绪和首条教材回答的时间差，标明是否仍有加载或首次推理被留到第一问。
- [ ] 验收时核对固定教材内部的串行阶段与父阶段总时间能对账。总时间有明显剩余时，补出未计时区间或注明来源。线上切换和设备变更另行安排。
