基线发行 progressive-context-20261125d
关联计划 [学生问答的上下文与工具定义渐进式披露](2026-11-25-progressive-context-and-tool-disclosure.md)

真实 Chromium + deepseek-flash 复测覆盖七例。短引用、页码高亮和刷新后保存通过。下表记录其余范围的证据和验收目标。

| 原计划 | 已交付与复测 | 整改验收 |
|---|---|---|

## 1. 恢复浏览器首轮教材预检索

- [ ] 核对 `web/features/chat/controllers/buildStartTurnInput.ts`、聊天状态和 WebSocket 合约。现状是未选值被序列化为 `knowledge_bases: []`，后端 `_apply_course_defaults` 只处理缺省。早先修过的 `native_executor.py` 属于另一入口。
- [ ] 在实际学生 WS 入口恢复默认语义。测试缺省、旧客户端空列表、显式非空、课程无教材、无授权，以及回合重试。若其他入口把空列表用作显式清空，按学生固定教材策略处理其默认值，保留其他入口已有语义。检查决定最终值的工作区和权限过滤，再进入 `_retrieve_kb_seed_block`。
- [ ] 做三条真实断言：概念题与多概念题的预检索在首个模型请求前，短问和纯目录在首个请求前没有正文检索。相关证据只披露一次，无可核验证据时沿用现有降级。

## 2. 修复选区入口

- [x] `LegacyTextbook.tsx` 的文字提问只发意图，原文由后台核验并注入。对旧版本的精确自动生成问句做兼容，保留人为编辑的问题。
- [x] 在可信选区核验之后，将与已验证 area 裁图绑定的唯一附件标为阅读器来源，沿用截图入口过滤附件来源的约定。图片仍提供给阅读模型。普通上传图片、重试和不匹配的选区各自回归。
- [ ] 用浏览器拖选真实文字、框选含表头和单位的表格，查看模型消息与工具流水。表格应进入阅读问答且不出现作业识别，原有 reader_goto 保留。

工作树已完成文字去重与裁图来源标记。选区、WebSocket 合约与作业截图定向测试共 30 项通过。浏览器真模型重测仍需使用包含这次改动的候选发行。

## 3. 优化场景与工具定义

- [ ] 用已有 `tool_policy.py` 和 `tool_disclosure.py`，先把用户意图与阅读器状态分开。区分纯目录、出处、概念解释、混合意图、阅读和无关短问。纯目录识别「有哪些章节」「哪几章」等完整语义，去掉单个「哪」触发讲解的歧义。打开阅读器不自动把任意短问视为教材题。
- [ ] 高频且确定的工具直接提供精简可调用定义。纯目录直挂 kb_files，禁止无关预检索；普通概念题用最小教材工具组。长尾工具显示简述，按需用 load_tools 加载。让实际 JSON schema、文字清单与执行权限由同一名单生成。
- [ ] 对比场景首包 schema tokens、总输入、未命中缓存、调用次数和首字时间。目录应省掉 load_tools 往返，概念题不回归，混合需求与已授权的长尾请求仍能完成。以真实问题跑可重复对照，保留误分流样本。

| 调研方案 | 决定 |
|---|---|
| DeepTutor DeferredToolLoader、LangChain 动态工具 | 直接复用本地加载器和工具注册表；参考 LangChain 在单次模型请求前根据状态过滤工具。 [LangChain](https://docs.langchain.com/oss/python/langchain/context-engineering) |
| MCP 客户端规范、AWS 实作 | 复用目录、检查、执行的设计，高频直挂，长尾按需。AWS 示例可作实现对照。 [MCP](https://modelcontextprotocol.io/docs/2026-07-28/develop/clients/client-best-practices) · [AWS 示例](https://github.com/aws-samples/sample-context-engineering/blob/main/docs/design/design-b-progressive-tool-disclosure.md) |
| Concise and Precise 工具文档压缩 | 借鉴保留名字、参数名及关键约束的原则。本次用手工精简定义，描述和示例按需出现。 [论文](https://aclanthology.org/2024.findings-acl.974/) |
| BigTool、ToolScope、Toollery | 作为工具库扩大后的备选。眼下明确目录题的额外往返更紧迫。 [BigTool](https://github.com/langchain-ai/langgraph-bigtool) · [ToolScope](https://aclanthology.org/2026.acl-long.1573/) · [Toollery](https://aclanthology.org/2026.emnlp-industry.20/) |

针对长文档的受控研究发现，单本书的收益取决于现有检索和 Agent 实现，更深的发现层在其试验中没有带来改善。这里把它作为评估深层路由的参考，工具侧的实际收益以本项目计量为准。 [渐进披露研究](https://aclanthology.org/2026.realm-1.14/)

## 4. 做完整的历史恢复与最终验收

- [ ] 原始历史保留，按会话分支、权限和当前问题筛选。上一轮的短 ID 只能在原回合解释。根据上一答的可见引用顺序找到持久化来源，再登记成新回合可读的 ID。普通续聊和编辑分支、缺少旧来源记录及已取消授权分别验证。
- [ ] 当前工具回合保留 provider 所需状态及调用配对。无关短问没有阅读器定位和旧工具正文。保留旧链接和历史保存兼容性。
- [ ] 重跑现有历史压缩失败项，依据新策略明确应触发摘要的测试夹具，同时验证裁剪不会损坏消息配对。真实候选补测模型出口的 8,000 字段、真实截断恢复和不同账号隔离。
- [ ] 用独立候选复跑七类浏览器用例，再核对同题逐请求分项与检索等待。实际浏览器入口按候选配置确认，发布回滚沿用本地发行控制流程。
