## 阶段 0 · 例程与真实基线

- [ ] 在独立测试部署固定代码发行、教材身份、LightRAG 工作区、模型/输出预算、Embedding 与 Rerank 设备。使用单独的可写运行目录、测试账号及可控的数据存储。确认正在运行的发行与采样记录一致。
- [ ] 保留现有启动轨迹格式。以控制脚本起点记录每个服务的创建及首次就绪，分别试默认编排与 worker 先行。每组至少记录一次进程冷启动和两次重复启动。受控失败也记录最后成功阶段与异常类别。单独计 worker 的 bridge 安装、旧索引打开、Embedding/召回/Rerank、端口监听及健康通过。
- [ ] 用现有首问采样器和宿主/worker 检索分段记录关联同一回合。用例为无检索问候、原题「自变量是什么」、明确引用教材小节的题、无教材证据题。分别记录连接、回合受理、首次模型请求、首个模型正文、检索排队/关键词/向量/重排、来源校验与组装、客户端来源、首个正式正文及完成。以同回合标识对齐进程间记录，对重叠区间取并集。
- [ ] 同一题比较热服务新会话与同会话重复。先确认上一回合终态和服务可接收，再发送第二问，另记 `done` 到可接收的时间。采样器记录协议错误码；若活跃检查为 none 仍遭拒，分别对齐持久化终态、协调租约是否已释放和实际受理时间。保留工具和模型调用次数、输入/命中 Token、引用数量及输出长度。
- [ ] 上下文阶段开始前，使用同一个追问测短历史、长历史已有有效摘要、长历史本轮触发摘要。记录 SQLite 返回行数、读取与解码时间、摘要调用、输入 Token 和正式正文延迟。使用合成历史，覆盖分支和澄清事件。样本少时报告各样本和中位数，不据三次启动推断 P95。

## 阶段 1 · 启动顺序、旧检索和固定教材

- [ ] 第一项先改启动顺序。worker 通过独立就绪探测后再启动宿主。验证 Web 的实际依赖、worker 提前退出和失败后重启。先单独验收此改动，便于观测启动编排收益。
- [ ] 移除 Heart 软件发行流程中强制逐文件核对哈希的步骤。检查 `deploy/student_release.py` 的打包和选版调用，以及 `deploy/run_student_release.py` 与 `deploy/manage_student_local.py` 的检查、启动和重启路径。三个服务使用同一发行路径。启动只检查必要路径、配置与服务就绪。验收以这些常规入口均不调用全量软件校验为准。
- [ ] 按 [旧教材索引退役计划](2026-11-25-retire-legacy-textbook-index.md) 移除 worker 的旧索引预热和宿主的旧本地检索样例。将仍依赖旧索引的调用方迁到现有 LightRAG 或原文读取入口。在隔离候选环境验证旧索引缺席时，教材问答、引用跳页、选区、练习和旧会话仍可用，再从在线目录迁出旧文件。
- [ ] 固定教材安装时完整核对正式教材与活动 LightRAG 索引，保存教材版本绑定和正式教材哈希表。普通重启直接读取安装时保存的哈希表，取消正式教材目录的两次全量扫描。加载预先生成的资料时检查必需文件可读、教材版本与实际 LightRAG 工作区一致。
- [ ] 取消启动时对建库冻结输入的逐文件扫描。逐项清点运行时还读取的 PDF 清单、章节原文映射和图表资料。把必需内容放入已发布的运行资产，在隔离环境中让冻结输入整目录缺席，验证启动、检索、引用跳页、图表和阅读。通过后从在线目录移出冻结输入。记录仍有依赖的文件和调用方，据此判断哪些可以移出。建库原始副本可留档供重建索引使用。
- [ ] 教材发布时提前生成图表清单和检索词表，并绑定教材版本。普通重启直接加载两份结果，取消为整理图表或生成词表而重新遍历教材。
- [ ] 教材发布时生成段落、原文块、PDF 和页码之间的映射，作为已发布资产保存。启动加载映射，回答时用检索结果的原文块 ID 查 PDF 和页码。验收覆盖新旧回答引用、图表、原文定位与点击跳页。

验收比较相同教材、模型和设备下的服务就绪时间。核对 worker 已就绪才启动宿主，软件部署和启动无强制全量哈希校验，固定教材重启无两次正式目录扫描及冻结输入逐文件扫描，旧检索启动样例消失。验证教材必要资料缺失或与数据库版本不一致时能给出明确错误，原文与页码保持准确。


## 阶段 2 · 回答与上下文

- [ ] GPU 重排作为本阶段的明确改动。将正式教材 LightRAG 路径的候选原文重排切到 CUDA，使用现有配置 `RAG_RERANK_DEVICE=cuda`，沿用现有重排模型并复用 GPU 推理会话。部署时确认实际命中 CUDA 执行后端，记录设备初始化成本、显存占用和重排耗时。用同一模型、候选集合、候选数和题集对照旧 CPU 基线，复核前排来源、原文页码及首个正式正文时间。CUDA 未就绪时按现有设备校验报告错误。
- [ ] 按阶段 0 的检索轨迹选定优化点，每轮实验只动一个主要变量。若重复校验或连接显著，则按已发布教材版本复用静态结果，或单独对照桥接 HTTP 连接复用；若时间主要在检索排队、重排或模型调用，直接对该阶段做对照。已有同回合去重与来源验证继续用于对照。
- [ ] 若有效摘要下历史读取仍慢，在 DeepTutor SQLite 会话存储引入按摘要位置读近期消息的查询。分支先验证摘要锚点属于当前祖先链，保留澄清事件、模型工具调用配对及未摘要的近期原文。保留现有兼容读取路径以处理缺失或无效摘要。
- [ ] 若同步摘要显著占用提问后的时间，通过已持久化回合的完成入口按预算阈值调度已有摘要逻辑。下一轮用有效旧摘要与预算内近期原文。写入时校验摘要基准位置、分支和相关记忆版本；失败或过期保持已有有效摘要，记录错误原因。
- [ ] 验收包含引用跳页、图表或公式来源、无匹配、连续追问、分支重答、记忆删除和教材资产身份不匹配。对比首个正式正文、完成时间、工具次数及输入 Token，再决定是否推进教材摘要、画像快照或进程级缓存。

## 阶段 3 · 统一 Heart 后端

现有复用的 DeepTutor 源码按 Heart 自有维护的代码处理，今后由 Heart 自行开发。取消跟随 DeepTutor 上游升级的要求，并移除运行时要求源码与上游快照匹配的检查。保留第三方来源和许可证声明。模块可按 Heart 的实际职责重组，无需为了上游合并维持 DeepTutor 与 Heart 的原有代码边界。

- [ ] 第一期启动整改完成后，将现有宿主与 worker 的路由、对话服务、教材检索及后台任务接入同一个后端应用。将适合合并的本机 HTTP 桥接替换为服务内调用。
- [ ] 验证登录、WebSocket 流式输出、会话恢复、账号隔离、教材与来源权限、后台任务和资源关闭。对比桥接往返、首个正式正文和回答完成耗时。


## 回退

启动编排与教材静态快照分开提交和验收。遇到启动失败可恢复上一版控制脚本与发行指针，并用原启动轨迹复核。旧教材索引先在候选中验证缺席，运行目录仍需支持按现有退役计划恢复资产。上下文阶段保留已持久化原始对话，回退时恢复原历史组装入口。
