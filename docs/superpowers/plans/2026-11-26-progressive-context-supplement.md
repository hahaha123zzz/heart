## 1. 学生自动绑定唯一课程教材

- [ ] 以课程挂载且通过授权的规范教材 KB 为唯一来源，复用 `course_rag_provider.canonical_kb_name` 和课程资源。按产品要求学生进入固定教材课程即默认选中该教材，无需手动选择。页面可展示默认教材名称。教材标识由服务端配置提供，避免浏览器硬编码另一个值。
- [ ] 学生 `/ws` 与宿主发起的学生任务共用默认绑定规则。兼容字段缺省和旧浏览器的 `knowledge_bases: []`。白名单校验在服务端做。显式给出唯一已授权教材仍能使用，未知、越权以及课程没有可读教材按现有规则收口。保留其他能力或入口已有的显式选择语义。
- [ ] 把默认绑定与本题是否查教材分开。普通概念与比较题先用教材预检索，然后生成第一条模型请求。目录和明确无关短问仍拥有课程归属，首轮不查正文。阅读选区优先使用经核验的选区，证据不足时才补查。
- [ ] 核对 `buildStartTurnInput.ts`、`_apply_course_defaults`、课程授权过滤和 `_retrieve_kb_seed_block` 的顺序。用学生账号的真实 `/ws` 事件断言唯一提交、一次默认解析、预检索完成早于首个模型请求。追加旧浏览器空列表、显式教材、失去授权、重试和目录、日期反例。

## 2. 共用一套规则，保留现有进程分工

- [ ] 本次以学生正常入口统一、规则一致为目标。Web 处理页面和代理，DeepTutor worker 负责聊天会话、模型和工具，HEART 宿主负责固定教材、索引检索和课程业务。两条后端调用入口不意味着一个用户问题执行两次。worker 请求宿主检索是同一回合的下游步骤。
- [ ] 将默认教材解析放到现有共享服务端路径。浏览器与宿主请求都经过它，调用同一教材检索能力。用 `client_submission_id` 与回合 ID 核对重试、重连与真实工具调用，避免因重复入口处理产生重复模型请求。
- [ ] 本轮保留两个后端进程和可分别读取的健康状态。对照记录 worker→宿主 HTTP 往返、宿主处理、查询锁、召回、重排和批次等待。只有发现跨进程成本在真实题中持续显著，才另立物理合并方案，并一并评估 GPU/索引驻留、启动就绪、内存、故障隔离和回滚成本。此前独立样本的 13.472 秒往返与 13.319 秒宿主处理只差约 0.153 秒，不能用来承诺合并后多批查询会变快。

## 3. 保留 DeepTutor 上限，减少重复检索与工具发现

| 层级 | 当前学生普通聊天的限制 | 本次处理 |
|---|---|---|
| 一次模型返回的并行工具批次 | `MAX_PARALLEL_TOOL_CALLS = 15`，只执行前 15 个，剩余返回未执行的工具结果 | 保留 |
| 一次学生提问的探索阶段 | 普通聊天 `max_rounds = 8`，当前 worker 的 `capabilities.chat` 没有覆盖该值。每个模型循环轮计一次，不等于执行一次工具。能力可以有不同配置或最低要求 | 保留 |
| 探索结束后的收尾 | 最多 3 个收尾循环，工具仍可用。需要时最后再发一次无工具请求强制收尾。模型可提前结束 | 保留 |
| 宿主教材 RAG | 已取消整个学生回合最多两次的独立限制，真实对比题已执行 6 次。服务端预检索也与模型返回的并行批次分别计量 | 保留取消结果，按证据缺口发起补查 |

- [ ] 通过已有 `tool_policy.py` 和 `tool_disclosure.py` 把纯目录、概念、比较、当前页、无关短问、混合需求分开。纯目录直挂精简 `kb_files`，用于明确的问题。少见相关工具通过现有 `load_tools` 按需展开。用同一套名单发出 JSON schema、文字清单和执行准入。
- [ ] 首轮教材证据覆盖问题的不同维度，按完整原文条目入预算。重复来源复用短 ID，证据足够时引导作答，原文略短用 `read_source`，确实缺项才用 `rag`。同一回合内相同查询应复用现有结果或正在执行的任务。记录不同查询回来的相同证据、本轮披露次数与等待阶段，避免把工具调用浪费误判成模型输出预算问题。
- [ ] 复用已有的 DeepTutor 加载器。参考 MCP 的发现、检查和执行，以及 LangChain 按请求动态选工具。小工具集先验证场景筛选和精简定义的收益，BigTool 及 Toollery 作为工具库扩大时的对照。 [MCP](https://modelcontextprotocol.io/docs/2026-07-28/develop/clients/client-best-practices) · [LangChain](https://docs.langchain.com/oss/python/langchain/context-engineering) · [BigTool](https://github.com/langchain-ai/langgraph-bigtool) · [Toollery](https://aclanthology.org/2026.emnlp-industry.20/)

## 4. 整包验收与交付

- [ ] 复用当前工作树的选区、历史补读和短问隔离改动，检查未遗漏新增历史模块及回归用例。候选中用普通浏览器文字拖选与表格框选，断言选区原文只出现一次、图表进入阅读问答、普通作业截图继续走原流程。复验点击角标、自动跳页、保存刷新。
- [ ] 相关追问用 `read_source` 恢复上一答复已核验的真实引文。测试过期、不可读、不同账号和编辑分支。阅读器打开时问日期，确认无旧教材结果、无阅读器自动定位、无教材工具。明确上一答复与更早历史的支持边界。
- [ ] 在同一模型配置下复跑概念、跨章比较、目录、短问、追问和选区。报告未命中缓存的输入 tokens、首个模型请求时间、首字、总时间、检索批次及实际执行工具数。目录题须去掉发现往返。对比题分别核对首轮证据覆盖和检索时延。
- [ ] 使用脱敏的模型出口结构证实普通生成、续写、收尾不发送项目固定 8,000 输出额度。验证真正的服务商截断后仍能续写。重跑历史压缩与同轮 RAG 补读的失败项，验证消息配对、旧链接和教材测试资源。
- [ ] 以独立候选发行验证 Web、worker 和宿主就绪及真实模型问答。通过再切换对外端口所指发行。出现首轮教材丢失、权限串用、图表误入作业识别、角标错误或核心流程回归时，复用旧发行回滚并复验。
