## 1. 目标、范围与旧计划关系

目标：学生默认进入 DeepTutor 对话工作台；通过“我的学习”查看知识图谱、掌握路径、学习档案和记忆，并进入独立练习页面；设置仅保留实际可用的个人与学习选项。所选模块的详情、会话、菜单、弹窗、抽屉和状态界面随页面成组复用，不只移植首页截图。

优先直接使用原版组件和布局；只实现宿主身份、教材、数据与事件适配，以及原项目没有的必要业务组合。效果图确认后才开始产品页面实现；效果图不得冒充真实浏览器截图。

本计划接替 2026-11-11《前端功能补齐与组件规划》中“五个目的地、继续维护原生 JS 外壳”的未来页面建设方向。白灰配色与旧方向一致，但页面组织和整组复用方式已有变化。旧计划、已完成改动和验收产物均保留，不回滚、不批量重写旧文档。

本计划不重开此前已完成的回答事件、流式渲染和教材证据工作。迁移必须保留这些行为，其实际状态以当前代码和重新建立的基线为准，不能把旧文档中的历史故障视作当前故障。

本次不包含：教师/班级管理、课程商城、多课程平台、学生自建教材库、开放注册、邮件服务、学校单点登录、替换记忆引擎、重建教材索引、重写教学算法、修改正式教材或删除旧数据。统一网站的登录隔离与个人模型凭据属于已确认范围，不能作为额外功能省略。

| 34 | 全量做完再演示 | 四条主链 + 图谱 + 记忆改造 + 结果同步 + 练习复习 + 白灰主题 + 部署回退，全部通过后才切换 |

本轮新增的已知代价：

- 新聊天的会话与消息不在 PG；H 的 evidence 只能靠 §33 的同步产生。
- 厂家设置页对学生是 403，因此模型 Key 必须走自建设置页。
- 打开厂家认证前，必须回归 H→厂家的 `/internal/heart/*` 桥接不被 401 打断。

## 4. 白灰主题与视觉评审

- 使用 DeepTutor 的布局、间距、字号、图标和交互；尽量只通过主题 token 改色，不重新设计同款组件。
- 白色内容表面，浅灰侧栏与页面背景，灰色边框，深灰正文；使用固定浅色主题，消除当前混用的暖棕和蓝色主色。具体灰阶由效果图及对比度核验确定，不维护两套色板。
- 图谱状态使用标签、图标、填充/描边及图例，不能只依赖颜色深浅。教材批注颜色是内容属性，保留原记录，不把历史高亮强制改灰。
- 统一按钮、选区栏、引用区、抽屉和弹窗；手机采用原版响应式与底部面板模式，不另造一套交互。
- “与原版相同”按固定版本、语言、字体、视口和相同事件 fixture 比较布局及动作。允许差异仅为品牌、白灰 token、已声明的导航筛选、宿主业务字段和权限状态。

## 5. 实施架构与数据边界

优先直接以 V/web 完整 Next.js 应用为新前端源码，保留原版路由、组件和 Provider，不继续扩大原生 JS 外壳的嵌入范围，也不复制第二套完整 DeepTutor 前端。**2026-11-17 起架构定为“整租”（决定 26）**：页面、路由与接口归厂家 worker（`127.0.0.1:18001`），H 只做登录身份补充、个人模型设置、结果同步、旧壳与回退。宿主专属新增集中在 `V/web/features/heart/` 与 `H/integrations/deeptutor/`，上游少量接线改动记入 `V/LOCAL_PATCHES` 的本次来源账本（含 `proxy.ts` 注入 bridge token）。

H 的 FastAPI、教学执行、发布核验、课程数据、学生状态和现有持久化仍是业务后端。浏览器只访问同源宿主接口；原生 worker 与服务凭据不直连浏览器。开发/部署代理同时覆盖 HTTP、静态附件和实际使用的流通道，不把“能打开页面”当作集成成功。

最先验证普通对话纵向链路。V/web 的真实契约已核实（2026-11-16）：对话走自研 v2 WebSocket（`TurnRuntimeClient.ts:133` → `/ws`），协议 2.0，含 seq 重放、resume 与 ask_user 重挂。

**用户决定（2026-11-16）：整条厂家后端接管对话（方案 B）。** 厂家 worker 已运行在 `127.0.0.1:18001`，`deeptutor.api.main:app` 自带 `/ws` 与完整 `/api/*`；当前被 `HostBridgeBoundary` 拦成 401/1008，厂家认证默认关闭。实施顺序：① V/web 代理把后端指向 18001 并注入 `x-heart-bridge-token`；② 打开厂家认证，H 登录时为 `heart_native_<digest(student_id)>` 铸造 `dt_token`；③ 回归验证 H→厂家的 `/internal/heart/*` 不被 401 打断；④ 前端认证改由厂家返回。

已知代价（用户已接受）：聊天与学习记录写厂家存储，不写 H 的 PostgreSQL；掌握度、待复习与引用核验不随聊天自动更新，需要另做同步。`/api/auth/*` 的 H 实现保留给旧壳与回退。代理层 `web/proxy.ts` 已把 `/api/*`、`/ws/*` rewrite 到后端。

### 5.0 登录身份与个人模型凭据

统一网站必须先具备真正的登录会话和服务端身份解析。普通学生无权通过 URL、请求体或自定义 student_id 切换他人的学习记录、Key、附件或任务。旧接口参数若仍保留，必须与已认证主体核对；旧页面回退不能绕过新身份检查。现有上游账号服务如可安全复用，优先适配；否则补最小会话服务，不建立第二套互不一致的账户身份。

实现方式按决定 19 待定：执行到任务 2 前，先检查现有鉴权代码，再在“实现上游已定义的 `/api/auth/status`、`/api/auth/login`、`/api/auth/logout` 契约（前端零改动）/ 自建会话服务 / 以 DeepTutor 用户库为主”之间由用户选择。`V/web/lib/auth.ts` 已确认前端只消费后端返回的 `AuthStatus` 与 `learning_policy`（含 `reading.allow_upload`、`material_ids`、`allowed_capabilities`、`preset`），因此“固定教材、禁止上传”应作为权限卡字段实现，而不是在前端另写拦截。

账号主存储随数据库替换一并落位（决定 18）：数据库替换已完成，H 的业务数据运行在 PostgreSQL 的 `heart_psychology` 上，新增的账号、会话、个人凭据表必须使用 SQLAlchemy 通用类型与通用索引，不写 SQLite 方言，也不扩展 FTS5。

预置 10 个测试账号的初始化必须幂等：重复运行不增加账号、不重置密码、不清空学习记录；账号有效期使用明确的永久语义，不以极大 TTL 冒充，排查启动清理、定时回收及 worker 授权中的全部过期检查。此政策仅应用于这 10 个账号，其他历史测试账号不自动延长。初始化凭据只在受控交付中提供给用户，不写入 Git、日志、报告或效果图。

个人 Key 在服务端加密保存，加密密钥由部署环境独立提供；浏览器不持久化明文 Key，读取接口只返回脱敏信息。所有模型请求从服务器发起，不修改进程全局环境变量或共享 Provider 的默认 Key；客户端/缓存/后台任务必须按账号和凭据版本隔离，不能把某学生的 Key 用于其他学生。Key 更新/删除后，后续请求使用新配置；已开始任务按明确的凭据快照完成或取消，不暗中切换账号。

学生只配置 OpenAI-compatible 生成模型。连接验证区分“鉴权/基础响应通过”和“工具调用/图片能力通过”，不以拉取模型列表成功代表学习能力全部可用。题目截图必须使用已验证支持图像输入的模型；不支持时提示更换配置，不静默忽略图片。显示鉴权失败、余额不足、限流、模型不存在、超时等可行动错误，不回显密钥或供应商敏感响应。没有个人 Key 时允许阅读教材和查看已有记录，生成任务引导去模型设置；不使用项目共享 Key 自动兜底。

Base URL 属于学生输入：实施前验证 HTTPS、地址解析/重定向与请求超时，阻止访问服务器本机、内网和云元数据地址；确需内部模型时由管理员配置允许的端点。共享教材检索、Embedding 和建库继续使用项目配置，生成任务使用个人凭据；不因学生换模型重建共享索引。

### 5.2 图谱状态

教材图节点和关系来自当前发布版本的 LightRAG 数据；学生状态来自当前启用的学习存储。旧知识状态默认 mastery=0.5 不能当作学生已有掌握证据；历史只读归档不自动换算为当前掌握度。

新增稳定对应关系须区分：课程与教材版本、实体 ID、规范知识点 ID、掌握路径/目标 ID、映射依据。优先已有规范 ID；只按名称相似度不能自动确认。无对应、对应歧义与无测评证据分别保留为未知状态。

默认显示当前章节或当前概念的有界子图，支持搜索、聚焦和筛选。每次接口设置服务端上限并在截断时提示“部分显示”，不承诺全图已加载。节点详情展示已有证据、教材链接及学习/练习入口。图谱关系仅表达已核实的关系类型，未知关联不画成先修箭头。

学生端不开放手动标记已掌握；上游相应按钮和写动作须同时受宿主权限限制，不能只隐藏按钮。记忆新增/更正不能修改掌握状态或测评证据。

掌握与待复习状态复用现有 is_assessed_mastered、review_sort_key、RetentionScheduler 等业务规则；先确认其与当前存储的适用范围，不照搬其他项目的 0.85/0.6 阈值。关系和掌握状态不相互推导，也不按原始实体数计算全章完成率。

### 5.3 学生记忆

卡片主要显示自然语言条目及可验证的分类/来源/时间；缺失字段明确缺省，不生成虚构时间和来源。不展示 L1/L2/L3、内部文件、token、审计脚本或整篇 Markdown 编辑器。

现有 entries 投影主要为行、section、entry_id。**2026-11-16 起记忆存储已变为**：卡片正文在 PG 的 `memory_documents`，向量索引在 `student_memory`（mem0，`infer=False`，异步同步）。因此任务 7 开工前必须重新核对：哪些投影仍由 `native_bridge.memory` 提供、哪些要走 mem0 检索、异步同步滞后时如何回退到 PG 关键词检索。不得沿用“文件式 L1/L2/L3”的旧假设。实施时先判断哪些行是真实条目、哪些是标题/说明，保留稳定定位，不按前端数组下标删除。单条编辑由引擎现有更新能力或最小受控写接口完成，提交带条目/文档版本检查，冲突重新加载后再确认；不读整篇后无条件覆盖，避免覆盖后台新记忆。

学生可查看、更正、删除记忆，并主动添加学习偏好。新增偏好与设置页明确选项共用同一有效偏好来源，记录用户确认与生效范围；不创建另一份相互覆盖的状态。学习证据和成绩不通过记忆卡片编辑。未知或推断描述显示其状态，不包装成已确认事实。删除按现有遗忘语义核验，防止旧缓存/恢复路径重新出现已删除正文；不擅自承诺永久排除所有未来重新推断。
