# 正式教材旧索引退役与清理实施计划

日期 2026-11-25
工作树 student-frontend-reuse-20261117
运行基线 lightrag-native-v4-20261124

## 目标和清理范围

将正式《实验心理学》教材的课程文本检索统一到 PostgreSQL LightRAG。解除教材就绪、版本校验、启动预热和仍在使用的功能对旧 SQLite 全书索引的依赖。先验证旧文件缺席时能正常使用，再从运行目录迁出旧索引和已经确认无调用的缓存。

| 对象 | 处理方式 |
| --- | --- |
| 正式教材目录下的 rag_index.sqlite3 | 本次退役目标。本机约 14.91 MiB，包含 1,465 个文本块、向量和 SQLite FTS。 |
| 与该旧索引签名对应的 BM25 或旧检索缓存 | 确认目录属于该签名、无活跃调用后迁出。以实际存在的路径为准。 |
| LightRAG 迁移前的 GraphML、vdb JSON 与 KV JSON | 独立作为可选清理批次。这批文件约 149.20 MiB，需核实导入、验收和回退脚本的依赖。 |
| PostgreSQL LightRAG 及现行出处资产 | 运行所需资产。涵盖候选输入、source_map.json、入库 sidecar、引用坐标库、教材 PDF、阅读定位与图表资料。 |
| sample/rag_index.sqlite3 和离散数学索引 | 各自服务于课程预览或其他教材，路径不能匹配此清理清单。 |

实测基线为固定教材初始化 98.72 秒。独立复跑中，旧索引加载和组装检索器耗时 4.11 秒，旧查询预热耗时 28.64 秒，包含 28.30 秒原文重排。这些数字用于定位优化点，改后收益以同环境的启动对照为准。

## 1. 清点调用，再解除启动依赖

- [ ] 从当前运行配置和代码确认实际启用的入口。核对 knowledge/fixed_book.py、knowledge/course_release.py、knowledge/lightrag/course_input.py、knowledge/textbook.py、agents/course_search.py、agents/agent_loop_service.py、agents/q5_runtime.py。重点验证普通聊天、旧宿主答题入口、教学导航、学习相关功能和教材来源读取。
- [ ] 核对 integrations/deeptutor/knowledge_client.py、published_course.py、knowledge_bridge.py 以及阅读和教材发布链路。仍被运行时使用的召回迁到现有课程 LightRAG，旧 chunk ID 的证据回读迁到受版本和权限约束的正式原文读法。只有离线工具使用的入口可以改为显式传入归档索引路径，记录其调用方式。
- [ ] 在固定教材启动中去掉旧 local_rag 的 warm() 和样例 retrieve()。LightRAG 实际需要的 embedding、原文重排器和对应就绪校验继续由主检索链负责。用日志或测试断言固定教材启动没有打开旧 SQLite、加载旧检索栈、发起旧样例查询。
- [ ] 搜索引用旧索引的启动、部署、资产冻结和验收脚本。按新入口更新当前生产验收与 README，并核对旧版回退还需要哪些文件。

## 2. 解除发布身份和引用对旧 SQLite 的依赖

- [ ] 先记录正式教材 manifest、PDF 版本、旧 SQLite 哈希、当前教材 release_id、引用坐标库位置、活动 LightRAG 工作区和索引清单。确认同一批材料的原文、PDF 和出处仍能对上版本。
- [ ] 修改 knowledge/course_release.py 的就绪判据。当前 readiness 要求旧 SQLite 存在，并把其 SHA-256 写入 release_id 的计算输入。改用已经核验的固定教材文件、来源映射与 LightRAG 清单作为有效索引的判据。完整保留原文和 PDF 校验。
- [ ] 明确教材发行身份的兼容办法。短期优先在已验证的教材版本记录中固定旧索引摘要，用它兼容已持久化的旧 release_id，同时用当前 LightRAG 清单判断就绪。后续如切换发行身份格式，建立经过核验的旧新身份映射，仅在 PDF 版本、文档身份与原文范围一致时承认历史引用。校验或调整 citations.sqlite3 的版本绑定，验证历史回答刷新、点击、跳页和高亮。
- [ ] 当前候选 input_manifest.json 的 files 不包含正式教材 SQLite，q2_input_manifest.json 把它记作 included=false 的历史参考。清理前在实际候选重新验证这一点。更新 inventory() 的正式教材必需文件定义和资产冻结流程，使缺少旧 SQLite 的输入可以生成、校验和启动。冻结历史描述按其既有签名保留。

## 3. 在独立候选环境试运行，再迁出旧文件

- [ ] 先用由同一份已核验资产派生的候选环境验证。让候选的正式教材路径缺少旧 SQLite 和旧缓存，指向经过验证的 LightRAG、来源映射及发行配置。使用隔离的可写缓存路径，保持生产目录可直接回退。
- [ ] 验收通过后，记录待迁文件绝对路径、大小、SHA-256、所属发行和可恢复位置。核对路径在本次指定范围内，确认 SQLite 无写事务或活动 WAL，使用可逆移动将旧索引和确认无调用的缓存迁到发行目录以外的归档位置。部署后的首次重启复查运行目录没有重新生成旧索引。
- [ ] 如需处理迁移前的 LightRAG 文件副本，用独立清单按文件逐项验证当前 PostgreSQL 存储和回滚依赖。保留活动的文件清单、源签名、入库 sidecar、源映射和冻结教材输入。整目录移走会影响所在目录中仍在用的文件。
- [ ] 在确认回退方式后留存归档，归档的最终销毁单独确认。

## 4. 验收和回退

| 检查 | 通过条件 |
| --- | --- |
| 就绪和耗时 | 无旧 SQLite 的候选启动成功，fixed_book.ready 为 true。用相同设备、同教材和同候选设置测量宿主启动、固定教材初始化和第一条教材回答。分别记录冷启动与热重启，确认旧预热阶段已消失。 |
| 课程问答 | 普通新会话、继续追问、章节或选区提问均能使用已授权教材。若生成前检索改动已合入，同一教材初查仅执行一批，证据进入首次模型请求。 |
| 阅读与证据 | 新旧回答均验证引用跳页和高亮。至少覆盖跨章、图表或公式，以及教材没有依据的题目。读取权限和文档版本仍由当前服务端核验。 |
| 其他依赖 | 教材预览、学习导航、练习及测评按入口核对。旧发布或测试工具若继续需要归档索引，应能显式找到归档。 |
| 存储清理 | 在线目录缺少旧 SQLite 及已迁出的同签名缓存，PostgreSQL 索引清单和有效来源数量可核验。若另行迁出 LightRAG 文件副本，再检查图谱查询和出处映射。 |

出现宿主无法就绪、LightRAG 查不到有效原文、历史引用失效或预览与学习入口回归时，暂停迁出。已迁出的文件按记录和哈希恢复到原位，再使用既有发行工具切回上一版并验证健康和至少一条带引用的教材问答。回退使用原有数据库和教材正文。
